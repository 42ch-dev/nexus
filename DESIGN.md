# Nexus Design System

<!-- COMPLETENESS_LEVEL: 3 — Production contract, reviewed 2026-09-09; runtime acceptance is separate -->

## Overview

Nexus is a **precision creative tool**: a neutral workbench with clear boundaries, comfortable reading regions, and deliberate cobalt interaction. Preserve the Nexus name and the five-node timeline mark. Warm-paper surfaces, global literary serif, cyan glow, and marketing motion are not the active language.

This light/default frontmatter and [DESIGN.dark.md](DESIGN.dark.md) are the sole token authority. `version: 0.5.0` is this repository's design-contract revision, continuing its existing schema: nested component recipes, semantic `rounded` keys, `space-*` steps, and scalar typography metrics are intentional. Do not flatten/rename them to match an external template. Every frontmatter key exists in both themes; only values differ. Level 3 describes specification completeness, not a claim of rendered QA.

The implementation contract and complete Studio inventory live in [.mstar/specs/design-studio.md](.mstar/specs/design-studio.md). No app-specific palette, shadow table, font stack, or live token override is allowed.

## Design Concept — Precision Creative Tool

- Silver-neutral light planes and graphite dark planes distinguish workspace, panel, and raised content. No grain, glass, decorative gradients, or full-width marketing heroes.
- Cobalt denotes action, focus, selection, and timeline activity. Semantic hues still distinguish success/running, warning/stale, error, queued, presets, and annotation categories. Color is never the only status cue.
- Interface and authoring titles are **both sans**. Content voice remains a larger title hierarchy, not a different typeface. Existing `font-display`, `display-*`, and `CardTitle.voice` consumers remain valid.
- Compact chrome uses existing 32px controls; form/default 40px and large 48px remain. Reading is not squeezed to match toolbars.
- Motion communicates changes, not personality. No hover translation, scale-on-press, animated gradients, or perpetual decorative motion.

## Brand Colors

All brand values are in `colors`. Public names `brand-deep-blue`, `brand-cyan`, their extended steps, `blue-*`, and package `brandColors.deepBlue/cyan/white` remain unchanged. These are stable API identifiers, not promises of historical pigment: `brand-cyan` now carries the theme's cobalt signal. No new alias or compatibility layer is introduced.

`brand-deep-blue` remains a dark structural pigment in **both** themes, suitable for bright-fill labels and fixed dark brand surfaces, never dark-theme paragraph text. `brand-cyan` and `blue-700` match per theme; their 800/900/1000 steps deepen in light and brighten in dark. `blue-1100` is retained and now explicitly present in dark. Package numeric `brandColors` exports are generated light/default snapshots; theme-aware UI reads CSS, not JavaScript constants.

### Background-driven contrast invariant

Foreground follows the actual fill, not the page name. Light primary uses `blue-700` fill and `brand-white` text; dark primary uses `blue-700` fill and `brand-deep-blue` text. Hover/active use `blue-800/900`. Light destructive uses white on the red scale; dark uses deep-blue on its brighter red scale. Never place white on a bright dark-theme accent.

## Colors

- `background-100`: document/raised reading plane; `background-200`: quiet groups; `background-300`: stronger panel/selection plane.
- Gray 100–300: neutral fills; 400–500: borders and subdued graphical detail; 600–700: secondary/helper copy; 800–1000: increasing text emphasis. Do not set active small text in gray-500. Use gray-700 for Studio metadata instead of the old gray-500 convention.
- Gray-alpha: hover washes and decorative separators. Input boundaries use opaque gray-500; a low-alpha divider is not a control's only affordance.
- `scrim`: backdrop only; text lives on an opaque dialog/popover plane above it.
- `red`: failed/destructive/conflict; `amber`: warning/stale/review; `green`: success/healthy/running/completed; `teal`: queued/starting; `blue`: info/interaction/timeline; `purple`: preset/strategy/research; `pink`: annotation/relationship category. Preserve labels and icon/shape cues.
- All existing component status, finding, memory, reading, SOUL, and canvas families remain. Literal semantic tints in recipes are resolved from the same color scales; they are not independent palettes.

Alpha fills must be composited over the actual backing plane before evaluating contrast. ## Typography

Exact families and metrics live in `typography`. UI/prose/display use the OS sans stack: system-ui, Apple/Segoe UI, then named Simplified Chinese system fallbacks (PingFang SC, Hiragino Sans GB, Microsoft YaHei UI, Noto Sans CJK SC). No network font request is needed. Do not claim identical glyph metrics across operating systems. Keep Latin and CJK in the same specimen and inspect punctuation, glyph fallback, and baseline alignment. Do not introduce a font dependency solely for visual novelty.

- Display 32/24/20: creative-entity titles and reading headings, sans; CardTitle content remains 20px vs interface 16px.
- Heading 32/24/20/16: page through panel hierarchy, weight 600. Preserve the token metrics, not overrides such as `leading-tight` that erase them.
- Label 14/12: 1.5 line height, no tracking; no all-caps treatment for Chinese.
- Copy 16/14/13/12: prose, explanatory text, dense helpers; copy-12 formalizes an existing Tailwind utility rather than adding a new control.
- Button 14/12: weight 600, 1.25 line height, one line when practical; do not clip glyphs to enforce density.
- Mono: OS monospace stack with CJK sans fallback. IDs/code remain legible offline; numerical columns use tabular figures.
- Reading measure 66ch, line-height 1.75, paragraph gap 1.25em in both themes. Main prose is 16px; responsive containers constrain the measure, never shrink the font to fit.

The old Source Serif 4 font-face declarations and Studio-only preloads are removed from the active pipeline. Existing web/desktop files and preloads are outside this change's edit scope; their unused packaged font files do not constitute an active typography authority. No replacement asset is required.

## Spacing & Layout

Base 4px; retain the nine public space steps. Rhythm: 4–8px inside a control/label group, 12–16px between related controls, 24px between groups, 32–40px between gallery sections. Default card padding 24px, compact 16px, large composition 32px. Do not turn every sample into a nested card.

Use existing Tailwind v3 breakpoints: `sm` 640px, `md` 768px, `lg` 1024px, `xl` 1280px, `2xl` 1536px. The former 401/601/961 breakpoint prose is retired; no screen-key remapping is needed. Studio content cap 1400px; horizontal padding 24px desktop / 16px narrow. A fixed section rail is allowed at lg and above; below lg place it above the content. Top navigation wraps with all five labels visible below md. Header has a 56px minimum height, not a fixed height that clips wrapped content.

Existing control sizes stay tiny 24px / small 32px / default 40px / large 48px. Tiny is for compact pointer/keyboard chrome, not the only touch affordance. Studio chrome uses a 44px minimum hit area at narrow/coarse-pointer layouts without changing public size enums. Tables and canvas fixtures use labeled local overflow regions; never hide document overflow to conceal broken layout.

## Elevation

Exact elevation-0–4 and existing shadow-card/popover/modal projections are in frontmatter. Rest card/node = elevation-1; interactive hover = elevation-2; popover/menu/tooltip = elevation-3; modal/dragging = elevation-4. Flat grouping = elevation-0. Shadows separate planes, not brand glow. Preserve existing public shadow names; new code may use elevation names directly.

Interactive card hover changes border/shadow only, without moving text. Canvas dragging elevation changes immediately so the node tracks the pointer. Selected nodes keep their accent stroke plus a 2px ring and a textual/shape selection cue, not a shadow alone.

## Shapes

Control 4px; card/popover 8px; fullscreen 12px; pill 9999px. Pills are for compact status/avatar shapes, not the default container. Logo geometry and asset corner radii are frozen, independent of UI radius tokens.

## Focus

Do not suppress outline without providing this ring. Shared primitives provide their own focus-visible treatment so external consumers do not rely on Studio global CSS. Forced-colors mode preserves an outline. Active controls never use the disabled opacity wash.

## Voice & Content

Helpful, precise, local-first. Title Case for existing English nav labels/page titles; sentence case for helper text, errors, loading, and toasts. Keep existing localized product vocabulary.

Buttons use a clear verb when the object is obvious: Save, Create, Delete. Dialog/page titles and accessible names retain the object (Delete Work); use Action + object where context would otherwise be ambiguous. Do not expand source-level product copy changes into apps/web. Errors state what happened and a recoverable next action. Empty states explain the first action; loading says what is happening with an ellipsis; success/toasts name the changed object without “successfully” or a trailing period. No decorative emoji, fake metrics, or marketing slogans.

## Component Primitives

All current public signatures remain. No new public families and no promotion of Dialog/States/Table. Values are frontmatter recipes; behavior remains native or owned by the existing component.

- **Button:** four variants × four sizes; source-compatible `asChild`, refs, native attributes and callbacks. Primary uses the new blue-700/800/900 recipe. Disabled remains non-interactive. No layout transform on hover/press.
- **Badge:** neutral/running/queued/warning/error/preset × soft/solid. Preserve default soft and state meaning. Soft uses named semantic fills/borders; solid chooses text by fill luminance. Domain badges retain every finding/task/chapter status.
- **Card:** preserve `interactive?: boolean` as a visual opt-in and `voice?: 'interface' | 'content'`; no synthetic click behavior. Content voice now uses the larger sans display tier. Host still owns role, tabindex, and action semantics.
- **Input / Select / Textarea / Label:** native behavior, refs, invalid/aria-invalid and id/htmlFor remain. Label/control/helper/error composition stays fixture/app-owned; helper IDs use aria-describedby; errors are readable and identified beyond a red border. Native Select remains native.
- **Tabs:** preserve existing controlled/uncontrolled props and values. Baseline TabsTrigger has **no disabled prop**; do not add one to satisfy a generic matrix. Show supported rest/hover/selected/focus, and label disabled as unsupported. Repair keyboard arrow navigation and unique tab/panel associations internally without changing signatures.
- **Toast:** existing success/error/warning/info, real queue/dismissal/portals and caller-owned copy. Dialog/Toast portals stay in their rendering document, including comparison frames. Long text wraps, viewport inset is respected.
- **TransportErrorBlock:** existing six kinds and optional actions; compact text-link CTAs, not filled buttons in an alert. Preserve kind-to-action/callback/copy rules.
- **Compute composites:** existing field schemas, entity pickers, proposal sections, statuses, run tables, node chrome, inspector props remain. Show existing empty/populated/invalid/disabled/truncated/overflow/provenance states as supported, never simulate network state inside a pure primitive.
- **Dialog / States / Table:** remain transitional @web-ui extracts in Studio. Style through shared tokens and fixture composition only. Dialog/Popover recipes also govern menus/tooltips; no new package export is implied.

## Form Field

Label htmlFor matches control id; the caller composes helper/error text and aria-describedby. Input/Select/Textarea own only native control styling and invalid state. Required/optional copy, validation, submit and routing are caller-owned. This contract is complete here, with no dependency on a local process document.

## Canvas Surface

Keep all existing canvas/outline/worldkb/timeline/layer/SOUL/annotation tokens and width slots. ## Implementation Mapping

One pipeline: DESIGN pair → shared token projection → shared Tailwind utilities and existing brand projections → public primitives → Studio and web consumers. Full projection/compiler contract: [Studio spec §3.5](.mstar/specs/design-studio.md#35-token-projection-contract). Shared `:root` and `.dark` are the only theme value layers. Pair view uses isolated documents loading the **same** entrypoint and CSS, not nested `.dark`/light-reset subtrees.

All existing CSS names and Tailwind utility keys are retained, including historical structural names under `--color-*`; do not rename them while web edits are excluded. New missing color, typography and brand-step projections follow the documented mapping. Existing shadow names remain projections of the elevation scale, not duplicated shadow values. `brandColors` literal values are generated light snapshots; `--nexus-brand-*` and `--color-*` resolve per theme.

Studio-local comparison viewport dimensions and labeled overflow constraints are composition, not global token families. Do not invent new visual pigments or typography outside the DESIGN pair.
