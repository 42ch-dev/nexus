# Canvas Surface Implementation Pattern

**Track**: Knowledge (durable guidance, distilled from the V1.67–V1.76 canvas program — 4 β surfaces: Strategy α/β, Outline+Timeline β, World KB β, World KB Relationships β/γ).

## Context

The Nexus canvas (`apps/web`, React Flow `@xyflow/react`) lets an author steer an AI-autonomous writing process by editing a graph of structured nodes/edges. The daemon owns canonical state (preset YAML, outline markdown, `kb_key_blocks`, `kb_relationships`); the browser/Tauri webview **never writes raw files**. Four surfaces shipped across V1.67–V1.76, each refining the same pattern. V1.75 retired the earlier V1.65 whole-document editor in favor of node-granular canvas edits. This doc distills the reusable implementation contract so the next surface (or any similar structured-authoring surface) lands correctly the first time.

## Guidance (the pattern)

A new canvas surface implements **the coupled layers below** (layers 1–6 are foundational; 7+ are refinements distilled from subsequent iterations). Build them in this order; skipping a layer produces the failures noted.

1. **Schema-backed patch DTOs** (`schemas/local-api/<surface>/`). Each authoring operation is a structured patch request/response + a structured conflict error + a structured validation error. Never a whole-document PUT. The V1.65 whole-document PUT model was retired (V1.75 canvas-pivot) because it could not address or validate individual nodes.
2. **Per-row OCC revision** (`<table>.revision` column + `expected_version` in the patch request). The daemon rejects stale writes with **409 `<Surface>ConflictError`** carrying the current revision + structured locator. Do NOT invent a new OCC scheme per surface — reuse the `kb_key_blocks.revision` / outline `outline_revision:` frontmatter / Strategy `revision:` pattern.
3. **Conflict modal reuse** (UI). Stale writes surface a modal with **Use current / Reapply my edit / Review side-by-side** (side-by-side disabled for same-field conflicts). Flavor the copy with the domain entity (`{node_label}` placeholder → chapter / event / entity / relationship). One modal pattern, four flavors — do not build a fifth.
4. **Non-spatial alternate view** (accessibility). Every spatial graph surface also ships a sortable table/list variant (virtualized for scale) so keyboard + screen-reader users have a non-spatial path. This is a product requirement, not a checkbox.
5. **DESIGN.md token contract**. Each surface adds canvas tokens to `apps/web/DESIGN.md` + `DESIGN.dark.md` (YAML frontmatter SSOT; same token names, light/dark values split). **Token names are preserved verbatim across versions** (V1.69 invariant) — never rename a shipped token; only add new ones.
6. **Draft → Normative promotion discipline**. A new surface starts as a Draft overlay spec; promote to Shipped β at P-last only after QC tri-review + QA Pass. The `canvas-strategy-surface.md` Master holds the cross-surface contract; per-stage details live in Draft overlays until folded in.
7. **Projection data-completeness invariant** (V1.108). When a canvas projection derives graph **nodes** from a paginated query (e.g., `useChapters()` with `DEFAULT_PAGE_SIZE=20`) but derives **edges** from the full domain model (e.g., `outline.volumes[].chapter_ids`), the graph can emit **edges to non-existent nodes** — producing a broken React Flow graph. Fix: either (a) ensure all pages are loaded before projecting (auto-fetch-all pattern), or (b) filter edges to a `Set` of known node IDs after deriving them. Apply defense-in-depth: do both. Add a test with >page-size items or a domain model containing IDs absent from the query result asserting zero dangling edges.
8. **Spatial edge editing pattern** (V1.109). When a canvas surface adds spatial edge creation (`onConnect`), the flow is: **draft edge** (local RF state, no daemon call) → **edge inspector** (condition/label fields) → **commit** (`patch_transition` with `op: "create"`) → **conflict** (409 → modal). The conflict modal must be **command-aware**: store a `retry` callback that replays the original command, not a generic save trigger. The wire DTO may need an additive `op` field (`"create" | "update"`, default `"update"`) if the shipped patch route was rewire-only — verify the daemon handler before assuming the DTO supports create. Edge reconnection uses a single `op: "update"` payload (old_target + new_target), not delete+create.
9. **Fixture-driven read-projection** (V1.109). When a UI feature needs graph nodes that the wire model doesn't carry (e.g., Scene/Beat inside Chapters), project from **fixture-injected payloads** rather than adding wire DTOs prematurely. The projection emits zero children when no fixture data is present (honest empty chrome on real Works). Design Studio / test fixtures are the primary fixture source. This keeps `wire_contracts_changed: false` while proving the projection/UI path. Add wire DTOs only when real data flows and the inspector needs write operations.
10. **Viewport preservation + selection-sync guard** (V1.109). The graph↔list alt-view toggle unmounts CanvasShell, losing RF viewport state. Fix: a module-level `Map<surfaceKey, {x,y,zoom}>` cache (survives unmount, clears on reload = no disk persistence) restores viewport via `defaultViewport` + conditional `fitView`. Use RF `onMove` (user-initiated only), not `onViewportChange` (includes programmatic). Selection-sync `useEffect` overfire: use a primitive `selectionKey` memo (selected node id or `''`) as the effect dependency instead of `[rfNodes]` — RF creates a new array ref on every node interaction including position-only drags, causing the effect to fire on every drag.
11. **Discoverability layer** (V1.111). Spatial completeness is not enough — surfaces must be reachable by keyboard and nested nav. Ship a **global command palette** (⌘K) on an extensible action registry (`useSyncExternalStore` module store + `useRegisterCommand`; see `action-registry-command-palette.md`) and a **sidebar Canvas group** with route-pattern active highlight (not a single Work param — Outline/World KB/Strategy use different route params). When the chrome's built-in `item.to` prefix match is too broad, extend chrome with optional `isActiveItem?(item, activeRoute) => boolean` rather than mirroring nav-item markup in the host. Studio-first: Design Studio hand-mirrors surface chrome as static JSX (no RF / no App canvas imports) so all three surfaces stay previewable under the RF-coupled boundary.
12. **Surface adapter abstraction** (V1.114). Once ≥3 concrete surfaces exist with duplicated wiring (layout assembly, conflict hosting, alt-view, inspector routing, graph projection), extract a **`CanvasSurfaceAdapter<TGraph, TNodeData, TEdgeData>`** interface + **`useCanvasSurface(adapter, queryResult)`** composition hook. The adapter owns: `projectGraph`, `nodeTypes`/`edgeTypes`, `adaptConflict`, `renderInspector`, `renderAltView`, `summarizeGraph`. The hook owns: projection memo, conflict state (auto-populated from `queryResult.error` + explicit `setConflict` for mutation 409s), alt-view toggle, inspector selection, viewport delegation. **Stable adapter object + mutable `ctxRef`**: the adapter is created once (`useMemo([])`); a `ctxRef` is overwritten every render so inspectors/alt-view read fresh state without invalidating the projection memo. Test mocks MUST return stable array identities for `nodes`/`edges` — a fresh object literal per call causes `useMemo` to recompute every render → infinite re-project loop (caught + fixed in the Strategy migration). Migrate surfaces incrementally (≥2 proves the pattern; the rest follow opportunistically). The `layoutOptions` field on the adapter is the opt-in for layer 13.
13. **Dagre auto-layout + manual override** (V1.114). Canvas graphs auto-arrange via `dagre` (`@dagrejs/dagre`, ~2.6KB gzipped + graphlib ~1KB). Implement `useAutoLayout(nodes, edges, options)` returning `{ nodes, isLayouting, relayout }`. **Manual-override model**: on initial graph load, auto-layout runs automatically; once an author drags any node, a surface-level `hasManualPositionRef` suppresses auto-layout until the author clicks **Re-layout** (which clears manual positions + re-runs dagre). Compound (parent/child) graphs: dagre `graph.setParent(child, parent)` ↔ React Flow `parentId` + `extent: "parent"`. **Strict-mode hazard**: dagre computation + ref mutations MUST live in a `useLayoutEffect` (not `useMemo`) — `useMemo` side-effects double-invoke in React strict mode, silently returning un-laid-out nodes at (0,0). Performance: 50-node compound graph ~19ms (<200ms target). Layout is **ephemeral** (component state, not daemon-persisted) in V1.114; persisted positions are a future iteration. Non-opted-in surfaces (`layoutOptions: undefined`) get a no-op pass-through — no behavior change.
14. **Adapter contract convergence** (V1.115). Once the adapter exists (layer 12), **the declared interface must be the contract the implementation honors** — an abstraction that says one thing and does another is worse than none, because a new surface copying it copies a lie. Three V1.114 convergence failures, caught in QC and fixed in V1.115: (a) **W001 — passthrough `projectGraph`** (Strategy): the adapter unwrapped a graph pre-projected upstream in `useStrategyCanvas`/`usePresetGraph`, so `projectGraph` was decorative. Fix: move `buildStrategyGraph(parsed)` inside `projectGraph`, drop the pre-projected `graph` field from the surface-graph type, reduce the orchestrator hook to a thin query+state wrapper (no projection memo, no duplicate path). (b) **W002 — ignored `node` parameter** (World KB): `renderInspector(node)`/`renderAltView(node)` discarded the passed `node` and routed via `ctxRef.current.selection`, so a stale orchestrator selection rendered the wrong inspector. Fix: route from `node.data` (`candidateId`/`keyBlockId`) with id resolution against ctxRef graph lists; callbacks, cross-node graph context (`entities`/`candidates`), and the relationship edge-inspector path legitimately stay on `ctxRef` — they are handlers and graph lookups, not per-node data. (c) **W003 — `useAutoLayout` first-run override**: auto-layout clobbered surface-supplied positions on open. Fix: an explicit `hasSuppliedPositions?: boolean` on `CanvasSurfaceLayoutOptions` opts out of first-run dagre; the all-`{0,0}` heuristic was rejected because Strategy (layer layout) and World KB (deterministic grid) supply *meaningful non-zero positions AND opt into dagre* — a heuristic would false-positive them and change their behavior, violating no-domain-behavior-change. `relayout()` still overrides supplied positions on explicit author request. **Migration completion criterion**: a surface is "on the adapter" when it *genuinely delegates* projection + inspector routing to the adapter — not when the adapter module merely exists while the orchestrator still does the work. Shipping the interface (V1.114) and completing the migration (V1.115) are two separate gates; declare done only at the second. **Surface inventory (locked)**: there are **3 product surfaces / orchestrators** — Strategy, Outline+Timeline, World KB. `CanvasSurfaceKind` has **4 keys** (`strategy`, `outline`, `world-kb-entities`, `world-kb-relationships`): `world-kb-relationships` is a **reserved kind** (viewport/cache identity key for the relationship projection within the World KB surface), **not** a separate orchestrator — do not invent a fourth orchestrator to satisfy the enum. **Dagre compound-graph limitation**: `@dagrejs/dagre` crashes (`TypeError: Cannot set properties of undefined (setting 'rank')`) on compound graphs where an edge targets a node that has `setParent` children — exactly the Outline `volume → chapter` edge pattern where chapters own scene/beat children. Outline therefore keeps `layoutOptions: undefined` and uses the projection's built-in deterministic grid (matching pre-adapter behavior); a layout engine that handles compound graphs (e.g. elk-js) is the documented future evaluation path.

## Why This Matters

- **No raw file writes from the webview** is the load-bearing security/correctness boundary. Violating it (e.g., a whole-document PUT) reintroduces the V1.65 race between the human editor and the orchestration co-writer, which the node-granular patch model was built to eliminate.
- **OCC revision** prevents silent overwrites when the daemon (extraction, orchestration) and the author edit concurrently. Last-writer-wins is acceptable **only** for surfaces with a single-author threat model (e.g., findings triage — see `findings-lifecycle.md`); graph surfaces with a daemon co-writer MUST use OCC.
- **Conflict modal reuse** keeps the UX coherent across surfaces and bounds the implementation cost. A fifth bespoke modal would fragment recovery semantics.

## When to Apply

- Adding a new canvas surface (a fifth surface after Strategy/Outline+Timeline/World KB/Relationships).
- Adding a new structured-authoring Local API resource that a daemon co-writer and a human both edit (apply the OCC + conflict-modal layers even off-canvas).
- **Do NOT apply** OCC/conflict-modal to a surface with a genuine single-author threat model (e.g., findings triage, where the producer writes and a single author triages) — last-writer-wins is correct there, and forcing OCC adds cost without value.

## What Didn't Work (V1.65 → V1.75 pivot)

The V1.65 whole-document TipTap outline editor (`chapter-page.tsx` PUT save) could not validate or address individual outline nodes, and it raced with the orchestration co-writer. V1.75 retired it (canvas-pivot) in favor of the V1.72 node-granular canvas. The lesson: a document-editor model is the wrong abstraction for a graph-of-nodes that a daemon also mutates; use structured patch routes from day one.

## Examples (cross-reference)

- **Strategy β** (V1.71): `strategy.patch_state` / `patch_transition` / `patch_prompt_template` + `graphRevision` + `StrategyConflictError`.
- **Outline+Timeline β** (V1.72): `outline.patch_structure` / `patch_chapter` + `timeline.patch_event` + `outline_revision:` markdown frontmatter + `OutlineConflictError`.
- **World KB β** (V1.73): `world_kb.patch_entity` + `promote_candidate` + reuse of `kb_key_blocks.revision` / `kb_extract_jobs.version` + `WorldKbConflictError`.
- **World KB Relationships β/γ** (V1.74/V1.76): `world_kb.patch_relationship` + `kb_relationships.revision` + `needs_review` extraction gate + confidence-weighting.
- **Findings-remediation (V1.77)**: the **counter-example** — last-writer-wins, no OCC, no conflict modal (single-author triage threat model; see `findings-lifecycle.md`).
- **Outline spatial (V1.108)**: third spatial surface to follow this pattern. Confirmed layer 7 (projection data-completeness): paginated `useChapters()` + edges from full `outline.volumes[].chapter_ids` initially produced dangling edges → fix: auto-fetch-all + edge `Set` filter. Also confirmed additive wire escape hatch pattern (`unlink_foreshadow` op added to `TimelinePatchEventRequest` when daemon lacked unlink; schema→TS→Rust same commit; conflict-modal `changedFieldsOf` consumer must be updated for every new enum value).
- **Strategy spatial edge editing (V1.109)**: confirmed layer 8 — `onConnect` draft → inspector → `patch_transition(op:"create")` + command-aware conflict retry. The shipped V1.71 DTO was rewire-only; additive `op` field needed (schema+daemon+codegen one commit). Reconnect uses single `op:"update"` payload. Label field removed from UI when DTO lacks it (no silent drop).
- **Discoverability (V1.111)**: confirmed layer 11 — command palette + action registry (`command-registry.ts` / `use-hotkey.ts` / `command-palette.tsx`); sidebar Canvas group + `resolveActiveCanvasSurface` + chrome `isActiveItem?`; Design Studio `CanvasSurfacesFixtures` expanded with Strategy + World KB static chrome (Outline already mirrored V1.108). Residual: World KB sidebar item disabled when no `worldId` (no `/worlds` picker — `R-V1111P1-WORLDS-PICKER`).
- **Scene/Beat fixture-projection (V1.109)**: confirmed layer 9 — outline model has no scene/beat data; fixture-driven projection emits zero children on real Works (honest empty chrome); `wire_contracts_changed: false` preserved. `useOutlineCanvasGraph()` extract keeps orchestrator thin and makes selection-sync fix file-disjoint.
- **Graph scale + viewport (V1.109)**: confirmed layer 10 — module-level viewport Map cache + `onMove` (not `onViewportChange`); `selectionKey` primitive memo prevents effect overfire on position drags.
- **Surface adapter + auto-layout (V1.114)**: confirmed layers 12–13 — `CanvasSurfaceAdapter` + `useCanvasSurface` extracted; Strategy + World KB migrated (2 of 4 surfaces). `dagre` auto-layout with manual-override (`hasManualPositionRef` + Re-layout action); strict-mode fix (`useLayoutEffect` not `useMemo` for side effects); 50-node compound ~19ms. Test-mock stable-identity lesson: `useStrategyCanvas` mock returning fresh arrays per call → infinite re-project loop. `canvas-strategy-surface.md` §3.3.1 documents the adapter recipe.
- **Adapter contract convergence (V1.115)**: confirmed layer 14 — W001 Strategy passthrough fixed (`buildStrategyGraph` moved into `projectGraph`; `useStrategyCanvas` → thin query+state wrapper, no projection memo); W002 World KB node-param leak fixed (`renderInspector` routes from `node.data`, not `ctxRef.current.selection`); W003 `hasSuppliedPositions` explicit signal added (heuristic rejected — would false-positive Strategy/World KB supplied positions and change their behavior). Outline+Timeline migrated to `OutlineCanvasAdapter` + `useCanvasSurface()` (**3 of 3 product surfaces on the adapter**). Dagre compound-graph crash discovered → Outline keeps `layoutOptions: undefined` (built-in grid); `world-kb-relationships` confirmed as a reserved kind (no 4th orchestrator). All existing canvas tests pass; `wire_contracts_changed: false`.
