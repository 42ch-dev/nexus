# v1.190 Iteration Summary — Rust Core + Standalone TS Service

## What shipped

Six producer plans (P0–P5) plus P6 (CLI/Connect cutover) migrated the Nexus codebase from a daemon-mediated architecture to a **Rust core authority with a standalone TypeScript HTTP service**. All business logic now lives in `crates/nexus-core` (22+ modules); `apps/nexus-service` serves it over HTTP; `nexus42` CLI talks typed core APIs directly (no daemon round-trip for core operations).

## Key architectural decisions

1. **Single authority per domain** — World/KB/fork/timeline → core narrative; Work/outline/chronology → core work; actor/memory/SOUL/ToM → core memory+context; execution/lifecycle → core execution; capability dispatch → core capabilities; Connect invoke → core connect_invoke. No parallel handwritten shapes.
2. **Bearer isolation via typed carriers** — `AdmittedActor`/`ActorActivityLease`/`CharacterTransitionLease` enforce cross-bearer access control at the type level, not runtime checks.
3. **Non-blocking fences** — `character_busy` is observable (409), never awaited. `OwnerReservation` RAII ensures per-DB single-owner across processes.
4. **Scoped `CARGO_TARGET_DIR`** — `.envrc` auto-detects worktree context; feature worktrees get isolated `~/.cache/nexus-target-<name>`; merge gate requires cleanup before integration merge.
5. **Wire contracts from schemas** — `x-nexus-tri-state` annotation, 33 Strict drift registrations, per-module response-scoped type qualification.
