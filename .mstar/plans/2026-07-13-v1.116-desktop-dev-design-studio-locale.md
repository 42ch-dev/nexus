**Goal:** Make `pnpm dev:desktop` production-like (no Vite server spam) and
make design-studio previews show real localized **en** text.

**Architecture:** Two independent tracks. Track A: reconfigure Tauri dev mode
to load from pre-built `web/dist/` instead of a live Vite dev server, preserving
a `:web` variant for HMR. Track B: wrap the design-studio entry point with an
i18n provider that loads compiled en locale catalogs from web (web remains
locale SSOT).

**Tech Stack:** Tauri v2 config (JSON), TypeScript/React (design-studio entry),
i18next / react-i18next

**Execution:** mstar-sdd

## Problem Statement

Two maintainer-facing honesty issues block confident daily development on a
stabilize iteration:

### Track A — Desktop dev noise

`pnpm dev:desktop` runs `tauri dev` which (via `beforeDevCommand:
"pnpm --filter web dev"`) starts the Vite dev server at :5173. During the
Rust compilation phase (which takes minutes), Vite is already running and
polling the daemon API endpoint — but the Tauri sidecar hasn't started
yet → continuous "cannot connect to daemon API" errors in the console.

**Product expectation for the default desktop script:** behave like
double-clicking the installed app — load pre-built web assets, start the
daemon sidecar, render. No web server needed.

HMR remains available via an explicit variant: `pnpm dev:desktop:web`.

### Track B — Design-studio raw keys

`apps/design-studio` imports shared components from `@web-setup/*` which
use `react-i18next`'s `t()` function. But the Studio entry point does NOT
wrap the app in an i18n provider with loaded locale catalogs. Result:
preview surfaces show raw i18n keys (e.g., `setup.agent.verify`) instead
of actual text ("Verify").

The test setup (`src/test/setup.ts`) forces `i18n.changeLanguage('en')`
but this only works in tests, not in the live Studio preview.

**Why this pairs with P0:** Studio is used to review Setup/chrome copy that
P0 also touches (Verify, agent list). Raw keys make design review of that
work unreliable.

## User value

| Who | Outcome |
| --- | --- |
| Maintainers | Quiet, production-like desktop default; intentional HMR script |
| Design reviewers | Studio shows real en copy for shared components |
| Authors (indirect) | Fewer false "daemon broken" alarms; fewer copy mistakes from mis-previews |

## Scope

### Track A — Desktop dev script

**In scope:**
- `pnpm dev:desktop` loads from pre-built `web/dist/` (production-like)
- `pnpm dev:desktop:web` preserves current Vite + Tauri HMR mode
- Tauri config / package.json scripts adjusted accordingly
- No daemon connection errors during `dev:desktop` startup
- Brief docs in `apps/desktop/AGENTS.md` for when to use which mode

**Not in scope:**
- Auto-rebuild web on file change in `dev:desktop` mode (user runs
  `pnpm build:web` manually or uses `dev:desktop:web` for HMR)
- Tauri auto-reload when web dist changes (nice-to-have, not blocking)

### Track B — Design-studio locale

**In scope:**
- Studio entry wraps `I18nextProvider` (or equivalent i18next init) with
  en locale loaded from web's compiled JSON catalogs
- Studio preview surfaces show real text, not raw keys
- Source locale files stay in web; Studio imports compiled output only

**Not in scope:**
- Multi-language Studio (zh-CN etc.) — en only
- Studio editing locale content — read-only preview
- Locale SSOT migration — web remains the single source
- Dynamic locale bundle splitting (deferred residual)

## Global Constraints

- **Locale SSOT:** web's `src/locales/` is the source; Studio imports source
  JSON directly via `@web-locales/en` Vite alias (web locale files ARE the
  source — there is no compiled output step).
- **Tauri v2 config (AD-1):** `--config <file>` deep-merges a JSON patch.
  Empty `devUrl` → dev mode loads from `frontendDist`. Empty
  `beforeDevCommand` → no pre-dev hook. Base config unchanged; override in
  `tauri.dev.dist.conf.json`.
- **No circular deps:** Studio imports web's static JSON files (data-only,
  no module graph). Studio creates its own i18next instance — does NOT import
  web's `lib/i18n/config.ts` module (which would pull in web providers/hooks).
- **i18next instance:** Studio inits its own i18next instance (not shared
  with web's runtime singleton) to keep the two SPAs decoupled.
- **Missing file:** `apps/design-studio/src/lib/i18n/config.ts` does not
  exist yet — the test setup already references it. This plan creates it.
- **No wire/schema change.**
