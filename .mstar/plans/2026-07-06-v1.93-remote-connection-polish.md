## Context

V1.92 shipped the Remote Client Connection Model with four low/nit deferrals on the client surface. (1) `apps/web/src/lib/nexus/connection-storage.ts` load parses `localStorage` without validating the config shape — a corrupt entry feeds malformed config into the client rather than failing gracefully (qc1 S-001). (2) The browser certificate-fingerprint fetch in `browser-client.ts` + the error copy on `connect-daemon-page.tsx` cannot distinguish a self-signed-cert rejection from an unreachable daemon — the supported TOFU-capable surface is the desktop app (TOFU = Trust On First Use), so the copy should hint there (qc3 S-003). (3) `apps/desktop/src-tauri/src/connection_config.rs` **already has unit tests on `main`** (lines 142–317: keychain store/load, fallback file, delete, keychain-unavailable fallback — 5 tests via the `StubStore` seam). R-V192P1-003 may have been resolved during the V1.92 fix-wave; T3 below verifies coverage is sufficient and adds any missing edge case. (4) A reconnect to a same-endpoint pinned connection could surface a "pinned fingerprint matches" reassurance hint (qc1 S-002). All four are polish on the existing V1.92 surface — no new UI, no contract change.

## Scope (plan locked → tasks → implement)

### Tasks (coverage IDs)
- [x] **T1 — Connection-storage shape validation** (`apps/web/src/lib/nexus/connection-storage.ts`): add minimal schema/shape validation on load — validate the parsed object has the required `connection-config` fields (`endpointUrl`, `apiKey`, optional `pinnedFingerprint?`, optional `label?`) with correct types. On validation failure, discard the corrupt entry and surface a clear reset path (do not feed malformed config into the client). Pure additive guard; happy path unchanged.
- [x] **T2 — Fingerprint-fetch error copy** (`apps/web/src/lib/nexus/browser-client.ts` fingerprint path + `apps/web/src/pages/connect-daemon-page.tsx` error surface): when the fingerprint fetch fails, the browser cannot deterministically distinguish self-signed-cert rejection (browser blocks the fetch for security) from an unreachable daemon. The product direction (consistent with V1.92 TOFU model) is to surface a clear UI hint that the Nexus desktop app is the supported remote-connection surface for self-signed certs / TOFU. The copy must be honest about the limitation (browser path is secondary) without promising browser-remote will work for untrusted certs. Copy-only; no behavioural change to the fetch logic or new error classification.
- [x] **T3 — Desktop connection_config unit test verification + gap-fill** (`apps/desktop/src-tauri/src/connection_config.rs` tests, existing lines 142–317): existing tests on `main` already cover keychain store/load (line 232), fallback file read when keychain has no entry (line 253), keychain write + fallback cleanup (line 268), keychain-unavailable → fallback write (line 284), and delete both stores (line 299) — all via the `StubStore` seam. Verify these pass on CI (`cargo test -p nexus42-desktop` from the `src-tauri/` directory after `pnpm -w run sidecar`). If any test edge case is missing (e.g., get reads fallback when keychain returns generic error but fallback file is also missing), add it. Do NOT re-implement or refactor the `CredentialStore` trait abstraction — it is already test-hermetic.
- [x] **T4 — Reconnect pinned-match hint** (`apps/web/src/pages/connect-daemon-page.tsx` reconnect flow): when reconnecting to an endpoint whose pinned fingerprint matches the served fingerprint, surface a reassurance hint ("Fingerprint matches the trusted daemon" or equivalent consistent with the existing fingerprint-block voice). Product decision: this is low-surface reassurance on an already-detected happy-path state (`reconnectWithMatch`); it reinforces the TOFU trust model for users returning to a pinned endpoint. Not a new affordance or navigation change. If copy review during polish finds it noisy, the hint may be omitted without affecting other acceptance.
