**Goal (product outcome):** A contributor can open Design Studio (no daemon) and **visually accept** V1.122/V1.123 World Timeline + Work Timeline **node chrome** in light and dark — so Timeline visual QA no longer requires launching `apps/web`. In the same plan, the root `AGENTS.md` UI Component Policy (Studio-first) becomes the durable, committed rule that makes this the default path for every future visual surface.

**Architecture:** Follows the V1.106 Studio-first workflow and the V1.115 `@web-canvas/node-chrome-shell` extraction precedent. **Boundary locked** in `.mstar/iterations/v1.124/specs/studio-timeline-fixture-boundaries.md` (architect Phase 1 seat 2):

1. **Card shell** — direct-consume existing `@web-canvas/node-chrome-shell`.
2. **Timeline body chrome** — **new** `apps/web/src/components/canvas/presentational/timeline-node-chrome.tsx` exported as `@web-canvas/timeline-node-chrome` (six body components: Brief-era / Event / KeyBlock / Work Narrative / Moment scene / Moment beat). **No new Vite alias root** — existing `@web-canvas/*` → `canvas/presentational/*`.
3. **RF wrappers** stay App-local: `NodeChromeShell` + `Handle`s + body extract; i18n/contracts stay in wrappers; extract receives resolved strings only.
4. Event/Work-Narrative badge colors migrate to `--color-canvas-layer-narrative-accent` inside the shared extract (V1.123 P4 layer-feel completion — not a density redesign).

New fixture files under `apps/design-studio/src/fixtures/`; sections in `surfaces.tsx`. Guardrails: no new alias allowlist entry required for P0.

**Tech Stack:** React 18, Vite 6, Tailwind 3, `@xyflow/react` (forbidden in Studio — extract must be RF-free), `@nexus/design-tokens`, `@42ch/nexus-ui`, lucide-react.

**Execution:** mstar-sdd (multi-task plan)

## Global Constraints

- **Studio import boundary** (`apps/design-studio/AGENTS.md`): no `@xyflow/react`, no `@42ch/nexus-contracts`, no daemon clients, no `apps/web/src/lib/nexus/**`, no app providers/contexts. Allowed: `@web-canvas/*`, `@nexus/design-tokens`, `@42ch/nexus-ui`, `@/lib/utils` (cn only).
- **Transitional annotation required** for any new `@web-canvas/*` import (`// @web-canvas/<name> — transitional until …` on the module-specifier line, per V1.106 guardrail).
- **Both themes** (`light` + `.dark`) must render correctly for every fixture variant — see `studio-fixture-acceptance-criteria.md`.
- **i18n**: Studio fixtures are developer-facing — no `t()` calls; static English fixture strings only (per `apps/web/AGENTS.md` § i18n "User-facing-only catalogs").
- **Voice & Content (still applies):** fixture labels use product vocabulary (Brief / Narrative / Moment / Timeline / Layer / KeyBlock) and DESIGN.md Voice tone — clear, non-marketing, no ACP jargon. English-only ≠ free-form slang.
- **Accessibility baseline for fixtures:** interactive chrome in fixtures (Layer breadcrumb segments, focusable node chrome if any) must preserve visible focus and the same aria patterns the App extract uses (`aria-current` on active breadcrumb segment, etc.). Do not strip a11y attributes "because it's a fixture."
- **Tokens SSOT**: every accent / fill / border consumes `@nexus/design-tokens` CSS variables; never invent a token inline. New tokens (if P0 surfaces a missing one) → root `DESIGN.md` first, then `tooling/design-tokens/src/tokens.css`; never invent in fixture. (Gallery registration of any new token is P1's job — coordinate if P0 adds one.)
- **Same-extract fidelity**: fixtures compose the **same presentational extract** App uses (or a thin props-driven shell of it). No hand-redrawn parallel CSS that drifts from shipped App chrome.
- **AGENTS.md policy land is Task 1**: the root `AGENTS.md` already has the UI Component Policy section on disk (uncommitted). This plan **commits** it first so fixture work implements a known rule, not the other way around.
- **No `@42ch/nexus-ui` promotion in P0**: Timeline RF wrappers stay App-local; body extract is `studio-local fixture` path. Promotion decisions are P3.
- **Boundary SSOT**: Do not re-open extract vs hand-mirror — follow `studio-timeline-fixture-boundaries.md`. F4 requires App + Studio both import `@web-canvas/timeline-node-chrome`.
- **No Layer breadcrumb in P0 fixtures** — owned by P2 (`surface-audit-checklist.md` §4.2).
- **Studio Tests**: `pnpm --filter design-studio test` must remain green. Add smoke tests for new fixtures mirroring `src/App.test.tsx` conventions.
