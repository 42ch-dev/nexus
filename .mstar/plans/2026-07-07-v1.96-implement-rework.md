#### T1: Shared `errorMessage()` helper extraction (C2 foundation)

**Files**: new `apps/web/src/lib/error-message.ts` +
`apps/web/src/pages/setup-step-daemon.tsx` (remove inline helper, import
shared) + `apps/web/src/pages/setup-step-welcome.tsx` (replace
`String(err)`-style with shared helper).

Extract a single canonical helper:

```ts
export function errorMessage(err: unknown): string {
  if (err && typeof err === 'object' && 'message' in err) {
    const msg = (err as { message: unknown }).message;
    if (typeof msg === 'string' && msg.length > 0) return msg;
  }
  if (err instanceof Error) return err.message;
  if (typeof err === 'string') return err;
  return '';
}
```

Notes:
- Check `'message' in err` BEFORE `instanceof Error` (Tauri invoke errors
  are plain objects with `message` field, not `Error` instances — this is
  the V1.95-style reverse order bug in the welcome step).
- Return empty string for unknown shapes (callers decide fallback copy).
- Replace both wizard-step call sites. Add a vitest for the helper
  covering: `Error`, `{message:'x'}`, `'{message:42}'` (non-string),
  `'string'`, `undefined`, `null`, plain `{}`.

#### T3: Rust sidecar stderr capture (C3 — closes `R-V195-ARCH-STRERR-GAP`)

**Files**: `apps/desktop/src-tauri/src/sidecar.rs`.

Capture the daemon's stderr from the `_rx` event receiver returned by
`command.spawn()`. Strategy (per Phase 1 D3 RCA guide — read it before
starting):

- Spawn a bounded async task that drains `_rx` for `Terminated`/stderr
  events and appends them to an `Option<String>` in `SidecarInner` (e.g.
  `last_stderr_tail: Option<String>`, capped at 2 kiB tail).
- On the Error transition in `start_with_budget` (where `detail` is
  currently set to a generic message), append the captured stderr verbatim
  if non-empty: e.g. `format!("{message}\n\nDaemon output:\n{stderr_tail}")`.
- Keep the existing generic messages as fallback when stderr is empty.
- Do **not** block the spawn path on stderr reading — the task runs
  concurrently with `wait_for_first_health`.
- Update `DaemonStatus` serialization if needed (the existing `detail:
  Option<String>` field carries the combined message — no schema change).

Add unit tests for the stderr-tail cap and the append formatting (use the
existing test pattern in `sidecar.rs:526+`).

**Constraint**: the daemon process must still be killed on failed start
(existing `child.kill()` logic) — stderr capture is purely additive for
diagnostic surfacing, not a lifecycle change.

#### T4: React daemon-step subscribe + timeout + `'starting'` fix (C3)

**Files**: `apps/web/src/pages/setup-step-daemon.tsx`.

**Prerequisite read**: `.mstar/iterations/v1.96/guides/daemon-startup-rca.md` §1
(Bug 1 — subscription race analysis).

Four fixes (the D3 RCA guide confirms the daemon crashes, not hangs — all fixes
are wizard-side; no daemon-side T9 needed):

1. **Initial state probe on mount**: before subscribing via
   `desktop.onDaemonStatusChanged`, call `desktop.getDaemonStatus()` once to
   fetch the current daemon state. This closes the "event already fired" race:
   on a clean `~/.nexus42/` first launch, the daemon exits within milliseconds,
   SidecarManager transitions to Error, and `notify()` fires **before** the SPA
   subscribes. Without this initial probe, the SPA never learns about the Error
   and stays in "Starting daemon…" forever — even after adding the `'starting'`
   branch. If the daemon is already Running/Error/Starting, transition
   immediately; then subscribe for future changes.
2. **`'starting'` branch**: in the `onDaemonStatusChanged` callback, add
   `else if (status.state === 'starting') { /* no-op or subtle "still working" indicator */ }`.
   The default UI ("Starting daemon…" spinner) already covers this; the
   fix is to NOT leave the callback silent (which previously meant no
   state change ever happened for the first event after subscription).
3. **Hard timeout**: add a `setTimeout` (e.g. 25s) that fires if no
   terminal status (`'running'` / `'error'` / `'stopped'`) arrived. On
   fire: call `desktop.getDaemonStatus()` once to fetch the current state
   (the daemon may have transitioned without emitting an event the SPA
   caught); if still non-terminal, surface a "Taking longer than expected"
   state with the existing Retry / Reset buttons. Clear the timeout in the
   effect cleanup.
4. **Error display**: when `status.state === 'error'`, show `status.detail`
   verbatim (which now includes the captured stderr thanks to T3). Closes
   the loop on real daemon-error surfacing.

Coordinate with T2 on toast wiring for this file.
