## Context

V1.90 made remote bind opt-in but the listener is plain `tokio::net::TcpListener` + `axum::serve` (`boot.rs` §10) — zero TLS in the workspace. Remote bind therefore exposes the API key + manuscript in cleartext. P0 adds auto self-signed cert generation (rustls + `rcgen`), a TLS listener path for non-loopback binds, integrates the remote-bind gate with TLS presence (fail-closed), and exposes the cert fingerprint via the P-1-locked read-only endpoint. Folds in R-V191P1-004 (backend mid-batch error test).

## Scope (plan locked → tasks → implement)

### Tasks (coverage IDs)
- [ ] **T1 — Self-signed cert generation + persistence** (`crates/nexus-daemon-runtime/src/tls/` or `boot.rs` helper): on first boot, generate an ECDSA/Ed25519 self-signed cert via `rcgen`, persist PEM under `~/.nexus42/tls/` (paths via `nexus-home-layout`); reuse across restarts; compute SHA-256 DER fingerprint (colon-hex). Idempotent: if cert+key exist and parse, reuse; else generate.
- [ ] **T2 — TLS listener path** (`boot.rs` `Transport` + §10): when bind is non-loopback **and** a usable cert exists, serve via rustls (`tokio-rustls` wrap of accepted `TcpStream`s, or `axum-server` `bind_rustls` per P-1 T1 lock). Loopback binds stay plain HTTP. Unix-socket transport unaffected.
- [ ] **T3 — Remote/TLS gate integration** (`boot.rs` `ensure_remote_bind_allowed`): remote bind (non-loopback) now additionally requires a usable TLS cert; refuse to start with a clear error if remote bind is requested but no cert can be loaded/generated. Fail-closed, consistent with V1.90.
- [ ] **T4 — Fingerprint endpoint** (`api/handlers/` + router): read-only, **no auth** (fingerprint is a public trust anchor). Returns the pinned SHA-256 fingerprint per the P-1 T2 contract. Path + schema from P-1. **This is the P0↔P1 seam** — the ONLY cross-track dependency: P1 calls this endpoint for TOFU confirmation. See P-1 "P0↔P1 Seam" section for the contract boundary.
- [ ] **T5 — Regression tests** (`tests/`): (a) cert generation idempotent (second boot reuses); (b) remote bind refused without a usable cert (fail-closed); (c) TLS handshake succeeds against the generated cert (rustls client accepts); (d) fingerprint endpoint returns the pinned value on a TLS-configured daemon; (e) fingerprint endpoint returns HTTP 200 with `fingerprint: ""` on a loopback-only daemon (no TLS cert) — the "reachable but no cert" contract from P-1 T2, distinct from an unreachable endpoint; (f) loopback plain-HTTP still works (no regression).
- [ ] **T6 — R-V191P1-004 mid-batch internal-error test** (`tests/findings_api.rs` + `api/handlers/findings.rs`): add a test that injects a DAO error mid-batch in `batch_update_findings`, asserts partial persistence (some IDs updated before the error) + a 5xx response. Closes R-V191P1-004.
- [ ] **T7 — Startup observability** (`boot.rs`): log the cert fingerprint + TLS status at INFO on startup so the user / connecting client can see the trust anchor.

- R-V191P1-004 closed (`lifecycle: resolved` with resolution commit).
