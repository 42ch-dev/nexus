## Specify

### Problem

Contributors cannot visually browse or validate Nexus UI tokens, brand VI, and component states in one place. The DESIGN contract is split across root and `apps/web`, causing drift risk. We need `apps/design-studio` as a comprehensive read-only gallery and a unified DESIGN SSOT consumed by `apps/web` and the studio.

**Outcome:** contributors complete the [token tuning journey](../iterations/v1.98/guides/design-studio-information-architecture.md) (Prepare plan Journey A) without daemon; authors see no studio UI in the shipped product.

### Gallery section priorities

| Priority | Section | Route | Ship gate |
| --- | --- | --- | --- |
| **P0** | Tokens | `/tokens` | Required for P0 Done — all scalar scales in active theme |
| **P0** | Brand VI | `/brand` | Required — 4 logos + mark + theme.css |
| **P0** | Components | `/components` | Required — full ui primitive matrix (IA guide §4.3) |
| **P1** | Voice & Content | `/voice` | Required for QA Pass — ≥3 labeled samples |
| **P1** | Surface slices | `/surfaces` | Required for QA Pass — Setup card + shell chrome |

P0 tasks (T1–T5) may land before P1 sections; **iteration Done** requires all five sections observable in QA.

### Scope

In scope:

- Execute DESIGN merge per `design-unification.md`: root `DESIGN.md` + `DESIGN.dark.md` as sole SSOT; remove `apps/web/DESIGN*.md`.
- Update `apps/web` token consumers (`src/index.css`, `tailwind.config.ts`, docs/AGENTS references).
- Bootstrap `apps/design-studio`: Vite + React + TypeScript + Tailwind (match apps/web toolchain conventions).
- Register in `pnpm-workspace.yaml` and root `package.json` scripts if needed.
- Implement gallery sections per IA guide (priorities above):
  - **Tokens** — colors, typography, spacing, rounded, semantic scales
  - **Brand VI** — `@42ch/nexus-ui` logos, marks, theme.css swatches
  - **Components** — all `apps/web/src/components/ui/*.tsx` primitives with variants/states
  - **Voice & Content** — labeled specimens from DESIGN § Voice & Content (IA guide §4.4)
  - **Surfaces** — Setup wizard step slice + App shell chrome slice (IA guide §4.5 fixtures)
- Light/dark theme toggle wired to DESIGN pair.
- Unit/smoke tests: studio renders key sections; web visual regression via existing component tests (no snapshot churn unless token merge requires it).
- `apps/design-studio/AGENTS.md` finalized.

Out of scope:

- nexus-ui shadcn migration.
- Live token editing / YAML write-back.
- Daemon/Tauri integration.
- Product feature changes in apps/web beyond DESIGN path migration.

## Clarify

- Studio **imports** apps/web `components/ui/*` via `@web-ui/*` Vite alias (transitional coupling — see `design-unification.md` §7).
- **CSS pipeline:** shared `@nexus/design-tokens` workspace package (`tooling/design-tokens`) — Tailwind preset + `tokens.css`; both apps consume; no duplicate `theme.extend`.
- Visual parity bar: post-merge apps/web must match pre-merge appearance (allow documented intentional fixes from `design-unification.md` §9 only).
- Pre-1.0: breaking DESIGN path change is allowed.
