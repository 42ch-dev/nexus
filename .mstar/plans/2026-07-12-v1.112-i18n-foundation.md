## Problem

`apps/web` has no i18n library, no locale preference, and ~800–1500 hardcoded
user-facing English strings. Authors who prefer 简体中文 cannot use the Control
Room in their language. Theme already uses a `localStorage` + system preference
pattern; language has no equivalent.

## User value

Authors get a discoverable **Appearance → Language** control, system-locale
default with English fallback, and instant switch — the same product-quality bar
as theme. P0 proves the pattern on shell/nav/settings so P1 can migrate the
rest without re-litigating architecture.

## Scope

Land the i18n runtime, persistence, Settings Appearance Language control, product
conventions, and a **sample migration** of shell / nav / settings chrome so P1
has a proven pattern.

## Architecture locks (plan-lock — architect 2026-07-12)

Evidence: `theme-provider.tsx` (localStorage + system resolve + `document.documentElement`
side effects), `main.tsx` provider stack, `settings-shell-layout.tsx` + `App.tsx`
settings routes, `apps/web/AGENTS.md` i18n pointer.

### 1. Library & init module

- **Deps (P0 T1):** `i18next`, `react-i18next` in `apps/web/package.json`.
- **Init:** `apps/web/src/lib/i18n/config.ts` — create/configure the singleton
  `i18n` instance, register namespaces, import JSON catalogs from
  `src/locales/{en,zh-CN}/`. No daemon/wire changes.
- **Types:** `LocalePreference = 'system' | 'en' | 'zh-CN'`;
  `ResolvedLocale = 'en' | 'zh-CN'`.

### 2. LocaleProvider (mirror ThemeProvider)

- **File:** `apps/web/src/components/locale-provider.tsx` (parallel to
  `components/theme-provider.tsx`).
- **Storage key:** `nexus-web-locale` (same semantics as compass).
- **Resolve order:** `readStoredLocale()` → `resolveSystemLocale()` (`zh*` →
  `zh-CN`, else `en`) → fallback `en`.
- **Context API:** `{ preference, resolvedLocale, setPreference }` where
  `setPreference` updates React state, `i18n.changeLanguage(resolvedLocale)`, and
  `document.documentElement.lang = resolvedLocale`.
- **System follow:** when `preference === 'system'`, subscribe to
  `window` `languagechange` (and initial read of `navigator.language`) to
  re-resolve — same role as `ThemeProvider`'s `matchMedia` listener for
  `'system'` theme.
- **Mount order in `main.tsx`:** inside `ThemeProvider`, wrapping
  `ToastProvider` → `AppProviders` (locale is independent of theme tokens):

```text
ThemeProvider → LocaleProvider → ToastProvider → AppProviders → App
```

- **Tests:** add `LocaleProvider` to `test-providers.tsx` (or a dedicated
  `renderWithLocale` helper) for settings/shell tests; unit-test resolve/persist
  in `locale-provider.test.tsx` mirroring `theme-provider.test.tsx`.

### 3. Catalog layout & namespace map (P0 seeds; P1 extends)

```text
apps/web/src/locales/
  en/
    common.json      # shared actions, generic errors, loading labels
    shell.json       # header, sidebar, mobile nav, route titles, not-found
    settings.json    # settings shell + Appearance/Language (P0)
    setup.json       # (stub in P0; P1 migrates setup wizard)
    canvas.json      # (stub in P0; P1)
    reading.json     # (stub)
    findings.json    # (stub)
    memory.json      # memory / soul / chapters chrome (stub)
    commands.json    # command-palette action labels + group headings (stub)
  zh-CN/
    (same nine files)
```

| Namespace | P0 keys (minimum) | P1 expansion |
|-----------|-------------------|--------------|
| `common` | Save, Cancel, Loading…, generic toast titles | relative-time fragments if not using `Intl.RelativeTimeFormat` everywhere |
| `shell` | sidebar + `MOBILE_NAV` + `ROUTE_TITLES` + Settings page title/helper | remaining shell chrome |
| `settings` | section nav (Agent, Workspace, **Appearance**, Advanced), Appearance page, Language field + three option labels + helper | agent/workspace/advanced bodies |
| `setup` | — | setup wizard (P1) |
| `canvas` | — | inspectors, panels, canvas commands (non-palette) |
| `reading` | — | reading toolbar, inspectors |
| `findings` | — | list/detail chrome |
| `memory` | — | memory, soul, chapters |
| `commands` | — | all `useRegisterCommand` label/group keys (P1) |

**Key convention:** dot-separated within namespace file, Title Case English
source strings per DESIGN.md §Voice & Content — e.g. `settings.appearance.title`,
`shell.nav.works`, `commands.go.strategy.label`. Interpolation uses i18next
`{{name}}` syntax; no string concatenation in components.

**i18n config:** register all nine namespaces in `config.ts` even when stubbed
(empty `{}`) so P1 add keys without init changes.

### 4. Settings Appearance — route & nav integration

| Touchpoint | File | Change |
|------------|------|--------|
| Route | `App.tsx` | `<Route path="appearance" element={<SettingsAppearanceSection />} />` under `/settings` |
| Section page | `pages/settings/settings-appearance-section.tsx` | **new** — Language `<select>` or radio group bound to `useLocale().setPreference` |
| Shell nav | `pages/settings/settings-shell-layout.tsx` | Add **Appearance** entry to `SETTINGS_SECTIONS` (four-tab nav: Agent → Workspace → Appearance → Advanced); `id: 'appearance'`, `to: '/settings/appearance'`, icon `Palette` or `Languages`, labels via `t('settings.nav.appearance')` |
| Index redirect | `App.tsx` | Keep default `<Navigate to="agent" />` — Appearance is discoverable, not default landing |
| Header title | `root-layout.tsx` `ROUTE_TITLES` | `/settings` stays "Settings"; Appearance section title is in-section `h2` via `settings.json` |

Nav order (locked): **Agent → Workspace → Appearance → Advanced**.

Theme toggle remains in `header.tsx` (`useTheme`) — not moved into Appearance.

### 6. Command registry & format.ts (P0 defers behavior; P1 implements)

- **Command registry:** P0 does **not** change `Command` shape. P1 lock (see
  P1 plan/spec): `labelKey` + render-time `t()` in palette — documented here so
  P0 stubs `commands.json` and does not register translated commands yet.
- **format.ts:** P0 does **not** wire locale. P1 adds `getActiveLocale()` and
  replaces `Intl.DateTimeFormat(undefined, …)` call sites (see P1 spec).
