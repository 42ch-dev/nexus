## Problem statement (specify)

The desktop app's "Daemon starting" phase is noticeably slow on launch. The
user reports it "feels like a sidecar detection issue." Investigation of
`apps/desktop/src-tauri/src/sidecar.rs` confirms the cold-start path pays a
sequential round-trip before the bundled `nexus42` binary is even spawned:

1. `start_with_budget` runs `probe_health(port)` with
   `HEALTH_PROBE_TIMEOUT = Duration::from_secs(2)` (sidecar.rs:31, :557).
2. Only after that probe fails (returns `None`) does it spawn the sidecar
   (:247) and enter `wait_for_first_health` polling every
   `HEALTH_POLL_INTERVAL = 250ms` up to `HEALTH_START_TIMEOUT = 15s` (:582).

On a true cold start (no daemon running) the connect-refuse is usually fast,
but the *requirement* to probe-then-spawn-then-poll is the structural source
of the felt slowness, and any port-occupied edge makes the 2s budget visible.

## User value

A faster, less "stuck" first-launch. Authors reach the agent picker (and the
canvas) sooner; "Daemon starting" no longer feels like a hang.

## Scope / Non-goals

In scope:

- Eliminate the redundant pre-spawn probe on the **cold-start auto path** when
  the port is known free (or make it non-blocking / speculative).
- Preserve the **attach** path (`probe_health` succeeding → attach without
  ownership) for the manual `start_daemon` and "user ran `nexus42 daemon start`
  first" case — that must keep working.
- Surface startup progress so the UI is not blank during `wait_for_first_health`.
- Timing evidence / test that the cold-start path does not pay the probe
  round-trip.

Non-goals:

- Reducing the daemon's own boot time (DB migrations, subsystem init) — that is
  daemon-runtime work, not sidecar-lifecycle work.
- Replacing the bundled-sidecar model with an in-process library link
  (V1.67+ scope per `apps/desktop/AGENTS.md`).
- Crash-restart backoff tuning (already covered by `MAX_RESTART_ATTEMPTS`).

## Long-term target state

The desktop sidecar manager starts the bundled daemon **optimistically** — a
sub-50 ms three-valued port gate lets it spawn as soon as the port is known
`Free`, while reserving the HTTP attach probe for the `Occupied`/`Unknown` cases
(external daemon already running, or port inconclusive). The UI sees a
`Starting` → `Running` transition without a probe tax on a true cold start.

## Proposed approach (locked — architect §5.2)

- Introduce a **three-valued** `probe_port_state(port) -> PortState { Free, Occupied, Unknown }`
  (generalizes the existing `tcp_reachable` at sidecar.rs:573; tight ≈150 ms gate
  timeout via `tokio::time::timeout`). Loopback connect resolves in <10 ms
  normally, so the gate is sub-50 ms in the steady case.
- In shared `start_with_budget`: `Free` → spawn immediately, **skip** HTTP probe.
  `Occupied` → HTTP `probe_health` → attach or port-conflict error.
  `Unknown` → HTTP `probe_health` → attach or spawn. Both auto (`start`) and
  manual (`start_daemon`) paths use the gate; `reset_budget` budget semantics
  are untouched.
- Keep HTTP `probe_health` (2 s timeout) for: (a) any `Occupied`/`Unknown` port,
  (b) the existing `wait_for_first_health` poll loop, (c) the failure-diagnostic
  `tcp_reachable` call. Attach-without-ownership is preserved because
  `Occupied`/`Unknown` always run the HTTP probe.
- Two-phase poll in `wait_for_first_health`: `HEALTH_POLL_INTERVAL_FAST = 100 ms`
  for the first `FAST_POLL_WINDOW = 1 s`, then the existing 250 ms interval.
  Compute locally; do not lower the global `HEALTH_POLL_INTERVAL` constant.
- Emit `tracing` logs with a stable `phase` field (`port_probe`, `attach_probe`,
  `spawn`, `wait_for_ready`) for diagnostics. No `DaemonState` enum change, no
  wire change.

### Task 1 — `probe_port_state` three-valued gate + `Free` skip-probe path

Implement `probe_port_state(port) -> PortState { Free, Occupied, Unknown }` generalizing the existing `tcp_reachable` (sidecar.rs:573). Tight ≈150ms gate timeout via `tokio::time::timeout`. Loopback connect resolves in <10ms normally.

In shared `start_with_budget`: `Free` → spawn immediately, **skip** HTTP probe. Both auto (`start`) and manual (`start_daemon`) paths use the gate; `reset_budget` budget semantics untouched.

**DoD:** `Free` short-circuit skips the HTTP `probe_health`; `start`/`start_daemon` signatures unchanged.

### Task 2 — Preserve attach path: `Occupied`/`Unknown` → HTTP probe

`Occupied` → HTTP `probe_health` → attach (owned=false) or port-conflict error. `Unknown` → HTTP `probe_health` → attach or spawn. Reuses `probe_health`. Preserves attach-without-ownership invariant (`owned=false` on attach). Manual `start_daemon` unchanged in semantics.

**DoD:** external daemon (user ran `nexus42 daemon start` first) still attaches without ownership; port-conflict still errors.

### Task 3 — Two-phase poll + `phase` tracing

Compute locally; do not lower the global `HEALTH_POLL_INTERVAL` constant. Emit `tracing` logs with a stable `phase` field (`port_probe`, `attach_probe`, `spawn`, `wait_for_ready`). No `DaemonState` enum change, no wire change.

**DoD:** first-second polls at 100ms; phase logs present; global constant unchanged.

### Task 4 — Timing test / evidence
