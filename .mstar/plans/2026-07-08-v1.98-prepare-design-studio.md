## Specify

### Problem

Nexus has **two DESIGN sources** (repo root brand contract + `apps/web` consumption copy) that drift in completeness and values. Contributors lack a **visual gallery** to tune UI/UX/brand VI and preview components. A design-studio auxiliary app is requested; it requires a **single SSOT** and a written contract before implementation.

**Contributor pain today:** token changes require mentally merging two YAML files, running the full web app (often with daemon), and grep-driven component inspection — no dedicated light/dark preview or brand VI board.

### Product requirements (studio IA)

Normative IA: [`iterations/v1.98/guides/design-studio-information-architecture.md`](../iterations/v1.98/guides/design-studio-information-architecture.md).

| Requirement | Detail |
| --- | --- |
| Nav structure | Five top-level sections: **Tokens**, **Brand**, **Components**, **Voice**, **Surfaces** |
| Default landing | `/tokens` — foundations first |
| Theme control | Persistent light/dark toggle in app chrome |
| Read-only affordance | Visible hint that SSOT is `DESIGN.md` on disk; no in-app editor |
| Section priority | P0: Tokens, Brand, Components · P1: Voice, Surfaces (same iteration) |

### User journeys

#### Journey A — Contributor token tuning (primary)

1. Clone repo; `pnpm install`; `pnpm --filter design-studio dev`.
2. Open **Tokens**; toggle dark mode; note baseline swatches.
3. Edit repo-root `DESIGN.md` / `DESIGN.dark.md` (e.g. adjust `brand-cyan` or `gray-700`).
4. Refresh studio; confirm swatches and **Components → Button** matrix update.
5. Run `pnpm --filter web test` + build to confirm product consumers still resolve tokens.
6. Open PR with DESIGN diff + screenshot evidence from studio (both themes).

**Success:** steps 1–6 completable without daemon; contributor cites studio screenshots in PR.

#### Journey B — Frontend dev component reference

1. Open **Components** while implementing a screen in `apps/web`.
2. Find primitive (e.g. **Select**); verify open/closed and focus states in both themes.
3. Match variant names to DESIGN `components.*` tables in root SSOT.

**Success:** no need to mount isolated Storybook or full Setup flow to check a primitive.

#### Journey C — Brand VI review

1. Open **Brand** section.
2. Review all four logo variants on appropriate light/dark panels.
3. Confirm clear-space callout matches `nexus-ui` `logoMinSizePx` / `logoClearSpaceRatio`.

**Success:** brand reviewer does not open README + Figma + web app separately.
