## Problem statement (specify)

After opening the app, **all** agents show "Not installed" even though the
user has several agent CLIs installed. Root-cause investigation of
`crates/nexus-daemon-runtime/src/path_enrichment.rs`
(`login_equivalent_bin_dirs`) shows the enriched PATH directory list omits the
most common Node.js version-manager global bin locations:

- **nvm** — `~/.nvm/versions/node/<ver>/bin` (the default for the majority of
  macOS developers; npm-global agent CLIs land here). Not covered.
- **volta** — `~/.volta/bin`. Not covered.
- **fnm** — `~/Library/Application Support/fnm/aliases/default/bin` (macOS).
  Not covered.
- **pnpm** — `~/Library/pnpm` (macOS) / `~/.local/share/pnpm`. Not covered.
- **yarn** — `~/.yarn/bin`. Not covered.

The current list covers `.local/bin`, `bin`, `.cargo/bin`, `.npm-global/bin`,
`.bun/bin`, `.asdf/shims`, `.local/share/mise/shims`, and the homebrew /
`/usr/local` absolutes — but **not** the version-manager dirs above. Since many
agent CLIs (Codex, Claude Code, etc.) install via `npm install -g`, and most
macOS devs use nvm, the daemon's `which::which(binary)` probe
(`crates/nexus-acp-host/src/registry.rs:585`) cannot find them. This is the
deferred residual `R-V1101P0-003` materializing as a real user-facing bug.

## User value

Agents the author actually installed are detected as "Installed" without
forcing the custom-launch escape hatch. The picker becomes trustworthy.

## Scope / Non-goals

In scope:

- Expand `login_equivalent_bin_dirs()` to resolve version-manager global bin
  dirs: nvm (active version + glob fallback), volta, fnm, pnpm, yarn.
- Existence-gate every added dir (keep PATH free of dead entries).
- Unit tests covering the nvm node-bin glob case and at least one other
  version manager.
- Optional: lightweight scan diagnostics (log count of resolved extra dirs at
  enrichment time) so future false-negatives are debuggable.

Non-goals:

- Replacing the static-dir approach with a login-shell `echo $PATH` shell-out
  (higher-risk; explicitly out of scope per Non-Goals — the comment in
  `path_enrichment.rs` says "No shell-out").
- Changing the ACP registry format (read-only consumer).
- Agent **launch/execution** reliability (detection only).
- Windows version-manager resolution beyond the existing light touch
  (macOS/Linux are the reported platforms).

## Long-term target state

`login_equivalent_bin_dirs()` returns a login-shell-equivalent bin dir set for
the common macOS/Linux developer toolchains, so `scan_local_installations`
reports the same `installed` verdict a login shell would — without shelling out.

## Proposed approach (locked — architect §5.2)

- **nvm (active-version-first):** `nvm_root = $NVM_DIR` if set else `~/.nvm`.
  Read `<nvm_root>/alias/default`; resolve target with ≤2 alias-hops →
  `<nvm_root>/versions/node/<target>/bin`, existence-gated. If alias absent or
  resolved dir missing: glob `<nvm_root>/versions/node/*/bin`, take the **single
  highest-semver** match (handle `v`-prefixed + bare names; compare as semver),
  existence-gated. **Never glob-all.**
- **volta:** `$VOLTA_HOME` if set else `~/.volta` → `<volta_home>/bin`.
- **fnm:** `~/Library/Application Support/fnm/aliases/default/bin` (macOS) /
  `~/.local/share/fnm/aliases/default/bin` (linux); fallback `~/.fnm/current/bin`.
- **pnpm:** `$PNPM_HOME` if set else `~/Library/pnpm` (macOS) /
  `~/.local/share/pnpm` (linux).
- **yarn:** `~/.yarn/bin`.
- All additions existence-gated; de-duped by the existing `merge_path`.
- Extend the existing `apply_process_path_enrichment` `tracing::info!` with a
  `vm_managers` field listing resolved manager names.
