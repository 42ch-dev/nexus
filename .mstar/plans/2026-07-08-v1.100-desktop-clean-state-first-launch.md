# P0 — Desktop Clean-State First-Launch Completion

**Goal:** Close the clean-state desktop first-launch gap so a fresh local install can complete setup, bootstrap creator/workspace state, start the daemon, and reach the main UI.

**Architecture:** The desktop shell gates sidecar auto-start until setup state is ready. The setup wizard performs the minimum creator/workspace bootstrap through desktop-only Tauri IPC before the daemon-ready step. Existing-install launch behavior remains unchanged.

**Tech Stack:** Tauri v2 desktop shell, React setup wizard, `nexus42` sidecar, desktop Rust unit tests, Web Vitest tests.

**Execution:** mstar-sdd

## Product Framing

**User value:** A new author should be able to double-click the desktop app on a clean machine and reach Nexus without terminal setup or a hidden `No active creator` daemon failure.

**Problem statement:** V1.97 fixed the sidecar state machine and spawn-name path, making the daemon reachable. That revealed the next blocker: `.setup()` starts the daemon before any creator/workspace state exists, while the wizard has no bootstrap invoke.

**Target state:** Clean-state setup becomes an intentional wizard path: choose workspace, bootstrap local creator/workspace state, start daemon, detect agent, finish setup, land in the main UI.

**Acceptance posture:** The product is not complete when the daemon can be started in isolation; it is complete when the native desktop app carries a clean-state author to the main UI and preserves existing-install launch behavior.

**Non-goals:** No full `creator bootstrap` Work/intake flow, no schema changes, no signing/notarization/auto-update, no Windows/Linux release hardening.
