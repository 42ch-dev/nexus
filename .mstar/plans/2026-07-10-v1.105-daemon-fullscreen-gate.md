# P0 — App-Level Fullscreen Daemon Gate (D2)

**Goal:** Make daemon readiness an application-level fullscreen launch gate; always auto-start the sidecar (rewrite V1.100 Rule 13); stop treating Daemon as a wizard step.

**Architecture:** Tauri `.setup()` always starts/attaches sidecar (`lib.rs` ~697–711). **Outer** `DaemonLaunchGate` (new, wraps `AppRoutes` in `App.tsx`) blocks all desktop launches until Ready via `DaemonReadySplash`. **Inner** `SetupGate` routes by `setup_completed` only (splash logic removed). `/setup` is sibling under outer gate, not inside `SetupGate`. Wizard Daemon step retired; diagnostic UX migrates from `setup-step-daemon.tsx` to splash/gate.

**Interfaces:**
- Tauri: `SidecarManager::start` unconditional in `.setup()`; `get_setup_completed` / `set_setup_completed` unchanged
- Web: `DaemonLaunchGate` → health probe + `onDaemonStatusChanged`; `SetupGate` → `<Navigate to="/setup" />` vs `children`
- Recovery: timeout/retry/`resetLocalDatabase` on splash (from former daemon step)

## Product Framing

**User value:** Waiting for the local daemon is a **launch ritual**, not a setup preference. Authors never enter Agent selection or the wizard before the daemon can scan. The app owns daemon startup; the wizard owns author choices only.

**Author journey:** App open → fullscreen splash → Ready → (if setup incomplete) wizard at `/setup`; (if setup complete) main UI. Daemon never appears as a numbered wizard step.

**Iteration gate:** Must complete before P1 Agent-first wizard (scan depends on Ready).

**Non-goals:** Wizard step reorder (P1); portrait chrome (P2); Tauri PATH agent scan; wire/schema changes; changing V1.103 Re-run Setup semantics (marker clear only).

## Acceptance Criteria

1. Clean-state launch auto-starts sidecar without requiring `setup_completed=true` (D2 — rewrite V1.100 Rule 13).
2. Author sees fullscreen Daemon wait before **both** `/setup` and main UI (first-launch and return visits).
3. After Ready + `setup_completed=false`, only `/setup` is reachable for product routes (main shell blocked).
4. After Ready + `setup_completed=true`, main UI loads (existing post-setup path).
5. Settings Re-run Setup (V1.103 R1): after marker clear, author still passes fullscreen gate before wizard.
6. Timeout / retry / diagnostic affordances remain available (V1.96/V1.97 parity); migration-reset recovery reachable from splash error paths.
7. Prefer no schemas change.
