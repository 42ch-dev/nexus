# P0 - i18n Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `mstar-sdd`. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Migrate remaining ~110 hardcoded user-facing strings on Control Room
product pages/dialogs in `apps/web` to i18n `t()` calls, fix catalog hygiene,
cache Intl formatters, and make locale preference input fail closed.

**User value:** zh-CN authors no longer see English on Works, Schedule,
Sessions, Strategies, and Capabilities list+detail flows and two common dialogs —
completing the V1.112 localization promise for product pages.

**Architecture:** Extends V1.112 i18n foundation.

**Namespace decision (locked):**

| Surface | Namespace file | Notes |
|---------|----------------|-------|
| Works list + work detail + patch-work dialog | `works.json` | Keys: list, `workDetail.*`, `dialog.patchWork.*` |
| Schedule list | `schedule.json` | |
| Sessions list | `sessions.json` | |
| Strategies list + strategy detail + validate-preset dialog | `strategies.json` | Keys: list, `strategyDetail.*`, `dialog.validatePreset.*` |
| Capabilities list | `capabilities.json` | |
| Shell chrome / routes / not-found | `shell.json` | **Route labels only** — consolidate `mobileNav.*` → `route.*` |

Do **not** dual-SSOT page copy under both `shell.works.*` and `works.json`. If
unused page-specific keys exist under `shell.json`, remove or migrate them into
the page namespace during Task 1.

**Tech Stack:** React, react-i18next, TypeScript

**Execution:** mstar-sdd

**Priority:** Must (iteration Done gate)

**blocked_by:** none (P1 may run in parallel; P2 depends on this plan)

## Problem / Scope / DoD

### Problem

V1.112 migrated primary shell/canvas/settings. ~110 hardcoded strings remain in
9 page/dialog files → zh-CN users still see English on core Control Room pages.

### In scope

- Migrate the nine files listed in Tasks 2–3
- Catalog scaffold + `shell.json` duplicate-key consolidation (R-P0-002)
- `setPreference` runtime guard (R-P0-004)
- Intl formatter cache (R-P1-002)
- Close R-P0-005 (not a bug)
- Final grep audit of production UI modules under `apps/web/src/pages` and
  product components; fix any leftover user-facing hardcodes found there

### Out of scope

- Design-studio string migration (P2 may fix design-studio **tests** only)
- CLI / daemon messages
- Languages beyond en / zh-CN
- Bundle splitting (R-P0-003)
- Wire contracts

### Definition of Done

- Nine target files use `t()` for all user-facing copy; en + zh-CN catalogs
  parity-checked
- Shell mobile nav uses `route.*` only (no duplicate `mobileNav.*` keys)
- Runtime guard + formatter cache implemented and tested
- Full `apps/web` test + typecheck green
- Residual closures documented for R-P0-002 / R-P0-004 / R-P0-005 / R-P1-002 as
  applicable at plan QC

## Global Constraints

- Follow V1.112 i18n conventions: caller-owned presentational copy; user-facing-only catalogs
- Namespace convention: `<page-name>.json` per page (see locked table above)
- Key naming: dot-separated, camelCase leaf (e.g., `works.emptyTitle`, `works.columns.status`)
- Both `en` and `zh-CN` catalogs must be updated in lockstep
- `wire_contracts_changed: false` - no schema/DTO changes
- CLI / daemon messages remain English-only
- Design-studio is NOT in scope for string migration
- Existing tests must pass; new/updated tests required for migrated pages
- Catalog paths are `apps/web/src/locales/{en,zh-CN}/` (not `src/i18n/locales/`)
- i18n config is at `apps/web/src/lib/i18n/config.ts` (not `src/i18n/index.ts`)
- `IntlFormatterCache` key must include locale **and** format options (different
  callers use different `dateStyle`/`timeStyle` combos); `formatUtcAndLocal`
  uses a hardcoded `'en-US'` for the UTC branch, which is locale-independent
- **P0 / P1 parallel safety:** P0's Task 5 grep audit may find hardcoded strings
  in files P1 is modifying for opacity sweep (`sidebar.tsx`, `command-palette.tsx`,
  `chapters-page.tsx`, canvas components). If so, defer those string fixes to P1's
  branch or coordinate at integration merge to avoid conflict. These files were
  largely migrated in V1.112 P1, so the risk is low.

**Interfaces:**
- Consumes: V1.112 i18n foundation (`LocaleProvider`, `useTranslation`)
- Produces: Catalog namespaces for all unmigrated product pages; shell route SSOT

- [ ] **Step 1: Consolidate duplicate `route.*/mobileNav.*` keys in `shell.json`**

  Remove 7 duplicate `mobileNav.*` keys; have mobile nav reference `route.*`
  keys instead. Update both `en` and `zh-CN`.

- [ ] **Step 2: Create new catalog namespaces**

  Create `works.json`, `schedule.json`, `sessions.json`, `strategies.json`,
  `capabilities.json` for both `en` and `zh-CN`. Extract all hardcoded strings
  from the 9 target files into keys under the locked namespace table (include
  detail + dialog keys even if wiring lands in Tasks 2–3).

- [ ] **Step 3: Remove or migrate page-specific keys currently under `shell.json`**

  `shell.json` currently holds page-specific copy (`works.*`, `workDetail.*`,
  `schedule.*`, `sessions.*`) that was scaffolded in V1.112 P0 but is not yet
  consumed by the pages (pages still use hardcoded strings). Migrate these keys
  into the dedicated page namespace files created in Step 2. After migration,
  `shell.json` should contain only route/chrome/not-found/daemon/profile/health
  keys. Avoid dual SSOT: page copy must not remain as `shell.works.*` (or
  similar) after page namespaces exist.

- [ ] **Step 4: Register new namespaces in `lib/i18n/config.ts`**

  Add static imports + resource bindings for all new namespaces. The `namespaces`
  const array in `config.ts` also generates the `Namespace` type via
  `typeof namespaces[number]`, so adding to the array automatically extends the
  type. Three coordinated changes required: (1) static imports at top, (2) add
  to `namespaces` array, (3) add to `resources` object for both `en` and `zh-CN`.

- [ ] **Step 5: Verify catalog parity**

  Ensure `en` and `zh-CN` have identical key sets per namespace (scripted key-set
  diff is fine).

- [ ] **Step 6: Commit**
