## Problem Statement

Light Mode interactive chrome is disharmonious for author dogfood:

- Neon cyan (`blue-700` / `brand-cyan` `#25D1E0`) on light is **突兀** — **Dark only** for primary signal/CTA.
- Light primary `brand-deep-blue` (#0D2B3E) on fills feels too **办公**.
- Product chrome often **bypasses** Studio Components `Button` (e.g. shell mode `bg-brand-cyan`).
- `TransportErrorBlock` filled primary Retry is **太大、太突兀** on red alert.
- Canvas timeline / Narrative selection still use light `blue-700`.

**User value:** Calm Chronos teal in Light Mode; consistent SSOT; unobtrusive error actions.

## Goal

1. Lock light interactive = **`brand-cyan-1000` (`#117480`)** + white on fills; dark keeps neon cyan CTA.
2. Keep ink `brand-deep-blue` for titlebar / logo / **text links** (not interactive fills).
3. Retarget light canvas/selection/wizard/shell/spinner aliases to cyan-1000.
4. `TransportErrorBlock` CTAs → **compact text links** (ErrorState-aligned) at primitive SSOT.
5. Enforce reuse — no parallel product VI.

## Light VI lock

| Role | Light | Dark |
|------|-------|------|
| Primary Button fill | `brand-cyan-1000` + white | `brand-cyan` + deep-blue label |
| Selection / active / canvas accents / spinners | `brand-cyan-1000` | neon cyan / `blue-700` |
| Text links / titlebar / logo ink | `brand-deep-blue` | unchanged |
| Neon cyan `#25D1E0` | not light interactive default | primary signal |
