**Files:**

- Possibly modify: `apps/design-studio` test setup / vitest config

**Interfaces:**
- Consumes: V1.112 i18n foundation patterns (LocaleProvider in tests)
- Produces: Design-studio tests pass without the known pre-existing failures

- [ ] **Step 1: Diagnose root cause of failing tests**

  Run: `pnpm --filter @42ch/nexus-design-studio test` and capture output.
  Classify: missing i18n provider vs hardcoded string assertions vs fixtures.

  **Architect note (V1.113 Phase 1 review):** Root cause is confirmed by code
  inspection. Design-studio imports `AgentPicker` from `@web-setup/agent-picker`
  (alias to `apps/web/src/components/setup/agent-picker`). After V1.112 i18n
  migration, `AgentPicker` likely calls `useTranslation()`. Design-studio does
  NOT initialize i18next or wrap renders in `LocaleProvider` (no i18n imports
  found in `apps/design-studio/src/`). The fix is to initialize i18next in the
  design-studio test setup (import `lib/i18n/config.ts` or a minimal i18n init)
  so `useTranslation()` returns a valid `t` function. If the component also
  asserts on translated strings, update assertions to match `t()` output or use
  locale-independent testids. If root cause is different (not i18n), keep the
  escape hatch: document and defer with rationale + residual update.

- [ ] **Step 2: Fix test environment (prefer LocaleProvider in setup)**

- [ ] **Step 3: Update string assertions to t() output or locale-independent checks**

- [ ] **Step 4: Run tests — expect PASS**

  Run: `pnpm --filter @42ch/nexus-design-studio test`

- [ ] **Step 5: Commit**
