## Product Framing

**User value:** Soft pills have visible edges; solid tone provides high-contrast emphasis when needed.

**Author-facing outcome:** Contributors can review Soft vs Solid in Studio; product callers keep default soft without a forced cutover.

**Non-goals:** Forced product cutover to solid; Iconify; schemas / wire changes; finding-status / memory independent token trees; treating Stretch P2 items (or P1 Settings work) as this plan’s blockers.

## Acceptance Criteria (Must — this plan)

Measurable for automated / Studio gates (human desktop smoke is **not** required for this plan’s Done):

1. Soft borders are visibly stronger on light backgrounds per contract (neutral `gray-alpha-400` or equivalent; semantic ≈ 50% alpha).
2. `tone="solid"` renders all six variants with solid semantic fill, white text, and no visible border (light + dark maps in DESIGN).
3. Default `tone` is soft; omitting `tone` matches pre-V1.102 soft appearance aside from the intentional border strengthen.
4. Studio `/components` Badge section shows Soft row + Solid row (6 variants each); `VariantLabel` is label-only.
5. Package tests cover default soft, explicit solid, and border-related classes; README documents the `tone` axis.
6. No `schemas/` change; no Iconify; no forced `StatusBadge` cutover.
