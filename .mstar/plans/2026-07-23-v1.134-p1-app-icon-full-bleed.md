## Problem Statement

**User impact:** For ~5 iterations the macOS Dock / Launchpad tile has looked wrong — a **flat un-rounded square** instead of a normal macOS app icon. Authors judge product quality from the Dock tile before opening the app.

**Corrected root cause (do not re-litigate "inset shrinks the mark"):**  
`compose-app-icon.mjs` rasterizes `logo-primary-square.svg` at **768×768** onto a **fully transparent** 1024×1024 canvas (`background: { alpha: 0 }`) with a **128px transparent margin** per side. macOS Big Sur+ applies the automatic squircle mask **only to opaque icons that fill the canvas**; the transparent alpha border **defeats the mask**, so the icon renders as a flat un-rounded square. The squircle clipping plate corners **is** the intended rounded look.

## User value

Nexus looks like a normal macOS app in the Dock: system squircle rounding applied. Docs and Studio stop teaching the transparent-inset anti-pattern so the bug does not return.

## Goal

The macOS desktop app icon renders as a **normal macOS app icon** — macOS applies its automatic Big Sur squircle mask (rounded corners), instead of showing a flat un-rounded square.

## Priority

**Must.** No Stretch (no multi-OS marketing assets, no signing, no alternate mark experiments).

## Architecture (corrected root cause)

**Fix:** rasterize `logo-primary-square.svg` as an **opaque full-bleed 1024×1024** square (no resize-to-768, no transparent composite) so macOS masks it to the squircle.

**Honest caveat (PM / agents cannot view the icon this session):** the transparency-defeats-mask theory is the highest-probability cause and matches the symptom, but **Task 1 is an actual RCA**, not a pre-baked fix — the rebuilt opaque asset must be confirmed (**by the author**, after `killall Dock`) to now show macOS rounding.
