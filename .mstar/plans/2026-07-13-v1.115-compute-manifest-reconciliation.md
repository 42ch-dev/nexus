## Problem

V1.114 shipped a compute module registry (`list_modules()` / `get_module()` in
`crates/nexus-wasm-host/src/registry.rs`) that bridges the hand-written
`ModuleManifest` Rust struct to the generated `ModuleDetail` wire type via a
**JSON round-trip** (`serde_json::to_value` → `from_value`). This was deliberate
V1.114 debt (R-V1114P2QC1-W002): the round-trip works today because the two
shapes happen to match, but it **masks drift** — a field added to one type and
not the other silently disappears or fails at runtime instead of failing at
compile / schema-gate time.

This matters because the next compute work (module authoring SDK, more
modules, canvas↔compute intersection) will land on the manifest shape. A
JSON-bridged manifest is an unverified contract.

Product outcome: the compute manifest is **single-source and gate-verified** —
`ModuleManifest` and generated `ModuleDetail` are reconciled so drift fails the
build/gate, not the registry at runtime. **Authors see no Modules panel
behavior change.**

## Goals

1. Eliminate the JSON round-trip bridge in `registry.rs::manifest_to_detail()`.
2. Reconcile `ModuleManifest` with generated `ModuleDetail` via typed
   non-lossy `From<&ModuleManifest> for ModuleDetail` (all 15 fields shared
   per architect audit — no runtime-only split today).
3. Ensure schema drift detection passes bidirectionally and is **proven** to
   fail on deliberate drift.
4. Preserve embedded-module loader (`embedded_module_manifest`) — type-level
   reconciliation only.
5. Document wire vs runtime-only field split in `compute-module-abi.md` §7 if
   the audit clarifies it.

## Global Constraints

- **Generated type is the wire target** (STRATEGY: wire contracts are truth) —
  do not reverse reconciliation.
- **No wire-contract change by default**: `@42ch/nexus-contracts` stays at
  current version unless T1 finds a client-exposed field missing from schema
  (additive only).
- **All manifest fields are wire-promoted today (architect finding)**: all 15
  `ModuleManifest` fields — including `compute_export` and `init_export` — are
  present in `module-detail.schema.json` and thus in generated `ModuleDetail`.
  There is **no runtime-only field split today**. Use non-lossy `From`, not
  `TryFrom`. Do not invent runtime-only fields to justify `TryFrom`.
- **Schema-drift gate coverage (architect finding)**: the drift gate registers
  `module-detail.schema.json` ↔ generated `ModuleDetail` (`Strict` mode) and
  `module-summary.schema.json` ↔ `ModuleSummary` (`Strict`). It does **NOT**
  register the hand-written `ModuleManifest`. Once T2 ships the typed `From`,
  manifest↔generated drift becomes a **compile error** (a field on one struct
  but not the other fails compilation). That is stronger than the JSON
  round-trip. T3's deliberate-drift test demonstrates this compile-time
  guarantee.
- **Embedded-module loader preserved**: `embedded_module_ids()` /
  `embedded_module_manifest()` / `build.rs` compile-from-source flow unchanged.
- **Runtime-only fields kept (forward-looking)**: if a future field is
  genuinely runtime-only (e.g., a cached compiled-artifact handle), add it to
  `ModuleManifest` but NOT to the schema; the typed `From` simply omits it.
  Today none exist.
- **No new compute module**: `basic-combat` remains the only module.
- **Fully parallel to P0/P1**: compute crate only; no canvas overlap.

## Tasks (SDD)

### T1 — Audit ModuleManifest ↔ ModuleDetail field overlap
- **Architect pre-audit (done this seat):** all 15 `ModuleManifest` fields are
  wire-promoted — every field (`module_id`, `name`, `version`,
  `nexus_abi_version`, `required_key_block_types`, `compute_export`,
  `init_export`, `description`, `author`, `host_functions`, `schemas`,
  `battle_report_kind`, `max_fuel`, `max_memory_mib`, `max_wall_time_ms`) is
  present in `module-detail.schema.json`. Generated `ModuleDetail` carries all
  15. There is **no runtime-only field split today**.
- Enumerate every field on `ModuleManifest` (hand-written) and `ModuleDetail`
  (generated) to confirm the pre-audit against generated source. Classify:
  shared (all 15), wire-only (none), runtime-only (none today).
- Document the (empty) runtime-only classification in the iteration spec
  (append table). The table records "all wire; no split today" so a future
  runtime-only field has a clear precedent.
- **Product rule:** do not invent new product fields; promote only if already
  client-visible but schema-missing (T1 audit confirms: none missing).
- **Done when:** classification table exists (confirming all-shared); drift
  list explicit (empty today).

### T2 — Typed conversion (eliminate JSON round-trip)
- **Architect decision — `From`, not `TryFrom`:** since all 15 fields are
  shared and the conversion is non-lossy, implement
  `impl From<&ModuleManifest> for ModuleDetail` (field-by-field copy). Do NOT
  use `TryFrom` — there is no lossy field today, and `TryFrom` would imply a
  fallible conversion that cannot fail.
- **Enum representation check:** `ModuleManifest.host_functions` is
  `Vec<HostFunction>` (Rust enum, `#[serde(rename_all = "snake_case")]`).
  Verify the generated `ModuleDetail.host_functions` uses the same string-enum
  representation (`"kb_read"`, `"narrative_query"`). The `From` impl maps
  `HostFunction::KbRead → <generated enum>::KbRead` (or the equivalent string
  if the generated type uses `String`). Confirm against generated source.
- `registry.rs::get_module()` uses the typed conversion.
- **Done when:** AC-P2-1 + AC-P2-5.

### T3 — schema_drift_detection bidirectional gate
- **Architect finding — current coverage:** `schema_drift_detection.rs`
  already registers `module-detail.schema.json` ↔ `ModuleDetail` (`Strict`)
  and `module-summary.schema.json` ↔ `ModuleSummary` (`Strict`) at lines
  198–213. The gate covers **schema ↔ generated**. It does NOT cover
  hand-written `ModuleManifest` (different crate: `nexus-wasm-host`, not
  `nexus-contracts`).
- **Two-layer drift enforcement after T2:**
  1. **Schema ↔ generated** (existing gate, already proven `Strict`): run
     `./tooling/check-wire-drift.sh`; confirm compute entries pass.
  2. **Manifest ↔ generated** (new, compile-time by construction): the typed
     `From<&ModuleManifest> for ModuleDetail` makes a field on one struct but
     not the other a **compile error**. This is stronger than any runtime
     gate.
- **Deliberate-drift test (AC-P2-2):** add a doc-test or integration test
  that demonstrates the compile-time guarantee — e.g., a `#[test]` asserting
  the `From` impl exists and is total (or a code comment documenting that
  removing a field from `ModuleDetail` without updating the `From` impl fails
  `cargo build -p nexus-wasm-host`). The test proves the mechanism, not just
  assumes it.
- If a future runtime-only field is added to `ModuleManifest` (not in
  `ModuleDetail`), the `From` impl simply omits it — no gate change needed.
- **Done when:** AC-P2-2 + AC-P2-3.

### T4 — manifest_to_summary consistency
- `manifest_to_summary()` already builds `ModuleSummary` field-by-field (typed,
  not JSON) — it is the correct pattern.
- **Architect decision — no shared helper with `manifest_to_detail`:** since
  all 15 manifest fields are shared and `ModuleSummary` is a strict subset +
  runtime `status`, a shared extraction helper adds abstraction with little
  benefit (YAGNI). The typed `From<&ModuleManifest> for ModuleDetail` makes
  detail-field forgetfulness a compile error; summary-field forgetfulness is
  caught by the AC-P2-4 regression test (`list_modules()` vs `get_module()`
  agree on shared fields for `basic-combat`).
- Add a one-line cross-reference comment between the two functions so a future
  field addition is flagged in both places.
- Test: `list_modules()` and `get_module()` agree on shared fields for
  `basic-combat`.
- **Done when:** AC-P2-4.
