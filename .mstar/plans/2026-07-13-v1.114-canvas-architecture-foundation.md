## Problem

Authors open canvas to **steer** structure, but large graphs force minutes of
manual node-dragging first (top deferred canvas pain since V1.72). Four shipped
surfaces also each re-wire the same shell boilerplate, so the next surface
pays full copy-paste tax. Product outcome: readable graphs on open + a recipe
for surface #5.

## Goals

1. Extract `CanvasSurfaceAdapter` interface + `useCanvasSurface()` shared hook.
2. Migrate ≥2 of the 4 shipped surfaces to consume the adapter.
3. Integrate dagre auto-layout (`useAutoLayout()` or shell-level option) with a
   discoverable **Re-layout** action.
4. Consolidate shared canvas hooks (viewport, selection, dirty-state).
5. Update `canvas-strategy-surface.md` §3.3 with the adapter pattern recipe.

## Acceptance criteria (product-facing)

- [ ] Opening a migrated surface with a non-trivial graph yields a readable
  auto-layout without mandatory manual positioning
- [ ] **Re-layout** is available on canvas chrome; manual drag sticks until
  Re-layout
- [ ] ≥2 shipped surfaces use the shared adapter; existing surface tests pass
  (no domain-behavior regression)
- [ ] Adapter + layout recipe documented in `canvas-strategy-surface.md` §3.3

## Global Constraints

- **No domain-behavior change**: surface write ops, node semantics, and
  inspectors stay surface-owned. All existing canvas tests pass unchanged.
- **Manual override preserved**: auto-layout never overrides an author's manual
  drag until the next explicit "Re-layout" action.
- **Layout is ephemeral**: do not persist positions to the daemon this plan.
- **Route-split preserved**: `@xyflow/react` + `dagre` stay in the canvas route
  chunk, not the Control Room bootstrap.
- **DESIGN.md tokens**: no new canvas tokens required (layout is positional, not
  visual styling).

## Tasks (SDD)

### T1 — `CanvasSurfaceAdapter` interface + `useCanvasSurface()` hook
- Define the `CanvasSurfaceAdapter<TGraph, TNodeData, TEdgeData>` interface
  (projectGraph, nodeTypes, edgeTypes, layoutOptions, adaptConflict,
  renderInspector, renderAltView, summarizeGraph). See the locked interface
  sketch in the iteration spec.
- Implement `useCanvasSurface(adapter, queryResult)` owning graph projection,
  conflict state, alt-view toggle, inspector selection. **Delegates** viewport
  caching to the existing `useCanvasViewport(surfaceKey)` and **stubs** the
  auto-layout integration point (consumed by T4) as a no-op pass-through.
- Unit tests: adapter projection correctness, conflict adaptation, alt-view
  toggle state.

### T2 — Migrate Strategy canvas to the adapter
- Refactor `strategy-canvas/canvas-layout.tsx` to consume
  `useCanvasSurface()` + a `StrategyCanvasAdapter`.
- All existing Strategy canvas tests pass unchanged.

### T3 — Migrate World KB canvas (entities) to the adapter
- Refactor `world-kb/world-kb-canvas.tsx` to consume
  `useCanvasSurface()` + a `WorldKbCanvasAdapter`.
- All existing World KB canvas tests pass unchanged.

### T4 — Dagre auto-layout integration
- Add `dagre` (or `@dagrejs/dagre`) dependency to `apps/web`.
- Implement `useAutoLayout(nodes, edges, options)` hook: computes positions,
  respects parent/child group nesting. Reads `adapter.layoutOptions.direction`
  (default "TB") per surface.
- Wire into the `useCanvasSurface()` stub from T1 (the hook owns layout
  application; T4 fills in the computation) + expose a "Re-layout" action in
  `CanvasShell` chrome.
- Manual-override suppression: per-node `isManualPosition` or surface-level
  `layoutDirty`.
- Tests: layout produces valid positions; manual drag suppresses re-layout;
  re-layout action repositions; compound/group nodes (parentId + extent:parent)
  participate correctly.

### T5 — Architecture documentation
- Update `canvas-strategy-surface.md` §3.3 with the adapter pattern as the
  canonical surface-addition recipe.
- Document `useAutoLayout` integration + manual-override semantics.

## Risks

- dagre produces poor layouts for wide/irregular graphs → provide manual
  override + per-surface layout-direction option.
- **Dagre compound-graph performance** (architect flag): profile with a 50-node
  compound graph before P0 Done; if layout latency > 200ms, cap visible nodes or
  lazy-expand subgraphs; record threshold breach as a residual.
- Adapter migration introduces subtle regressions → SDD per-task review + QC tri;
  all existing tests are the regression gate.
