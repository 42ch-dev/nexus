## 1. Problem Statement

`@42ch/nexus-ui` was shipped in V1.83 as an assets/tokens/theme-CSS-only package (deliberately "framework-neutral — no React components"). Its own README defers a React component library to "a later plan after P2 proves stable usage." V1.85 (app icons) proved stable usage: `apps/web` consumes the SVG assets via a hand-written `components/brand/nexus-logo.tsx` (31 lines, 2 call sites) and `logo-mono.svg` ships but is **unconsumed**. The brand identity is duplicated in app-local code rather than structuralized as a shared library — exactly the gap the deferred roadmap item targets.

Separately, V1.86 left one medium same-class security residual: `R-V186-QC1-S005` — `nexus.manuscript.body.read` (`host_tool_handlers.rs:2155-2156`) still uses the string-prefix `starts_with` anti-pattern that V1.86 T3 eliminated for `fs/*`. The remote-reach vector is closed by V1.86 T1 (CORS Origin allowlist), so the finding is latent/medium, but the class is real. The fix is a short delegation to the canonical `resolve_guarded_path` (three concrete steps — see §5 P1-T1).

**User value (honest framing)**: For authors today there is **zero visible UX change** — the sidebar/header Nexus mark renders identically (same asset, same sizing, same theme behavior). The value is foundation plumbing: it eliminates duplication (the 31-line hand-written wrapper + unconsumed `logo-mono.svg`) and makes the Nexus brand a single structural source of truth inside the monorepo. When desktop (or future surfaces) consume the package they inherit coherence without copy-paste; for contributors, the surface area where brand drift can occur shrinks. This is the maturation of a deferred roadmap item (V1.83 README) into a real shared library — not a new author-facing feature.

P1 is a small latent security hygiene item. Bundling it as a companion batch avoids a separate hotfix round for a same-class pattern. Headline remains P0.

## 2. Goals

React as peer dep only. No theme context, no layout primitives.

3. **Surface `logo-mono.svg`** via `<NexusMark>` (previously shipped but unconsumed).
4. **Close `R-V186-QC1-S005`** (P1 companion) by delegating `nexus.manuscript.body.read` path validation to the canonical `resolve_guarded_path` (V1.86 T3 pattern). One regression test.
5. **Amend package docs** (`AGENTS.md` + `README.md` + `package.json`) to reflect React components shipped; version 0.1.0 → 0.2.0. No `web-ui.md` change (internal package evolution, not a product-contract surface change).

### Batch P0 — `@42ch/nexus-ui` React Component Library (frontend)

#### P0-T1 — Package build + dependency posture
- Add `react` + `react-dom` as **peer deps**; `@types/react` + `@types/react-dom` as dev deps in `packages/nexus-ui/package.json`.
- Enable JSX: add `"jsx": "react-jsx"` to `tsconfig.json` `compilerOptions` (required for `tsc --noEmit` typechecking of `.tsx` files). tsup's esbuild auto-detects JSX — no `--jsx` CLI flag needed; the existing `--format cjs,esm --dts` build command is sufficient.
- Bump version `0.1.0` → `0.2.0`; update `description` to drop "no React components".
- **Constraint: no `.svg` imports in package source.** tsup/esbuild cannot resolve `.svg` files — the components will use consumer-provided `src` prop (NexusLogo) or hand-authored JSX (NexusMark) instead.

- **Done when**: package builds with JSX enabled, React peer deps declared, and no `.svg` import errors.

#### P0-T2 — `<NexusLogo>` component (presentational, explicit variant, bundler-agnostic)
- New `packages/nexus-ui/src/components/nexus-logo.tsx`:
  - Props: `variant: 'primary' | 'color' | 'white' | 'mono'` (required), `src: string` (required — the consumer-resolved SVG URL, see below), `label?: string` (default `'Nexus'`), `className?: string`, `size?: number` (height in px, default 32).
  - Renders `<img src={src} alt={label} width={auto} height={size} decoding="async" />`.
  - **No theme context import.** Pure presentational.
  - **SVG import strategy — bundler-agnostic design**: The component does NOT import `.svg` files in its source. tsup/esbuild cannot resolve `.svg` imports — a component library must remain bundler-agnostic. Instead, the component accepts the resolved SVG URL via the `src` prop. The consumer (apps/web thin wrapper, P0-T4) imports the SVGs through Vite (which natively resolves `.svg` → URL string) and passes the URL to the component. This keeps the package buildable without Vite-specific loader configuration and compatible with any consumer bundler.
  - Export a helper constant `VARIANT_FILENAMES: Record<Variant, string>` mapping variant → asset filename (e.g. `'logo-primary.svg'`) for consumers that need programmatic filename lookup.
- Unit test (vitest or the package's existing test setup): mocks `src` prop (no `.svg` import in test either); covers all 4 variants with correct alt text + className forwarding + size.
- Re-export from `src/index.ts`.
- **Done when**: `<NexusLogo variant=...>` is a documented public export accepting `src` prop, with a passing unit test.

#### P0-T3 — `<NexusMark>` component (inline mono, currentColor, hand-authored JSX)
- New `packages/nexus-ui/src/components/nexus-mark.tsx`:

Hand-authoring as JSX is bundler-agnostic (no Vite `?raw` or tsup `text` loader needed) and concise (~50 lines of JSX).

  - Props: `label?: string`, `className?: string`, `size?: number` (default 24 — the documented `logoMinSizePx`).
  - Inline SVG includes `<title>` for a11y (per package README accessibility section).
- Unit test: renders inline SVG with expected viewBox, inherits `currentColor` via styled parent, respects `size`, includes `<title>`.

### Batch P1 — manuscript.body.read Path-Guard Fast-Follow (Rust runtime security)

#### P1-T1 — `nexus.manuscript.body.read` path validation fix
- `crates/nexus-daemon-runtime/src/api/handlers/host_tool_handlers.rs` (~line 2128-2162, the `nexus.manuscript.body.read` handler guard block): replace the existing two-branch guard (`abs_body.exists()` → canonicalize + `Path::starts_with`; else → string-prefix `abs_body_str.starts_with(&workspace_root)`) with delegation to the canonical `resolve_guarded_path` from `api/path_guard.rs`.
- **Delegation shape** (not a blind one-liner — three concrete steps):
  1. Determine `must_exist` before the call: `let must_exist = abs_body.exists();` — the existing file must pass canonicalize-based guard; a missing file must pass the parent-walk guard (so it falls through to FILE_READ_FAILED, preserving existing behavior).
  2. Call `resolve_guarded_path(workspace_root_path, &body_path, must_exist)` — this replaces **both** branches of the current guard (the `abs_body.exists()` canonicalize block AND the else string-prefix block).
  3. Map the returned `NexusApiError::BadRequest` (with `chapter_path_*` codes from path_guard.rs) to `NexusApiError::InvalidInput { field: "body_path", reason: ... }` — the handler's existing error shape.
- Reuse the existing `api/path_guard.rs` helper — do **not** duplicate logic.
- **Done when**: the handler delegates to `resolve_guarded_path`; no string-prefix comparison remains in this path; both the existing-file and missing-file code paths are guarded by component-wise `Path::starts_with` (via `resolve_guarded_path`).
