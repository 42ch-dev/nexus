## Architecture lock

- **Dependencies:** implementation starts after P4’s locked token projection is merged. P0 remains a soft integration dependency; P1 may proceed while P0 finishes, but shell acceptance cannot close with Restart red.
- **Shell boundary:** `RootLayout` owns dual-pane placement, overlay titlebar integration, and global overlay/provider mounts. Props-driven chrome lives under `components/layout/presentational/**` for Studio `@web-layout/*` fixtures; routing, creator queries, Tauri calls, and selection state remain app-local.
- **Settings shell:** one app-level modal host owns open/close state, focus trap/restore, scroll lock, URL section resolution, and dirty registrations. Desktop content is at least `80vw × 80vh` with viewport bounds; mobile is near-fullscreen. Every close vector calls the same `requestClose`; dirty sections require explicit discard confirmation.
- **P1/P3b split:** P1 delivers modal chrome/provider plus a section outlet contract. P3b registers Compute/Modules and rehomes 工作区; it does not create another dialog or duplicate shell styles.
- **Deep links:** `/settings/:section` remains accepted as a compatibility entry. It opens that section in the shared modal over the saved non-settings location, or `/works` on direct load; close restores the safe background location.
- **Profile selection:** enumerate all creator-list pages and read the configured active id through the existing active-creator endpoint (or ensure-bootstrap result during setup). Choose trimmed display name `Default` case-insensitively; tie-break by ascending `creator_id`. Otherwise choose the bootstrap/configured active creator if present; only then stable-first `creator_id` for recovery. Ignore stale localStorage ids absent from the list. Persist the chosen id, and on desktop invoke the existing active-creator switch before creator-scoped queries are enabled. Promoting the already-shipped active-creator GET onto `NexusClient` does not change schemas.
