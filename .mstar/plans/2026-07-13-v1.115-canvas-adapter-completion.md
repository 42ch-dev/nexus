## Problem

V1.114 shipped a shared `CanvasSurfaceAdapter` abstraction so that a 5th
surface is a recipe, not a rewrite. The recipe is proven on **2 of 3 product
canvas orchestrators** (Strategy + World KB entities). It is not yet honest or
complete:

1. **Strategy `projectGraph` is a passthrough** (R-V1114P0QC1-W001) — the real
   projection lives upstream in `useStrategyCanvas`, so the adapter's
   `projectGraph` is decorative. A new surface copying the Strategy adapter
   would copy a no-op.
2. **World KB `renderInspector`/`renderAltView` ignore the node parameter**
   (R-V1114P0QC1-W002) — they route via `ctxRef` instead of the passed `node`,
   so the adapter contract says one thing and the implementation does another.
3. **`useAutoLayout` first-run unconditionally overrides supplied positions**
   (R-V1114P0QC1-W003) — a surface that supplies persisted positions would have
   them clobbered on open.
4. **`useAutoLayout` non-null assertion** (R-V1114P0QC2-M001) — latent crash on
   missing dagre labels.

Plus **Outline+Timeline is not on the adapter at all**, so any deep-dive that
adds a 5th surface or canvas↔compute intersection still has two recipes.

**Surface inventory (locked):** product surfaces = 3 (Strategy, Outline+Timeline,
World KB). `CanvasSurfaceKind` includes reserved `world-kb-relationships` but
there is **no separate Relationships orchestrator** today — do not invent one
in this plan. Done = all three shipped orchestrators consume the adapter.

Product outcome: the adapter abstraction is **honest and complete** for every
shipped canvas orchestrator — and the contract it declares is the contract it
honors.

## Goals

1. Migrate Outline+Timeline to `OutlineCanvasAdapter` + `useCanvasSurface()`.
2. Fix Strategy adapter passthrough (W001): move real projection into
   `projectGraph`.
3. Fix World KB adapter node-parameter leak (W002): `renderInspector` /
   `renderAltView` consume contract inputs (not inspector data via ctxRef
   side-channel).
4. Fix `useAutoLayout` first-run override (W003): surfaces that supply
   positions keep them on first open.
5. Fix `useAutoLayout` non-null assertion (M001): defensive fallback instead of
   `label.x!` / `label.y!`.
6. Document layer-14 "contract convergence" in the canvas implementation pattern
   knowledge note (no new normative Master).

## Global Constraints

- **No domain-behavior change**: surface write ops, node semantics, inspectors,
  and conflict modals stay surface-owned. All existing canvas tests pass
  unchanged (except where tests must follow projection ownership moves).
- **Projection equivalence**: the migrated surface's projected graph (nodes +
  edges + `parentId` nesting) is identical before and after migration.
- **Manual override preserved**: auto-layout never overrides an author's manual
  drag until the next explicit "Re-layout" action (carried from V1.114).
- **No Relationships orchestrator**: do not create a second World KB canvas
  solely to satisfy a four-kind enum.
- **Selection coordination ownership (architect)**: `useCanvasSurface()` owns
  node selection (`selectedNode` / `selectedNodeId` via the RF `selected` flag).
  Surface-specific selection resolution (e.g., Outline chapter/scene/beat id
  from `selectedNodeId`) stays in the orchestrator as a thin resolver — do NOT
  duplicate selection state in a parallel hook. `useCanvasSurface()` already
  provides the position-merge sync effect (preserving dragged positions across
  projection rebuilds); migrated surfaces must NOT re-implement it.
- **Adapter interface is stable**: do NOT add `renderEdgeInspector(edge)` or
  extend `projectGraph` return shape this iteration. Edge-selection inspector
  routing (World KB relationships) stays on an orchestrator-owned path with a
  documented comment until a future interface extension.
- **Route-split preserved**: `@xyflow/react` + `dagre` stay in the canvas route
  chunk.
- **DESIGN.md tokens**: no new canvas tokens required.

## Interface contracts (architect)

### `OutlineCanvasAdapter` (T1)

- `TGraph` = `{ outline: WorkOutline; chapters: ChapterSummary[];
  sceneBeatFixture: SceneBeatFixturePayload }`.
- `projectGraph(graph)` calls `projectOutlineGraph(outline, chapters,
  sceneBeatFixture, translateFallback)` — the existing projection function
  moves inside the adapter; its signature is unchanged.
- The orchestrator builds a combined `CanvasSurfaceQueryResult<TGraph>` from
  three queries (outline, chapters, work): `data` is assembled only when all
  three are loaded; `isLoading`/`isError` aggregate via `||`; `refetch`
  refetches all three.
- **Selection resolver**: the orchestrator reads `selectedNodeId` from
  `useCanvasSurface()` and resolves chapter/scene/beat ids via the existing
  `selectedChapterIdFromNodes` / `selectedSceneIdFromNodes` /
  `selectedBeatIdFromNodes` helpers (adapted to take a single node id, or the
  one-node array). This replaces the current `useOutlineCanvasGraph`
  selection-sync effect.

### `StrategyCanvasAdapter` (T2 / W001)

- `StrategySurfaceGraph` changes from `{ revision, graph: StrategyGraph, parsed,
  activeSession }` to `{ revision: number; parsed: ParsedPreset; activeSession:
  ActiveSession | null }` — the pre-projected `graph` field is **dropped**.
- `projectGraph({ parsed })` calls `buildStrategyGraph(parsed)` internally
  (function moves from `strategy-graph.ts` call-site in the hook into the
  adapter). The projection runs once inside `useCanvasSurface`'s `useMemo` —
  no double-projection.
- `danglingTargets` (a projection byproduct) is surfaced via
  `ctxRef.current.danglingTargets` — the adapter writes it after projection;
  the orchestrator reads it for the ValidationPanel. This reuses the existing
  stable-ctxRef pattern (same as inspector data today).
- `useStrategyCanvas` becomes a thin query + state hook (no projection memo);
  it delegates projection to the adapter via `useCanvasSurface()`.

### `WorldKbCanvasAdapter` (T3 / W002)

- `renderInspector(node)` routes entity vs candidate from `node.data`
  (`WorldKbNodeData`) / `node.type` — NOT from `ctxRef.current.selection`.
- **ctxRef fields that legitimately STAY**: callbacks (`onEntityConflict`,
  `onPromoteConflict`, `onRelationshipConflict`, selection handlers),
  orchestrator context (`confirmedEntities` for PromotionInspector merge
  targets, `reseedSignal`), and the relationship-inspector path (edge
  selection — see Global Constraint on adapter interface stability).
- **ctxRef fields that are REDUNDANT after fix**: `selection` (for node-based
  routing) — the `node` parameter is the authority. `selectedNodeId` is
  already provided by `useCanvasSurface()`.

### T2 — Fix Strategy adapter passthrough (W001)
- Move `buildStrategyGraph(parsed)` call from `useStrategyCanvas` into the
  Strategy adapter's `projectGraph`. Per Interface Contracts, the adapter
  input changes: `StrategySurfaceGraph` drops the pre-projected `graph` field
  and carries `parsed: ParsedPreset` directly.
- `useStrategyCanvas` becomes a thin query + state hook that delegates
  projection to the adapter (no duplicate projection path, no projection
  memo).
- `danglingTargets` byproduct: the adapter writes it to
  `ctxRef.current.danglingTargets` after projection; the orchestrator reads it
  for the ValidationPanel (reuse existing ctxRef pattern).
- **Timing boundary (architect)**: projection timing is preserved because both
  old and new paths use `useMemo` over the same `parsed` dependency.
  `useCanvasSurface` memoizes `adapter.projectGraph(graph)` exactly as the old
  hook memoized `buildStrategyGraph(parsed)`. No double-projection: the
  function runs once per memoized input.
- Diff-test: before/after node positions + edges identical on the same
  preset graph.
- Update `strategy-graph.test.ts` — projection tests target the adapter, not
  the hook.
- **Done when:** AC-P0-2.

### T3 — Fix World KB adapter node-parameter leak (W002)
- `WorldKbCanvasAdapter.renderInspector(node)` routes entity vs candidate from
  `node.data` (`WorldKbNodeData`) / `node.type` — the contract `node` parameter
  is the authority, NOT `ctxRef.current.selection`.
- **ctxRef classification (architect)**: callbacks (`onEntityConflict`,
  `onPromoteConflict`, `onRelationshipConflict`, selection handlers) and
  orchestrator context (`confirmedEntities` for PromotionInspector merge
  targets, `reseedSignal`) STAY on ctxRef — they are handlers and cross-node
  context, not per-node data. Only the `selection`-driven inspector routing
  moves to the `node` parameter.
- **Known contract gap (documented, not fixed this iteration)**: relationship
  (edge) selection has no `renderEdgeInspector(edge)` method on
  `CanvasSurfaceAdapter`. The relationship inspector stays on an
  orchestrator-owned path. Do NOT expand the interface (YAGNI); add a comment
  marking it as a future `renderEdgeInspector?` extension point.
- All existing World KB inspector tests pass; add a test that the inspector
  renders the correct entity for the passed `node` (not whatever
  `ctxRef.current.selection` happens to hold).
- **Done when:** AC-P0-3.
