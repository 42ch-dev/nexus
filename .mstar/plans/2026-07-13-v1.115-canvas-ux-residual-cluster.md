## Problem

The post-V1.114 canvas residual cluster contains five items that are either
author-visible UX debt or latent resilience risks. They are individually small
but collectively make the canvas feel unfinished and carry one React Flow
upgrade risk. Closing them now keeps the residual slate trending down and
removes the RF-upgrade time bomb before a deep-dive iteration adds more canvas
surface area.

| Residual | Severity | Author-visible? | Why now |
|----------|----------|-----------------|---------|
| R-V1108P0QC1-M001 — Alt view read-only (no sort controls) | low | yes | Authors cannot sort chapter list / timeline events in the non-spatial alt view; sort is a navigation affordance |
| R-V1111P0QC2-W001 — Hotkey conflict-avoidance depends on `.react-flow` CSS class | low | no (latent) | RF upgrade could silently re-enable Cmd+K inside the canvas editor; detection is on an undocumented internal class |
| R-V1111P1-WORLDS-PICKER — World KB sidebar item disabled when no worldId active | low | yes | Authors with no world selected see a permanently-disabled nav item with no route to pick a world |
| R-V1108P1QC1-S002 — Studio node chrome mirror should import P0 extract | nit | no (Design Studio) | Design Studio re-mirrors chrome as static markup; V1.114 shipped the extract — Studio should consume it |
| R-V1109-P0-QC3-W002 — `beatParentSceneTitle` O(n) lookup on fixture scenes | nit | no (perf) | `Array.find()` on every render; cheap O(1) index now |

Product outcome: alt-views are navigable (sortable), World KB nav is reachable,
and hotkey detection no longer depends on an RF internal that could vanish on
upgrade.

## Goals

1. Add sort controls to Outline+Timeline alt-views (R-V1108P0QC1-M001).
2. Replace `.react-flow` CSS-class hotkey dependency with attribute selector
   and/or RF public API (R-V1111P0QC2-W001).
3. Make World KB sidebar nav reachable when no world is active (R-V1111P1-WORLDS-PICKER).
4. Design Studio consumes V1.114 node-chrome extract (R-V1108P1QC1-S002).
5. Index `beatParentSceneTitle` lookup (R-V1109-P0-QC3-W002).

## Global Constraints

- **No domain-behavior change**: sort is read-side only; World KB picker does
  not change the world data model.
- **Sort is client-side**: alt-view lists are small and un-paginated (V1.64 F-F1
  adaptation); server-side sort is a non-goal.
- **World picker scope**: minimal list reusing
  `GET /v1/local/narrative/worlds` **or** honest empty state — not full
  world-management, **not** auto-select first world.
- **Product-independent of P0**: may ship without Outline adapter migration;
  coordinate file conflicts at integration merge.
- **DESIGN.md tokens**: reuse existing table/list tokens; no new canvas tokens.

## Tasks (SDD)

### T1 — Alt-view sort controls (R-V1108P0QC1-M001)
- Sortable column header or sort dropdown on Outline alt-view chapter list and
  Timeline alt-view event list.
- Client-side sort: chapters by **number** and **volume**; events by **event
  time** (fields already present).
- Tests: sort toggles order; sort state ephemeral (not persisted); alt-view
  still reflects the underlying graph.
- **Done when:** AC-P1-1 + AC-P1-2.

### T2 — Hotkey `.react-flow` dependency removal (R-V1111P0QC2-W001)
- **Architect decision — detection mechanism:** drop `.react-flow` from the
  `shouldIgnoreTarget` selector in `use-hotkey.ts` (line 106). Instead, set
  `data-command-palette-ignore` on the `CanvasShell` root element (the canvas
  wrapper). The selector then matches via the existing
  `[data-command-palette-ignore]` clause — no new selector needed, just a
  self-owned attribute on the canvas root.
- **Why attribute-on-canvas-root, not RF public focus API:** the attribute is
  fully under our control (stable across RF upgrades); RF's public focus API
  is heavier, depends on RF internals for focus state, and has no stable
  "is a canvas pane focused" method. The attribute approach is simpler and
  more robust (Ladder rung 4 — native platform feature over library API).
- Verify Cmd/Ctrl+K still opens the palette outside the canvas editor and is
  suppressed inside it.
- Update `use-hotkey.test.ts`: the existing `.react-flow` class test becomes a
  `data-command-palette-ignore` test; add a test that detection survives RF
  class absence (no `.react-flow` in the DOM at all).
- **Done when:** AC-P1-3.

### T3 — World KB sidebar reachable (R-V1111P1-WORLDS-PICKER)
- **Architect decision — smallest IA change:** change
  `resolveCanvasNavTarget('world-kb', {})` in `canvas-nav.ts` to return
  `/worlds` (instead of `null`) when no `worldId` is active. Add a minimal
  `/worlds` route that reuses the existing `GET /v1/daemon/narrative/worlds`
  query (already consumed by `soul-section.tsx`) to render a world list, or an
  honest empty state when the list is empty.
- Picking a world navigates to `/worlds/<id>/kb` (the existing World KB
  route). No new endpoint, no new CRUD — the worlds query and `useWorlds`
  hook already exist.
- Update `canvas-nav.test.ts`: the `world-kb` no-context case expects `/worlds`
  (not `null`).
- **Do not** auto-select the first world.
- Test: nav item focusable + navigates; empty state honest when list empty.
- **Done when:** AC-P1-4.

### T4 — Design Studio node-chrome extract (R-V1108P1QC1-S002)
- **Architect correction:** V1.114 did **NOT** ship a shared presentational
  node-chrome extract. Today the chrome is inline in each RF node component
  (`strategy-nodes.tsx`, `outline-nodes.tsx`) using DESIGN.md tokens
  (`canvas-node-*`); Design Studio re-mirrors it as static markup. This task
  must FIRST create the extract, then consume it.
- **Presentational boundary (architect invariant):** create a
  `NodeChromeShell` (or equivalent) presentational component — props in, JSX
  out, **NO `@xyflow/react` import** (no `NodeProps` / `Handle` / `Position`).
  It lives in a location both `apps/web` and `apps/design-studio` can import
  (e.g., `@nexus/ui` or a shared canvas-presentational module).
- App RF node types adapt `NodeProps` → `NodeChromeShell` props (RF wrapper
  stays in `apps/web`). Design Studio fixtures consume `NodeChromeShell`
  directly with static props.
- Test: Design Studio canvas fixtures render `NodeChromeShell`; no
  `@xyflow/react` import in the extract module (enforce via a boundary test
  or import lint).
- **Done when:** AC-P1-5.
