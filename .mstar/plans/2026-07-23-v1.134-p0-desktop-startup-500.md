## Problem Statement

**User impact:** On desktop launch the author still sees a **`500 Internal Server Error`** in the startup network log. The app continues because the probe is non-blocking, so the defect is easy to ignore and has survived prior 404-class fixes (V1.132 P0, V1.133 brace sweep). Spurious 500s erode trust that the local daemon is healthy.

**User ask:** Locate the 500 ("需要定位500的报错是什么") and eliminate it — not paper over it.

## User value

Clean cold start: opening Nexus desktop does not report server errors for ordinary startup probes. Empty/uninitialized local state returns an expected domain outcome (e.g. empty 200), never Internal Server Error.

## Goal

Eliminate the non-blocking `500 Internal Server Error` that appears on desktop startup.

## Priority

**Must.** Entire plan is hardening. No Stretch tasks. If RCA reveals a large unrelated refactor, stop and escalate — do not expand scope.

## Architecture

A daemon route in `crates/nexus-daemon-runtime/` returns `INTERNAL_SERVER_ERROR` on a request `apps/web` issues during desktop mount. The 404 class was closed by V1.132 P0 + V1.133; a 500 on a startup route remains. **RCA first** — do not assume the route. Reproduce, capture the failing request + server-side stack, then fix at the handler. Anticipated `wire_contracts_changed: false` unless RCA reveals a missing/shape-mismatched DTO.

**Tech Stack:** Rust (axum, nexus-daemon-runtime), Tauri desktop shell, apps/web fetch paths. Local-only daemon at `127.0.0.1:8420`.

**Execution:** mstar-sdd
