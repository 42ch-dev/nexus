## Problem Statement

**User impact:** Open residual debt from V1.92–V1.132 still maps to real creator pain (daemon restart reliability, profile auto-select gaps, display-name XSS risk, worlds pagination cost) while many rows are stale or parked as “V1.12x+ polish.” That combination means: (1) users keep hitting known bugs that were never fully closed, and (2) the backlog cannot be trusted for prioritization — false debt crowds out true debt.

**Ledger problem:** ~64 open residuals accumulated across V1.92–V1.132. Many were marked "V1.127+ polish" / "V1.128+ polish" but never closed. Some describe issues that no longer exist (stale). A few represent actual bugs or incomplete features that were marked Done without full verification.

## Non-Goals

- Burning down all ~64 residuals (nits stay deferred unless already in a fix-now file touch)
- New features, visual redesign, or net-new product surfaces
- Human-verification smokes (Dock, Overlay) — keep open; do not mark Done without human evidence
- Engine auto-start, platform/cloud, Timeline/Fork/Computable, DF-70/71 (compass non-goals)
- P0 brace-param route sweep (owned by P0 plan; coordinate only if a residual is the same root cause)
- Broad refactors or “while we’re here” cleanups outside residual fix path

## Interfaces

No interface changes. All fixes are internal: Rust daemon code (port cleanup, timeout deadlines, Drop guards), TypeScript web code (XSS escaping, helper extraction, pagination caching).

**P0/P1 coordination:** P0 touches `crates/nexus-daemon-runtime/src/api/mod.rs` (route path strings only) and `agent_host.rs` (`cancel_operation` handler suffix strip). P1 fix-now items touch different code paths (daemon lifecycle, CLI config, web rendering). Merge order matters: both branches merge into `iteration/v1.133`; P0 has no dependency on P1 and vice versa. If a fix-now residual requires changing a handler whose route P0 modifies, the implementer should coordinate — but current fix-now candidates do not overlap with P0 route groups.
