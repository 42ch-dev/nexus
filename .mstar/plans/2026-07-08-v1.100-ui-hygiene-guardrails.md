# P1 — UI Hygiene Guardrails and `cn` SSOT

**Goal:** Close the V1.99 UI package hygiene residuals by making component wrapper drift and Design Studio boundary violations mechanically detectable, then consolidating duplicated class-merge configuration behind one approved SSOT.

**Architecture:** Guardrails run at repository boundaries: Web wrappers stay thin, Design Studio stays daemon/app-shell-free, and `@42ch/nexus-ui` owns the shared class-merge authority so the existing `@nexus/design-tokens` -> `@42ch/nexus-ui` dependency does not become a cycle.

**Tech Stack:** `@42ch/nexus-ui`, `apps/web`, `apps/design-studio`, `@nexus/design-tokens`, CI scripts, package tests.

## Product Framing

**User value:** Future UI promotion work should feel repeatable and trustworthy: contributors should know where class merging lives, which imports are forbidden, and how Design Studio stays a package-facing gallery instead of an app-shell clone.

**Problem statement:** V1.99 shipped the promotion workflow but left manual checks and duplicated helper configuration. Without guardrails, P2 form-field promotion could expand the same drift.

**Target state:** Repository checks enforce package and studio boundaries, class-merge configuration has one approved authority or a documented fallback residual with sync tests, and P2 can consume the wrapper/direct-import decision without reopening it.

**Non-goals:** No new component promotion, no broad ESLint rollout unless scoped, no visual redesign, and no schema changes.
