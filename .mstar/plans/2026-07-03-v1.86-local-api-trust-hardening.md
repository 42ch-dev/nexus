## Context

Three Cursor security reports (commit `49a14b2e`) were verified by the PM against source and found to compound into one attack chain on the Local API trust boundary (see compass §0). No wire/schema/contract change.

## Specify (requirements)

### P0 — must-fix (Batch 1)

**R-1: Permissive CORS + keyless-localhost remote reach (High).**
- Replace `CorsLayer::permissive()` (`api/mod.rs:515`) with a configured `CorsLayer` whose allowed origins are derived from: the daemon's own listening origin (`http://127.0.0.1:<NEXUS_DAEMON_PORT or 8420>`), the Tauri webview origins (`tauri://localhost`, `http://tauri.localhost`), the Vite dev origin (`http://localhost:5173`), and any `NEXUS_DAEMON_ALLOWED_ORIGINS` env override (comma-separated).
- Add an **Origin-reject defense-in-depth middleware**: reject any request carrying an `Origin` header whose value is not in the allowlist. Requests with **no** `Origin` header are allowed (non-browser clients).
- No CSRF token framework (non-goal). No keyless-mode deprecation (non-goal).

**R-2: fs/* trust-boundary bypass when workspace unconfigured (High).**
- In `admission_pipeline` (`host_tool_handlers.rs:82-94`), when `workspace_path()` is `None`/empty, fs/* tools must be **denied unconditionally** with a clear error ("fs/* tools require an active workspace with defined bounds") before `execute_read_file`/`execute_write_file` run.
- Grep all fs/* call sites (CLI `host-call`, worker IPC, schedule executor) to confirm none legitimately operates without a workspace context; document the finding.

**R-3: Path traversal via string-prefix comparison (Medium).**
- Replace `abs_requested_str.starts_with(&workspace_path_str)` (`host_tool_handlers.rs:738-739`) with component-wise `Path::starts_with` by delegating `validate_file_path` to the canonical `resolve_guarded_path` / `canonicalize + Path::starts_with` pattern already in `path_guard.rs` (lines 60-62 document the anti-pattern). Eliminate the duplicated logic. Cover both read (existing-file) and write (non-existing-file) branches.

## Clarify (resolved)

| Q | A |
|---|---|
| Which origins to allowlist? | Own listening origin + Tauri webview (`tauri://localhost`, `http://tauri.localhost`) + Vite dev (`http://localhost:5173`) + env override. Grounded in `vite.config.ts`, `tauri.conf.json`, `browser-client.ts` — **not** a guess. |
| Keep keyless-localhost? | Yes (default). Origin gate is the new defense; deprecation is a non-goal. |
| Deny fs/* or sandbox-dir when no workspace? | Deny. YAGNI; deny-by-default is the safe primitive. |
| String-prefix → what replacement? | `Path::starts_with` via `resolve_guarded_path`. |
| Single plan or split? | Single. All tasks edit overlapping files; parallel branches would only add merge overhead. |
| Contract bump? | None. `wire_contracts_changed: false`. |
| Plan structure / batches? | Single feature branch `feature/v1.86-local-api-trust-hardening`; Batch 1 (P0) → Batch 2 (P1), sequential. |
