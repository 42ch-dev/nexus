## Prepare Package (Product)

### Specify

- **Problem:** canvas is chromatically drifted (Tailwind-palette leftovers), flat (no elevation story), single-accent (purple spine only on Strategy); reading chrome is 40+ hardcoded values with the product's only serif untokenized — undermines the Literary Engine story more than any list page.
- **Scope:** Strategy/Outline(+Scene/Beat)/WorldKB canvases (ambient, node chrome v2, edges, inspectors, modals); reading surfaces (CSS migration to P0 tokens, display serif, annotations, chapter nav, progress); studio canvas galleries + canvas token gallery; light/dark parity + AA close-out.
- **Non-goals:** canvas interaction/model changes, new node types, React Flow upgrade, performance rewrites, manuscript editing, shell/Control Room rework (P2), i18n/copy rewrites, wire/desktop-native changes.
- **Draft DoD:** AC-P3-1…8 (+ compass AC-V1121-7).

### Clarify (locked — PM, autonomous)

- **Per-surface accent spines:** strategy=purple-700, outline=amber-700, worldkb=teal-700 — as tokens (P0), applied via `NodeChromeShell` accent extension. `node-chrome-shell.tsx` already exposes `accent?: boolean` (currently `border-l-canvas-strategy-accent`); P3 extends this single prop to a per-surface accent spine (chosen shape, e.g. `accent?: boolean | 'strategy' | 'outline' | 'worldkb'`, is a P3 design decision; **additive** — existing `accent={true}` keeps the strategy accent for backward compatibility).
- **Node chrome v2:** rest `elevation-1` → hover `elevation-2` → dragging `elevation-4`; selection = two-layer ring (canvas-focus token); widths consume `min-w-canvas-node-<role>` utilities registered in P0 (DESIGN.md `components.canvas.node-width.*`, 5 values per P0 spec T5); P2 adopts them in the page sweep.
- **Chromatic hygiene:** apply P0 mapping verbatim; hue families preserved (blue→blue etc.); relationship-edge typing colors remapped per table.
- **Reading chrome:** CSS block becomes `var()`-only per P0 T6 contract (tokens already authored); novel chapter title → `font-display`; other profiles keep identity via their `reading-chrome-*` tokens.
- **Parity + AA close-out:** screenshot pack = 3 canvases + reading × light/dark; AA spot-check table for remapped chromatics + ink text pairings; grep-clean hex leftovers; no open BLOCKING contrast/hygiene residuals at Done.

### Plan (technical)

- **T1 — Canvas ambient + shell:** canvas-shell surface/grid/minimap/controls → ambient tokens; per-theme grid tuning; ink dark canvas.
- **T2 — Node chrome v2 + edges:** NodeChromeShell elevation/selection/accent (extend existing `accent?: boolean` prop additively for per-surface spines); per-surface node adoption (state/group/join/terminal/inner; volume/chapter/scene/beat/timeline; entity/relationship); edge/port/hover tokens; chromatic remap applied; consume `min-w-canvas-node-<role>` utilities (registered P0).
- **T3 — Reading surfaces:** index.css reading-chrome → token-only (P0 contract); novel serif live; annotations/inspector/toolbar/progress → v0.4 tokens; AA checks.
- **T4 — Studio canvas galleries + parity close-out:** fixtures updated; canvas token gallery (light/dark); screenshot pack + AA table; all suites green; AC-V1121-7 evidence on plan.
