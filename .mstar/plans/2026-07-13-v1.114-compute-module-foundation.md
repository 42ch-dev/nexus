## Problem

Compute Modules are the **deterministic engine** (WASM world rules on
computable KeyBlocks), but authors cannot answer: what modules are installed,
what they require, or what state they left on characters. Invisible compute
cannot be a product pillar. V2.0+ state editors and canvas intersection are
blocked until registry + state **read** exist. Product outcome: discover +
inspect — not yet "press Play."

## Goals

1. `GET /v1/daemon/compute/modules` + `GET /v1/daemon/compute/modules/{id}` —
   registry endpoints reusing the existing manifest shape.
2. Computable KeyBlock state read — dedicated endpoint
   `GET /v1/daemon/worlds/{world_id}/kb/key-blocks/{id}/state` (Option B,
   locked by @architect — see spec §Architect decisions).
3. Control Room Modules panel — new page listing installed modules + manifest
   detail (author-facing labels: "Modules" / "Compute modules").
4. Compute onboarding documentation consolidation.
5. `@42ch/nexus-contracts` minor bump for additive schemas.

## Acceptance criteria (product-facing)

- [ ] Modules panel shows at least `basic-combat` with name, version, description
- [ ] Module detail shows required KeyBlock types (and battle-report kind when
  declared)
- [ ] Computable KeyBlock `state` is readable via the dedicated
  `GET .../key-blocks/{id}/state` endpoint (Option B, locked by @architect);
  non-computable blocks return `is_computable: false` (do not fake state)
- [ ] Registry shapes match existing `manifest.json` (no parallel module DTO)
- [ ] Module-author docs point at one onboarding path + new `/compute/*` routes
- [ ] No Run / Install / state-edit actions in V1.114 UI (discover + inspect only)

## Global Constraints

- **Read-only**: V1.114 ships no compute invocation from the UI; no state
  mutation from the Modules panel or state-read path.
- **Additive schemas**: new endpoints/fields are additive; existing compute
  tests unchanged.
- **Manifest shape reuse**: registry endpoints return the existing
  `manifest.json` shape (compute-module-abi.md §7), promoted to schemas under
  `schemas/daemon-api/compute/` — not a new invented DTO, not under the
  retired `local-api/` path.
- **Codegen**: new schemas produce Rust + TypeScript types via the existing
  pipeline. Run `pnpm run codegen` + commit generated output in the same
  commit as schema changes.
- **Nav IA**: dedicated "Compute" section with "Modules" entry (locked by
  @architect); label must be author-understandable.
- **Manifest reconciliation**: after codegen, reconcile or replace the
  hand-written `ModuleManifest` Rust struct in `nexus-wasm-host` with the
  generated `ComputeModuleDetail` type (no parallel DTO).

### T2 — Computable KeyBlock state read (backend)
- Add `GET /v1/daemon/worlds/{world_id}/kb/key-blocks/{key_block_id}/state`
  (**Option B — dedicated endpoint**, locked by @architect). Reads `body.state`
  directly from the KeyBlock (stored in SQLite `kb_key_blocks.body`).
- Response: `{ state, is_computable, version }` — `version` mirrors per-row OCC
  revision so callers detect staleness without a separate fetch.
- New schema:
  `schemas/daemon-api/canvas/world-kb/key-block-state-response.schema.json`.
- Read-only; no mutation.
- Backend tests: computable block returns state + `is_computable: true`;
  non-computable returns `state: null` + `is_computable: false`; 404 for
  unknown key_block_id.

### T3 — NexusClient + contracts wiring
- Run `pnpm run codegen` to generate Rust + TypeScript types for the new
  schemas (T1 + T2).
- Register new schemas in `schema_drift_detection.rs`
  (`build_schema_map()` — add `entry!` macros for the 3 new schemas); run
  `./tooling/check-wire-drift.sh` to verify bidirectional match.
- Promote new endpoints onto `NexusClient` interface.
- Reconcile hand-written `ModuleManifest` in `nexus-wasm-host` with the
  generated `ComputeModuleDetail` type (or replace it) to eliminate drift.
- `@42ch/nexus-contracts` minor bump.
