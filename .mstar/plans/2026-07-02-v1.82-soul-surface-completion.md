## 1. Problem statement

V1.81's SOUL surface has two gaps V1.82 closes: the world-selector shows raw
`world_id` (no titles), and the narrative is Creator-level only. P1 wires the
selector to `/v1/local/narrative/worlds` for titles + drives the narrative card
per selected world via the (P-1/P0) optional `world_id` on `/soul/reflect`.

## 2. Scope

### 2.1 Worlds-endpoint wiring (SP-2)
- New `useNarrativeWorlds()` query (or reuse if present) consuming
  `GET /v1/local/narrative/worlds` (P-1 verifies it returns `title` + is
  owner-scoped). Add a `NexusClient` method (`listNarrativeWorlds`) if missing;
  consume via the NexusClient interface boundary.
- `world-selector.tsx`: render world **titles** (not raw `world_id`); include
  Work-backed worlds (so a world with Works but no fragments appears, enabling
  the subset-empty state). Honest empty state for zero-fragment worlds.
- Replace the V1.81 `simplify:` placeholder (raw-id label + "tracked" comment).

### 2.2 per-World narrative selector scope linkage (SP-1)
- `useSoulNarrative` carries the selected `world_id` (absent = Creator-level
  narrative; present = per-World narrative). The narrative card re-renders when
  the selector changes: "All worlds" → Creator-level narrative; a world → that
  world's per-World narrative. Selector change is the single source of truth
  for narrative scope; no stale narrative from a prior selection remains
  visible.
- Per-world narrative states are independent of the Creator-level narrative:
  - A world may be `insufficient_data` (or `ungenerated`) even when the
    Creator-level narrative is `current` or `stale`. The card must surface the
    per-world state, not fall back to or restate the Creator-level
    narrative.
  - When a world has sufficient fragments for a distinct per-World narrative
    (meets the three-point quality bar scoped to that world's fragments, or
    surfaces world-specific signal), it shows the per-World narrative.
- `soul-narrative-card.tsx` + `soul-section.tsx`: wire the selector→narrative
  scope linkage; per-world empty/insufficient states use DESIGN.md tokens (P-1).
  The "distinct vs thin" product gate (per compass §6) is enforced at the
  surface: thin restatements of the Creator-level narrative without world
  signal must not be shown as a per-World narrative.

### 2.3 Auto-refresh consistency
- The V1.81 auto-refresh (poll + post-review invalidation) holds per selected
  scope; close the V1.81 `R-V181P0-GRPT-003` double-poll-timer nit (a world
  active should not spawn a duplicate observer) as part of this track OR P-last.

### 2.4 Tests
- world-selector renders titles; Work-backed subset-empty path reachable.
- narrative card re-renders per selector change; per-world insufficient state.
- Consume P-1 frozen contract types (no hand-written DTOs).

## 2.5 Contract types Consumed + P0‖P1 File-Disjoint Boundary (LOCKED)

P1 builds against **P-1 frozen contract types only** (no hand-written DTOs —
schemas are the single truth source). The exact contract surface P1 consumes:

| Contract (P-1 frozen) | P1 consumer | Notes |
|---|---|---|
| `SoulNarrativeRequest` (+ optional `world_id`) | `useSoulNarrative` query/mutation | carries the selected `world_id` (absent = Creator-level). |
| `SoulNarrativeResponse` (V1.81 shape, unchanged) | `soul-narrative-card.tsx` | state enum + counts scoped per world. |
| `WorldState` (`{ world_id, title, slug, status, … }`) | `useNarrativeWorlds` | from the **existing** `GET /v1/local/narrative/worlds`; `title` is present. Workspace-scoped (single-creator local model); P1 does NOT client-filter by owner — ownership is enforced server-side at `/soul/reflect`. |

**Files P1 MAY touch (exclusive — provably disjoint from P0):**

- `apps/web/src/api/queries.ts` (`useSoulNarrative` carries `world_id`; new
  `useNarrativeWorlds` if absent)
- `apps/web/src/components/soul/world-selector.tsx` (titles + Work-backed subset-empty)
- `apps/web/src/components/soul/soul-narrative-card.tsx` (per-world states)
- `apps/web/src/components/memory/soul-section.tsx` (selector→narrative linkage)
- `apps/web/src/lib/nexus/*` (a `listNarrativeWorlds` client method ONLY if the
  NexusClient interface lacks one; additive)
- `apps/web/src/components/soul/*.test.tsx` (new/updated tests)
- `apps/web/DESIGN.md` SOUL section (one-line reuse note — no new tokens; P-1 §2.3)

**Files P1 MUST NOT touch** (P0 / shared / generated):
- `crates/**`, `schemas/**`, `packages/nexus-contracts/**`, `.sqlx/**`,
  `crates/nexus-contracts/src/generated/**` — all P0/P-1 territory.
- `apps/web/src/lib/nexus/types.ts` **generated re-exports** — these resolve
  from P-1 codegen output; P1 does not hand-edit them.

**Shared-client collision risk + integration-sequencing rule**:
`apps/web/src/lib/nexus/types.ts` (and the generated import surface) is the
single collision risk between P0's regenerated types and P1's consumer code.
P1 develops against **P-1 frozen types** in its worktree (P-1 lands first and
freezes the contract before P0‖P1 dispatch). P1 may **mock** the P0 endpoint
shape until P0 merges (the response shape is unchanged from V1.81, so the mock
is trivial). Generated-import churn is resolved **once** on `iteration/v1.82`
after both topic branches merge — NOT in either worktree. P0 commits to
`feature/v1.82-soul-backend`; P1 commits to `feature/v1.82-soul-frontend`; the
two branches are file-disjoint by the table above.
