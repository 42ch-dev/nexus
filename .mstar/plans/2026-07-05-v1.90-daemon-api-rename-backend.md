# P0 — Track A: Daemon API rename backend + codegen + remote bind

## specify

**Problem statement**
The backend still calls the surface “Local API” in code, routes, schemas, and generated contracts. P-1 has locked the new name (Daemon API), path prefix (`/v1/daemon/`), and remote-bind gate. P0 executes the rename on the backend and regenerates cross-language contracts.

**User / author value**
- The daemon serves a consistently named, remote-capable API surface.
- Authors who opt in can bind the daemon to a non-loopback address with a clear security gate.

**Scope**
- Rename `schemas/local-api/` → `schemas/daemon-api/`.
- Update JSON Schema `$id`, `$ref`, and folder README paths.
- Update codegen pipeline mapping (if any hard-coded paths).
- Regenerate Rust types in `crates/nexus-contracts/src/generated/daemon_api/` (was `local_api/`).
- Regenerate TypeScript types in `packages/nexus-contracts/src/generated/daemon-api/` (was `local-api/`).
- Bump `@42ch/nexus-contracts` to `0.19.0`.
- Update daemon router path prefix from `/v1/local/` to `/v1/daemon/`.
- Update handler module doc comments and error messages.
- Update auth middleware / boot / CLI client (`apps/nexus42/src/api/daemon_client.rs`) references.
- Add remote-bind gate: reject non-loopback bind unless `NEXUS42_DAEMON_API_KEY` is set and `NEXUS_DAEMON_REMOTE_BIND=1`.
- Update Rust tests and `.sqlx/` metadata if needed.

**Non-goals**
- No endpoint behavior changes beyond path/namespace rename.
- No TLS.
- No new auth model.
- No cloud/platform integration.

**DoD draft**
- `cargo test --all` passes.
- `cargo clippy --all -- -D warnings` passes.
- `cargo +nightly-2026-06-26 fmt --all --check` passes.
- `pnpm run codegen` reproduces committed generated output.
- `validate-schemas` clean.
- Remote-bind gate has regression tests.

Only `generated::local_api::` (the codegen output for the Daemon API surface) is renamed. The `local/` module name refers to "local-only internal types", not the "Local API" surface. |

## plan

**Target state**
- A contributor grepping `local_api` or `local-api` in `schemas/`, `crates/`, `apps/nexus42/` finds zero matches (except historical comments/docstrings that deliberately cite the old name).
- The daemon router mounts all routes under `/v1/daemon/`.
- Generated contracts are version `0.19.0` and export `daemon-api` modules.
- Non-loopback bind is rejected unless both security conditions are met.

**Module boundaries / interface contracts**
- P0 owns `schemas/`, `crates/nexus-contracts/`, `crates/nexus-daemon-runtime/`, `apps/nexus42/`.
- P0 does **not** edit `apps/web/` except where it touches generated package exports (none — web consumes package, not source paths).
- P0 produces the migration evidence P1 needs: exact old → new import paths.

**Risk and rollback**
- Risk: generated code rename breaks web imports. Mitigation: P0 communicates the new module path to P1; P1 updates imports before integration.
- Risk: remote-bind gate rejects legitimate loopback. Mitigation: explicit loopback tests; gate only inspects bind host, not request origin.
- Rollback: revert P0 branch; regenerate old contracts from `main`.

**Verification plan**
- `cargo test --all`
- `cargo clippy --all -- -D warnings`
- `cargo fmt --all --check` with nightly pin
- `pnpm run codegen` and verify no diff
- `node tooling/validation/schema-validator.js`
- New test: `remote_bind_rejected_without_key`, `remote_bind_rejected_without_flag`, `remote_bind_allowed_with_both`, `loopback_bind_allowed_without_flag`.
