#### 2.4.1 `list_worlds` response shape — LOCKED

**Verified**: `GET /v1/local/narrative/worlds` → `ListWorldsResponse { worlds: Vec<WorldState> }`
(`crates/nexus-daemon-runtime/src/api/handlers/narrative.rs`). `WorldState`
(`crates/nexus-narrative/src/narrative_context.rs`) carries `world_id`, `title`,
`slug`, `status`, `is_fork`, `created_at`, … — **`title` IS present**, sufficient
for the selector to render world titles. **No new endpoint, no response-field
addition, no client adapter required.**

**Precision correction (architect)**: the endpoint is **workspace-scoped, not
owner-scoped** — `gateway.list_worlds()` returns all worlds in the workspace
(`worlds.values()`), and `WorldState` carries **no `owner_creator_id` field**, so
the frontend cannot client-filter by owner. This is acceptable for SP-2 in the
local-first single-creator model (all workspace worlds belong to the active
creator). **Ownership enforcement for SP-1 does NOT rely on this list** — it
lives server-side at `/soul/reflect` via the dedicated
`nexus_local_db::narrative_write::is_world_owned` helper (see 2.4.2 and P0 §2.B).

> Web-ui spec §27.1 ("already returns `title` + is owner-scoped") is imprecise
> on the second clause; `@architect` corrects it to "workspace-scoped (single-
> creator local model); ownership enforced server-side at /soul/reflect" — see
> the surgical edit to `web-ui.md` in this plan's artifacts.

#### 2.4.2 Composite-key migration DDL — LOCKED

**Verified**: the current `memory_soul_narratives` schema (after migrations
`20260701_000001` + `20260702_000001` + `20260703_000001`) is:

```
creator_id TEXT NOT NULL PRIMARY KEY,
narrative TEXT,                          -- nullable (G3)
generated_at TEXT,                       -- nullable (G3)
fragment_count_at_generation INTEGER NOT NULL DEFAULT 0,
max_fragment_created_at_at_generation TEXT,
distinct_keyword_count_cache INTEGER NOT NULL DEFAULT 0,
stats_fingerprint TEXT,
created_at TEXT NOT NULL,
updated_at TEXT NOT NULL
```

**V1.82 target**: PK `creator_id` → composite `(creator_id, world_id)`; add
`world_id TEXT` (NULL = Creator-level). The full migration DDL + by-name copy is
recorded in the **P0 plan §2.A** (authoritative location for the runnable DDL).
The DDL is reproduced here for review:

```sql
-- 20260704_000001_memory_soul_narratives_composite_world_key.sql (naming per P0)
CREATE TABLE memory_soul_narratives_new (
    creator_id TEXT NOT NULL,
    world_id   TEXT,                    -- NULL = Creator-level (whole) narrative
    narrative  TEXT,
    generated_at TEXT,
    fragment_count_at_generation INTEGER NOT NULL DEFAULT 0,
    max_fragment_created_at_at_generation TEXT,
    distinct_keyword_count_cache INTEGER NOT NULL DEFAULT 0,
    stats_fingerprint TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    PRIMARY KEY (creator_id, world_id)
);

-- SQLite quirk mitigation: PRIMARY KEY does NOT enforce uniqueness on NULL
-- world_id rows (SQLite treats NULL as distinct in PK/UNIQUE). A partial UNIQUE
-- index guarantees exactly one Creator-level (NULL world_id) row per creator.
CREATE UNIQUE INDEX idx_memory_soul_narratives_creator_only
    ON memory_soul_narratives_new (creator_id) WHERE world_id IS NULL;

-- By-name column-list copy (V1.81 greploop lesson: never positional SELECT *).
-- Existing rows are all Creator-level → world_id defaults to NULL.
INSERT INTO memory_soul_narratives_new (
    creator_id, world_id, narrative, generated_at,
    fragment_count_at_generation, max_fragment_created_at_at_generation,
    distinct_keyword_count_cache, stats_fingerprint, created_at, updated_at
)
SELECT
    creator_id, NULL, narrative, generated_at,
    fragment_count_at_generation, max_fragment_created_at_at_generation,
    distinct_keyword_count_cache, stats_fingerprint, created_at, updated_at
FROM memory_soul_narratives;

DROP TABLE memory_soul_narratives;
ALTER TABLE memory_soul_narratives_new RENAME TO memory_soul_narratives;
```

**NULL-world_id semantics on `memory_soul_narratives`**: existing V1.81 rows become the Creator-level
`(creator_id, NULL)` row — the Creator-level narrative, unchanged in behavior.
The composite PK correctly uniqueness-enforces world-bearing rows (non-NULL
world_id); the partial UNIQUE index closes the SQLite NULL-PK gap for the
Creator-level row. **INSERT OR REPLACE** in the DAO must bind world_id
consistently (NULL for Creator-level) so the partial-index conflict target
fires correctly.

**NULL-disambiguation**: `world_id IS NULL` means different things on different
tables — `memory_soul_narratives.world_id IS NULL` = Creator-level narrative
scope (the whole), while `memory_fragments.world_id IS NULL` = Creator-core-only
fragment provenance (no originating world). See
`creator-memory-soul-lifecycle.md` §7.2.4 for the complete disambiguation.

#### 2.4.3 per-World stats — LOCKED

**Verified**: `memory_fragments.world_id` (nullable, added `20260701_000001`)
+ index `idx_memory_fragments_creator_world_created ON memory_fragments
(creator_id, world_id, created_at DESC)` both exist. per-World stats derive
cleanly:

| Stat | Creator-level narrative (whole-scope) query | per-World narrative (subset) query |
|---|---|---|
| `fragment_count` | `COUNT(*) … WHERE creator_id = ?` | `… WHERE creator_id = ? AND world_id = ?` |
| `max_created_at` | `MAX(created_at) … WHERE creator_id = ?` | `… WHERE creator_id = ? AND world_id = ?` |
| distinct keywords | early-exit stream, `WHERE creator_id = ?` | early-exit stream, `WHERE creator_id = ? AND world_id = ?` |
| fingerprint | `"{count}:{max_created_at}"` over the whole | same formula over the subset |

**Creator SOUL = the whole** (all fragments, world-agnostic) — `WHERE creator_id = ?`
with **no** world filter, matching `creator-memory-soul-lifecycle.md` §7.2.1
("the Creator SOUL is the whole, not the NULL subset"). The per-World subset is
`WHERE creator_id = ? AND world_id = ?`. The V1.81 fingerprint cache +
early-exit-at-threshold distinct-count pattern applies **per (creator, world)**:
the cache row is the `(creator_id, world_id)` row on `memory_soul_narratives`,
keyed by the per-scope fingerprint. **No new index required** — the existing
`idx_memory_fragments_creator_world_created` serves all per-World aggregates.
