## Problem Statement

**User impact:** Agent selection (Setup wizard **and** Settings → Agent) keeps regressing visually. Status dots the author relies on are gone ("圆点都没了"; "右上角的状态圆点别删"). Light shell overuses cyan washes. Every dogfood re-opens the same VI fight.

**Cause class:** Presentational strip during V1.108–V1.119 polish. `agent-picker.tsx` still documents *"no competing tint wash or right-side status dot"* at line 15 — that comment is a regression artifact, not product intent.

## User value

Choosing a local ACP agent feels finished and scannable: status is visible at a glance; Light theme stays calm (cyan as accent only); Dark may use cyan more liberally. The look stops bouncing every iteration.

## Goal

Restore the AgentPicker status dots the author wants back (agent-selection dot + top-right status dot), impose cyan discipline (Light shell = accent-only; Dark shell = liberal), and retune the VI so the picker stops regressing each dogfood — on **both** Setup and Settings hosts.

## Priority

**Must.** No Stretch (no AgentPicker package promotion, no execution-mode matrix, no new agent types, no density experiments beyond restoring the prior intent).

## Architecture

`apps/web/src/components/setup/agent-picker.tsx` is presentational. Hosts: `setup-step-agent.tsx`, `settings-agent-section.tsx` (and any dialog remount). **RCA first (Task 1):** inspect V1.108–V1.119 diffs to recover exactly what the dots looked like (position, token, shape) and the author's VI references, so the restore is faithful — not a new guess. Then restore + audit cyan against DESIGN.md. **Studio-first fixture is the visual gate** (author eyeballs; agents cannot view the app).

**Tech Stack:** React + Tailwind, DESIGN.md tokens (`@nexus/design-tokens`), apps/design-studio, i18n.

**Execution:** mstar-sdd
