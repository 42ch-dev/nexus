## Context

V1.83 introduced Git LFS for brand PNG provenance and the `@42ch/nexus-ui` package, but the closeout recorded three low-severity CI/tooling residuals deferred to V1.84+. This plan closes all three. No author-facing change; pure CI/config hygiene.

## Specify

- **Problem**:
  - **W001** — CI checkout steps lack `lfs: true`, so a clean clone does not fetch the LFS-tracked brand PNGs, breaking provenance in CI artifacts.
  - **W002** — No dedicated `@42ch/nexus-ui` CI job; the package is only built transitively via `apps/web` pre-hooks, so a package-only regression could land unverified.
  - **W003** — Node 24+ emits an `ExperimentalWarning` for `localStorage` usage in Vitest test logs, adding noise that can mask real failures.
- **User value**: Foundation hygiene only — no direct author-facing change. CI now verifies brand-asset provenance and the `@42ch/nexus-ui` package independently (enabling future reliable author-visible work); test logs are free of noise that could mask real failures. This is SP-2 (infra) per compass; P0 is the author-facing headline.
- **Scope**:
  - **W001** — `.github/workflows/**`: add `lfs: true` to `actions/checkout` steps. Verified job list that builds/verifies brand assets or package dist: `web-build` (ci.yml L160), the **new `nexus-ui` job** (this plan), and both checkouts in `desktop-build.yml` (L47, L91). Verified `.gitattributes` scopes LFS to `packages/nexus-ui/assets/logos/*.png` only (small, bounded set). Jobs that do **not** need `lfs: true`: `validate-schemas`, `verify-codegen`, `rust-checks`, `typescript-checks`, `rust-tests`, `verify-sqlx-offline`, `schema-consistency-check`, `verify-no-acp-in-daemon` (lint/typecheck/test only, no asset build).
  - **W002** — `.github/workflows/ci.yml`: add a dedicated `nexus-ui` job matching ci.yml house style — `runs-on: ubuntu-latest`, pinned `actions/checkout@34e114876b0b11c390a56381ad14f8d5  # v4` (with `lfs: true`), `./.github/actions/setup-monorepo`, then `pnpm --filter @42ch/nexus-ui run build` + `pnpm --filter @42ch/nexus-ui run typecheck`. Verified `@42ch/nexus-ui` has **zero runtime deps** (devDeps `tsup`+`typescript` only) and **no `@42ch/nexus-contracts` dependency**, so the job is self-contained: no `needs: verify-codegen` and no `generated-types` artifact download (matches the `verify-no-acp-in-daemon` / `schema-consistency-check` independence pattern).
  - **W003** — `apps/web/vitest.config.ts` (verified to exist, with `setupFiles: ['./src/test/setup.ts']`): narrow-scoped suppression of the `ExperimentalWarning` for `localStorage`, documented with a comment citing W003. Prefer editing `apps/web/vitest.config.ts` (at `apps/web/` root, **outside** P0's `src/` tree) so P0/P1 file sets stay disjoint; if the filter must live in `apps/web/src/test/setup.ts` instead, that path is a P1-owned carve-out per compass §2.1 (P0 owns all other `apps/web/src/**`).
- **Non-goals**:
  - Any change to package `exports` or published surface (the CI job builds the *existing* package).
  - Node version pinning changes (the warning is suppressed, not the runtime swapped).
  - Any `apps/web` source/component/CSS logic change (P0's domain).
  - Per-job `paths:` filters on the new `nexus-ui` job — ci.yml uses workflow-level `paths-ignore` (docs/README/AGENTS/CLAUDE) for all jobs; a per-job path filter would deviate from house style. (Run on every qualifying push, like `web-build`/`typescript-checks`.)
- **DoD (draft)**: W001/W002/W003 resolved; CI green on a clean clone; test logs free of the localStorage warning.

## Clarify

- **Which jobs need `lfs: true`?** Verified: `web-build` (ci.yml L160) + the new `nexus-ui` job (ci.yml) + both `desktop-build.yml` checkouts (L47, L91). `.gitattributes` scopes LFS to `packages/nexus-ui/assets/logos/*.png` only, so CI cost is bounded. Lint/typecheck/test-only jobs are excluded (see Scope).
- **`nexus-ui` job triggering?** ci.yml uses workflow-level `paths-ignore` (no per-job `paths:` filters). Follow house style: the `nexus-ui` job runs on every qualifying push/PR like `web-build`. Do not add a per-job path filter unless explicitly justifying the deviation from ci.yml convention (desktop-build.yml uses per-job `paths:`, but it is a separate workflow).
- **`nexus-ui` job self-containment?** Verified: `packages/nexus-ui/package.json` has zero runtime deps (devDeps `tsup`+`typescript`) and does not depend on `@42ch/nexus-contracts`. The job needs no codegen artifact — model it on `verify-no-acp-in-daemon`/`schema-consistency-check` (no `needs:`), not on `web-build`/`typescript-checks` (which download `generated-types`). `setup-monorepo` composite action handles pnpm install; do not add a separate `pnpm install --frozen-lockfile` step.
- **Warning suppression mechanism?** Prefer a Vitest `onConsoleLog`/filter or a test-setup `process.removeAllListeners('warning')`-style narrow filter that targets the `ExperimentalWarning` + `localStorage` message only — documented with a comment citing W003. Do not blanket-suppress all warnings. Edit `apps/web/vitest.config.ts` (P1-owned, outside `src/`) per the §Scope carve-out.
- **Pre-existing build gap revealed by the new job?** Fix in-plan; do not suppress or skip.
- No open high-impact ambiguity.
