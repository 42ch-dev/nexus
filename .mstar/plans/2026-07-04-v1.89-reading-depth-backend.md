## Goal

Implement the daemon-side persistence and Local API for V1.89 reading depth so authors get two immediate, durable wins: "my reading position is remembered when I come back" and "I can mark and later find/edit important passages."

Deliverables: `reading_progress` upsert/query and `reading_annotations` CRUD. All endpoints are strictly read-side with respect to chapter body — no route writes to `body_path`, outline files, or chapter content. The body-ownership invariant (canvas is the sole authoring surface) is non-negotiable.

## Scope

### A. Database layer (`crates/nexus-local-db`)

| Capability | Detail |
|---|---|
| Migration | `crates/nexus-local-db/migrations/20260704_000002_reading_progress_and_annotations.sql` (authored in P-1). Verify it applies cleanly on a fresh DB and on existing V1.88 DBs. |
| DAO: progress | `upsert_reading_progress(creator_id, work_id, chapter, volume, scroll_progress) -> Result<(), LocalDbError>`; `get_reading_progress(creator_id, work_id, chapter) -> Result<ReadingProgressRow, LocalDbError>`. |
| DAO: annotations | `list_annotations(creator_id, work_id, chapter) -> Vec<ReadingAnnotationRow>`; `create_annotation(...)` returning `annotation_id`; `update_annotation(annotation_id, note, color)`; `delete_annotation(annotation_id, creator_id)`. |
| Auth gate | All DAO calls are creator-scoped; handlers enforce `active_creator_id` matches. Work ownership is implicit via `works.creator_id` FK path. |

### B. Local API handlers (`crates/nexus-daemon-runtime/src/api/handlers/reading.rs`)

| Method | Route | Behavior |
|---|---|---|
| GET | `/v1/local/reading/progress` | Query params: `work_id`, `chapter` (both required); `volume` (optional filter for edge cases — the primary key is `(creator_id, work_id, chapter)`). Returns `ReadingProgress` (defaults to `scroll_progress=0` when no row exists). |
| PUT | `/v1/local/reading/progress` | Body `ReadingProgress`. Upserts row (`INSERT … ON CONFLICT DO UPDATE`); `updated_at` set server-side. Idempotent — multiple identical PUTs produce the same final row. |
| GET | `/v1/local/reading/annotations` | Query params `work_id`, `chapter`. Returns `ReadingAnnotationList` (sorted by `start_offset`). |
| POST | `/v1/local/reading/annotations` | Body `ReadingAnnotationCreate`. Validates `start_offset < end_offset` and that offsets fall within body length if the body is cheaply available; otherwise trusts the client. Returns the created annotation. |
| PATCH | `/v1/local/reading/annotations/{annotation_id}` | Body `ReadingAnnotationPatch` (`note`, `color`). Handler must look up annotation by `annotation_id`, verify `annotation.creator_id == active_creator_id` (reject with 404 if not found, 403 if wrong creator), then update only the fields present in the patch body. |
| DELETE | `/v1/local/reading/annotations/{annotation_id}` | Handler must look up annotation by `annotation_id`, verify `annotation.creator_id == active_creator_id` (reject with 404/403), then hard-delete. Hard delete (not soft delete) — annotations are author metadata, not audit history. |
