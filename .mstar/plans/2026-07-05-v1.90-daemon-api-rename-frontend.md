# P1 — Track B: Daemon API rename frontend

## specify

**Problem statement**
The web UI consumes the daemon surface as “Local API” in comments, query keys, the `NexusClient` interface, and the `BrowserClient` base path. P0 will rename the generated contracts and the HTTP path prefix. P1 updates the frontend to match.

**User / author value**
- The web UI talks to the same daemon surface with consistent naming.
- No broken routes after the backend path change.

**Scope**
- Update `apps/web/src/lib/nexus/types.ts` comments and `NexusClient` doc strings.
- Update `apps/web/src/lib/nexus/browser-client.ts` base path from `/v1/local/` to `/v1/daemon/`.
- Update any hard-coded `/v1/local/` strings in screens/components/tests.
- Update query keys in `apps/web/src/lib/nexus/query-keys.ts` if they encode the old name.
- Update imports from `@42ch/nexus-contracts` if the generated module barrel export changed.
- Update tests and mocks that reference the old path or old module names.
- Update `apps/web/README.md` and any web-internal docs.

**Non-goals**
- No new UI features.
- No change to `NexusClient` method signatures or request/response shapes (only namespace/path renames).
- No Tauri IPC changes beyond path string constants.

**DoD draft**
- `pnpm --filter web run typecheck` passes.
- `pnpm --filter web run test` passes.
- `pnpm --filter @42ch/nexus-contracts run build` passes (consumes P0 output).
- No `local-api` / `Local API` references remain in `apps/web/`.

## clarify

| # | Ambiguity | Resolution |
|---|---|---|
| 1 | Base path source | `BrowserClient` builds URLs from a constant; update that constant to `/v1/daemon/`. |
| 2 | Vite dev proxy | `vite.config.ts` may proxy `/v1/local/*`; update to `/v1/daemon/*`. |
| 3 | Generated imports | If the package barrel re-export flattens names, imports may not change. If paths changed, update import specifiers. P0 will communicate exact diff. |
| 4 | TauriClient stub | `apps/web/src/lib/nexus/tauri-client.ts` (if exists) comments/base path updated; no IPC method changes. |
| 5 | Tests with hard-coded paths | Update MSW handlers / fetch mocks from `/v1/local/` to `/v1/daemon/`. |

## plan

**Target state**
- `apps/web/` contains no references to “Local API” or `/v1/local/`.
- The web app compiles and all tests pass against the renamed backend surface.
- `NexusClient` interface documentation reflects Daemon API terminology.

**Module boundaries / interface contracts**
- P1 owns `apps/web/` and `packages/nexus-contracts` consumer imports only.
- P1 does **not** edit daemon code or schemas.
- P1 consumes P0-generated contract output; if P0 is not yet merged to `iteration/v1.90`, P1 rebases its worktree onto P0 branch or waits.

**Risk and rollback**
- Risk: P0 changes generated module layout in a way P1 did not anticipate. Mitigation: P1 reads P0 Completion Report and generated diff; targeted fix wave if needed.
- Risk: Vite proxy path mismatch breaks dev mode. Mitigation: update `vite.config.ts` and test dev proxy.
- Rollback: revert P1 branch; no backend code changed.

**Verification plan**
- `pnpm --filter @42ch/nexus-contracts run build`
- `pnpm --filter web run typecheck`
- `pnpm --filter web run test`
- `rg "local[-_]api\|/v1/local/\|Local API" apps/web/` returns no matches.
