## Clarify

- **Which literals count as "duplicating a brand var"?** A literal is in scope only if its value equals the brand blue (`#1e3a5f` light / `#25d1e0` dark) or the brand-blue rgba. Theme-distinct values (e.g. a desaturated canvas edge gray, a semantic conflict red) stay as-is.
- **Rgba fills that are *tinted* from the blue?** Replace with a `color-mix(in srgb, var(--color-blue-700) N%, transparent)` form, preserving the original alpha `N`. This is the **established house pattern** — `--color-canvas-write-stale-bg` already uses it at index.css L110/L257 (`color-mix(in srgb, var(--color-amber-700) 8%/12%, transparent)`), and 30+ TSX sites (badge, status-badge, task-kind-badge, daemon-status-bar, maturation-indicators, canvas/strategy-canvas) use the Tailwind-arbitrary equivalent `bg-[color-mix(in_srgb,var(--color-<hue>-700)_N%,transparent)]`. P0 must use the index.css token form (not invent a new shape), so the tint tracks `--color-blue-700` across themes. Add a one-line CSS comment noting the convention.
- **Why is this a token-source fix, not a visual retint?** Verified: the canvas component/page TSX already renders brand-cyan (V1.83 retinted it). The 5 rgba + 6 hex lines are the *only* residual; they hold the correct brand color but as hardcoded literals. W004's filed symptom ("dark canvas reads inconsistently") is therefore already resolved at the component layer — the remaining work is SSOT hygiene (same class as W005). Flagged for writing-specialist/PM: the compass "author-facing headline" framing slightly oversells the visual delta; the closure decision (close W004/W005) is unchanged.
- **Genuine brand-token gap discovered?** Report to architect; amend root DESIGN first. Do not fabricate.
- No open high-impact ambiguity.
