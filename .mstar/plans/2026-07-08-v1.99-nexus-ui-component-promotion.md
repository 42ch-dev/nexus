# P0 — `@42ch/nexus-ui` Component Promotion

**Goal:** Promote a focused first batch of reusable, token-driven UI primitives from `apps/web` ownership into `@42ch/nexus-ui` and consume them from both Design Studio and Web.

**Architecture:** `@42ch/nexus-ui` becomes a small presentational component package, not an app shell package. Promoted components must depend only on React, shared class composition, and the shared token pipeline. App state, routing, daemon clients, and layout composition stay in `apps/web` or `apps/design-studio`.

**Tech Stack:** React 18, TypeScript, tsup, Vitest, Tailwind class strings from `@nexus/design-tokens`, `packages/nexus-ui`, `apps/web`, `apps/design-studio`.

**Execution:** mstar-sdd

## Product Framing

**User value:** Future UI work should not require copying or reinterpreting the same primitive across Design Studio and Web. Shared primitives should provide consistent visual behavior while leaving product logic in the app that owns it.

**Problem statement:** V1.98's transitional `@web-ui/*` import path made Design Studio useful quickly, but it leaves the shared visual language dependent on app internals. That is acceptable for a first mirror and unhealthy for a reusable component system.

**Target state for this plan:** A deliberately small first batch proves that `@42ch/nexus-ui` can own pure presentational primitives without becoming an app shell package. Every promoted primitive must have a traceable reason, a public import path, consumer adoption, and package-level verification.

**Non-goals:** Do not promote page layouts, app chrome, daemon-aware controls, or every shadcn primitive simply because it exists under `apps/web/src/components/ui`.

## Global Constraints

- Read P-1 outputs before implementation: `.mstar/iterations/v1.99/specs/component-promotion-boundary.md` and `.mstar/iterations/v1.99/guides/studio-first-ui-workflow.md`.
- Do not import from `apps/web` or `apps/design-studio` inside `packages/nexus-ui`.
- React and React DOM remain peer dependencies of `@42ch/nexus-ui`; implementation helpers such as `class-variance-authority`, `@radix-ui/react-slot`, `clsx`, or `tailwind-merge` are package runtime dependencies only if promoted primitives import them.
- Use public package exports only in consumers; V1.99 defaults to named root exports from `@42ch/nexus-ui`, not per-component deep imports.
- Keep first-batch scope to the P-1 lock: `Button`, `Badge`, and `Card` only. `Input`, `Label`, and `Textarea` defer to a later Form Field slice with a focused accessibility/form-state contract.
- Package components must use package-local class composition and token-backed class names; no `@web-lib/utils`, app aliases, product copy, app providers, or package-owned token duplication.
- Do not import SVG/PNG assets from component source. Preserve the existing bundler-agnostic logo asset pattern.
- `wire_contracts_changed: false`; no `schemas/` edits.

## Acceptance Hooks

- The promoted first batch matches the P-1 classification and has no surprise additions.
- `Input`, `Label`, and `Textarea` are recorded as deferred with the Form Field revisit trigger.
- `apps/design-studio` demonstrates promoted primitives without `@web-ui/*` for those components.
- `apps/web` either consumes the same primitives or records a clear wrapper/non-promotion reason for app-specific behavior.
- Package exports, README/AGENTS guidance, and tests make the new public API understandable to the next implementer.
