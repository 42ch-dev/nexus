# P1 - Timeline-first Canvas Surface Elevation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `mstar-sdd` (recommended). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Elevate Timeline from an outline sub-lane to a first-class peer `CanvasSurfaceKind = "timeline"` that projects World-building entities (KeyBlocks/events/Forks) on a timeline axis, and make it the default/hero surface when **entering a World** - the concrete PMF bet for the three-pillar pivot.

**Architecture:** Additive frontend refactor. Extracts Timeline from the shipped `work-outline-timeline` surface into a peer surface via the V1.114 `CanvasSurfaceAdapter` recipe. New `TimelineCanvasAdapter` projects the existing `WorldKbGraphResponse` (World KB entities + typed relationships + source anchors) onto a timeline-axis React Flow canvas; KeyBlock entities of `block_type=event` (entity-scope-model §5.1.1) are the when-axis "events"; other entity kinds render as Context clusters off the axis. **Single read endpoint reused: `GET /v1/daemon/worlds/{world_id}/kb/graph`** (V1.73 shipped) + optional `GET /v1/daemon/narrative/worlds/{world_id}` sidecar for a Fork-badge header. **No new Daemon HTTP routes, no new schemas, no daemon Rust changes, no codegen churn** (`wire_contracts_changed: false`, architect-locked feasible). Write boundary: `kb.patch_entity` only — `timeline.patch_event` (Work-scoped) is NOT invoked from this surface. Conflict UX reuses `WorldKbConflictError` (409) + `WorldKbValidationError` (422); no new conflict DTO. Canvas IA changes so World entry (`/worlds/:worldId`, Worlds list pick) renders Timeline by default (today: `/worlds/:worldId/kb`). **Work entry remains Outline** (V1.118); Outline adapter untouched.

**Tech Stack:** TypeScript, React, `@xyflow/react` (React Flow), `@dagrejs/dagre`, `apps/web` (Vite SPA), `packages/nexus-ui`, vitest. Rust/daemon untouched.

**Execution:** mstar-sdd

**Iteration compass:** `.mstar/iterations/v1.122/delivery-compass.md`  
**Product spec (iteration-scoped):** `.mstar/iterations/v1.122/specs/timeline-hero-product-spec.md`  
**Depends on:** P0 plan `2026-07-18-v1.122-three-pillar-spec-refactor` (Draft overlay lock for `"timeline"` + World-entry IA)

### Data composition (architect-locked)

The Timeline hero surface is **World-scoped**. The adapter's `projectGraph` accepts `WorldKbGraphResponse` (single source) and projects:

| `WorldKbGraphResponse` field | Projection on Timeline canvas |
|-------------------------------|-------------------------------|
| `entities[block_type=event]` | `TimelineEventNode` — positioned on the when-axis by `body.attributes.occurred_at` when present; else grouped into a temporal-unknown cluster with honest copy |
| `entities[block_type!=event]` (character/scene/organization/item/info_point/conflict/ability/...) | `TimelineKeyBlockNode` (Context cluster) — positioned off-axis or attached to related event nodes via relationship edges |
| `relationships[]` | `TimelineEdge` reusing `WorldKbEdgeData` exactly (`relationshipId, relationType: WorldKbRelationshipKind, customLabel?, confidence?, sourceAnchorIds[], symmetric, projectionDirection`) — read-only in V1.122 |
| `source_anchors[]` | Grounding badge data on nodes that carry `sourceAnchorCount > 0` |

- **No Work-scoped composition.** Work outline timeline events (`timeline.patch_event` surface) are NOT merged onto the World when-axis in V1.122. They remain on the Outline (Timeline-companion) surface.
- **No Fork marker nodes in V1.122.** `WorldState.is_fork` / `parent_world_id` / `forked_from_event_id` may render as a header badge on the canvas chrome (read-only), not as timeline nodes. Fork create/merge UI is forbidden (Non-Goal).
- **Honest empty-state.** Sparse World (zero `block_type=event` entities) renders an empty-state that explains the spine and links to peer World KB. The adapter MUST NOT fabricate event ordering; `summarizeGraph` MUST include the ordering-disclaimer string ("Ordering inferred from available event data; not a canonical chronology.") when temporal signals are partial or absent.

### Adapter contract (architect-locked)

```ts
// apps/web/src/components/canvas/timeline-canvas/timeline-canvas-adapter.tsx

type TimelineGraph = WorldKbGraphResponse;                       // single source, no wrapper
type TimelineNodeData = WorldKbEntityProjection & {
  layoutHint: 'event' | 'context';                              // 'event' when block_type === 'event'
  occurredAtHint?: string;                                       // from body.attributes.occurred_at if present
};
type TimelineEdgeData = WorldKbEdgeData;                         // exact reuse

// Factory form per V1.114 §3.3.1 (stable ctxRef pattern)
const adapter = createTimelineCanvasAdapter(ctxRef);
adapter.surfaceKind === 'timeline';
adapter.projectGraph(graph: WorldKbGraphResponse) => { nodes, edges };
adapter.nodeTypes // registers TimelineEventNode, TimelineKeyBlockNode (no Fork marker node)
adapter.edgeTypes? // optional; reuses world-kb edge components where applicable
adapter.layoutOptions? // { direction: 'LR', ... } — opts into dagre left-to-right
adapter.adaptConflict?(error) // projects WorldKbConflictError / WorldKbValidationError to modal props
adapter.renderInspector?(node) // entity-inspector reusing World KB entity fields
adapter.renderAltView?() // sortable entity table (title/kind/status/anchors/updated)
adapter.summarizeGraph(graph) // 'N events, M entities, K relationships' + ordering disclaimer when applicable
```

- Adapter **conforms to `CanvasSurfaceAdapter<TimelineGraph, TimelineNodeData, TimelineEdgeData>`** from `specs/canvas-strategy-surface.md` §3.3.1.
- `TimelineCanvasAdapter` is the **only** adapter permitted to register `surfaceKind: "timeline"` in `CanvasShell` / `canvas-nav`.
- Outline (`work-outline-timeline`) adapter is **unchanged**; no regression in Work-entry behavior.

### Write boundary (architect-locked)

- The Timeline surface edits World-scoped KeyBlock entities through **`POST /v1/daemon/worlds/{world_id}/kb/patch-entity`** (V1.73 shipped) only.
- Draft edits → typed canvas operation → existing `NexusClient.worldKb.patchEntity(...)` → daemon validation → atomic persistence → refetch canonical graph. No raw-file writes (§2 invariant preserved).
- `adaptConflict` projects `WorldKbConflictError` (stale `expected_version`) and `WorldKbValidationError` to existing conflict-modal props; conflict-modal copy is **world-kb-flavored** (reuses the V1.73/V1.74 copy tokens).
- **NOT invoked from Timeline:** `timeline.patch_event` (Work-scoped outline markdown), `world_kb.patch_relationship` (deferred to post-MVP; relationships read-only on Timeline in V1.122), `kb.promote_candidate` (candidate workflow belongs to World KB surface).
