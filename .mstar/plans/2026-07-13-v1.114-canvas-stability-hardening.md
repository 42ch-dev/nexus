## Problem

Authors expect the canvas write boundary to reject impossible Strategy graphs
at the **source of truth**. Today self-loop edges and duplicate transition
rules can land if client guards are bypassed. Conflict recovery also feels
different per surface, and ~15 canvas residuals undercut a "foundation"
claim. Product outcome: trustable writes + consistent conflict UX + honest
residual slate.

## Goals

1. Ship server-side self-loop guard on Strategy `op:create`.
2. Ship server-side duplicate-transition-rule dedup on Strategy `op:create`.
3. Add command-registry collision detection (dev-mode warn at minimum).
4. Harmonize conflict-modal focus/keyboard/ARIA across the 4 surface hosts.
5. Close ≥10 canvas-cluster open residuals (verify each against current code).

## Acceptance criteria (product-facing)

- [ ] Self-loop Strategy edge create is rejected by the daemon (422-class) even
  without the client guard
- [ ] Duplicate `(to, when)` transition rules cannot accumulate as distinct
  stored rules — **reject 422** (`strategy_transition_duplicate`, already
  implemented; T2 verifies + closes the residual)
- [ ] Four conflict modals share focus trap / keyboard dismiss / ARIA timing
- [ ] ≥10 canvas-cluster residuals closed or accepted with rationale in SSOT
- [ ] Command id collisions warn in dev (no silent last-write-wins for new
  registrations)

## Global Constraints

- **No behavior change for valid operations**: existing valid Strategy patches,
  commands, and conflict flows behave identically.
- **Additive guards only**: new validation rejects invalid input that was
  previously silently accepted; it does not reject input that was previously
  valid.
- **Conflict-modal base preserved**: harmonize on `conflict-modal-base.tsx`,
  do not redesign it.
- **Bounded residual batch**: ≥10 canvas-cluster only — not a full debt sweep.

## Tasks (SDD)

### T1 — Server-side self-loop guard
- Strategy `op:create` returns 422 when `source_state_id == new_target`.
- Add the guard at handler level in `apply_transition_create()` (before YAML
  mutation), matching the `outline.rs` precedent (~L1259). Error code:
  `strategy_self_loop`. Do not rely solely on `validate_preset_yaml` catching
  it after mutation.
- Server test: self-loop `op:create` returns 422 `strategy_self_loop`.
- Closes `R-V1109-P1-QC2-W001`.

### T2 — Server-side transition-rule dedup — VERIFY + CLOSE
- **The dedup guard already ships** in `append_conditional_rule()`
  (`strategy.rs` ~L900) with error code `strategy_transition_duplicate`
  (reject 422 semantics — locked by @architect). The test
  `patch_transition_create_rejects_duplicate_rule` already exists.
- T2's job: **verify** the guard against current code (run the test, audit the
  `update` op path for a similar gap), and **close** `R-V1109-P1-QC2-W002` as
  already-resolved. If the `update` op path (not just `create`) has a dedup
  gap, add a targeted guard there. Do NOT change reject → silent-dedup.

### T3 — Command-registry collision detection
- `useCommandRegistry()` (or equivalent) emits `console.warn` (dev mode) when
  two commands register the same id.
- Test: duplicate registration emits the warning.

### T4 — Conflict-modal harmonization audit + fix
- Audit the 4 conflict-modal hosts for focus-management, keyboard-shortcut, and
  ARIA-timing drift.
- Align on the shared base without losing surface-specific copy.
- Tests: focus trap, focus return, ARIA announcement timing consistent across
  surfaces.

### T5 — Canvas residual cluster closure (≥10)
- Triage ≥10 canvas-cluster open residuals from `status.json`.
- **Include `R-V1109-P1-QC2-W002`** (duplicate-transition dedup) — verify
  already-resolved, then close.
- Verify each against current code; close resolved, accept-with-rationale the
  intentional ones, defer the rest with updated targets.
- Update `status.json` residual_findings + archive resolved rows.
