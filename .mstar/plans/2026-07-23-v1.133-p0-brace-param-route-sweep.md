## Problem Statement

**User impact:** Creators using the Control Room / web SPA cannot reliably open or mutate ID-scoped resources — works, worlds, KB entries, findings, memory pending-review, agent-host sessions, orchestration schedules, reading annotations. Requests with real IDs hit the daemon and come back as framework 404 even when the entity exists. The product looks “not found” / broken for core daily paths.

**Root cause (false-Done):** V1.132 P0 fixed 404 errors on 4 daemon surfaces (presets/sessions/modules/strategy) by converting `{param}` → `:param` (matchit 0.7 capture syntax). ~31 other daemon routes in `crates/nexus-daemon-runtime/src/api/mod.rs` still use the broken `{param}` brace form. In axum 0.7 + matchit 0.7, `{param}` is a **literal** path segment — it never captures real IDs and returns framework 404. The web client (`apps/web/src/`) already sends real IDs to these endpoints.

## Technical Approach

### T1: Mechanical brace -> colon conversion (~33 routes)

Replace every `{param_name}` with `:param_name` in route path strings within `crates/nexus-daemon-runtime/src/api/mod.rs`. The handler signatures do not change — `axum::extract::Path` already works with `:param` captures.

**Standard cases (no handler change needed):** Chapter `{n}` → `:n` (nested router `/{n}`, `/{n}/outline`, `/{n}/body`; canvas route `/{work_id}/chapters/{n}/patch`). `{key_block_id}` → `:key_block_id` (line 381). All other `{work_id}`, `{world_id}`, `{session_id}`, `{schedule_id}`, `{entry_id}`, `{annotation_id}`, `{id}`, `{finding_id}` → colon form.

**Edge case — `{operation_id}:cancel` (line 70):** This is the only route with a brace param immediately followed by a `:suffix` without `/` separator. Matchit 0.7 rejects consecutive `:a:b` captures; simple `{param}` → `:param` substitution would produce `:operation_id:cancel`, which is invalid. The fix mirrors the existing `logout_creator` pattern:

1. Change the route from `"/v1/daemon/agent-host/operations/{operation_id}:cancel"` to `"/v1/daemon/agent-host/operations/:operation_id"` (drop the `:cancel` suffix from the route pattern).
2. In `cancel_operation` handler, add 2-3 lines at the top to strip the trailing `:cancel` from `operation_id` before UUID parsing:
   ```rust
   let operation_id = operation_id
       .strip_suffix(":cancel")
       .ok_or_else(|| NexusApiError::NotFound(...))?
       .to_string();
   ```
   The handler signature (`Path(operation_id): Path<String>`) does not change.

This is the **only** handler that needs a code change beyond the route string. The `:cancel` suffix is a matchit workaround, not a wire contract change — clients already send `POST .../operations/<uuid>:cancel`.

**Files:** `crates/nexus-daemon-runtime/src/api/mod.rs` + `crates/nexus-daemon-runtime/src/api/handlers/agent_host.rs` (cancel_operation only)

### T2: Update any test mocks that reference brace-form URLs

Search test files for `{param}` patterns in URL strings and update to use real IDs (tests should already use real IDs, but some mocks may hardcode the brace form).

**Files:** Any test files in `crates/nexus-daemon-runtime/src/` that reference route paths.

### T3: Regression tests for affected route groups

Add or extend tests that exercise at least one route from each affected group with a real ID to prove the 404 is fixed. Use the existing `axum_test::TestServer` infrastructure already in the crate.

**Route groups to cover:**
1. agent-host sessions - GET `/v1/daemon/agent-host/sessions/:real_id` (+ cancel operation: POST `/v1/daemon/agent-host/operations/:real_id:cancel`)
2. orchestration schedules - GET `/v1/daemon/orchestration/schedules/:real_id`
3. KB entries - GET `/v1/daemon/kb/entries/:real_id`
4. narrative worlds - GET `/v1/daemon/narrative/worlds/:real_id`
5. reading annotations - GET `/v1/daemon/reading/annotations/:real_id`
6. memory pending-review - GET `/v1/daemon/memory/pending-review/:real_id`
7. works - GET `/v1/daemon/works/:real_id`
8. worlds + KB - GET `/v1/daemon/worlds/:real_id`
9. findings - GET `/v1/daemon/findings/:real_id`

**Edge case test — cancel operation with `:cancel` suffix:** POST to `/v1/daemon/agent-host/operations/<real_uuid>:cancel` should route correctly and have the handler strip `:cancel` before UUID parsing. Without this fix, the route matches only the literal string `{operation_id}` in the URL path.

### T4: Verify and close

Run `cargo test -p nexus-daemon-runtime` and `cargo clippy -p nexus-daemon-runtime -- -D warnings`. Confirm zero `{param}` brace-form routes remain via grep.

## Risks

- Some tests may assert 404 for unknown IDs - these should still 404 (unknown ID), the fix ensures known IDs don't 404
- The `{n}` chapter route parameter is numeric - `:n` captures any segment, handler validates
- **`{operation_id}:cancel` edge case:** Matchit 0.7 rejects consecutive `:a:b` captures; the fix uses handler-side suffix stripping (same pattern as `logout_creator`). Risk is low — the pattern is proven in-tree, and only 2-3 lines are added.
- **Test mock URLs:** Some test files may reference brace-form route paths in mock request URLs. After conversion, tests must use real IDs. A search for `{param}` patterns in test files under `crates/nexus-daemon-runtime/` is required during implementation.
- **`axum::routing::patch` (line 123):** The `edit_core_context` handler is registered via `axum::routing::patch(...)` in bare form. This is correct as-is; only the path string `{schedule_id}` needs conversion.
- Residual confusion with domain “not found” vs framework path miss — acceptance must distinguish framework 404 from handler 404
