**Goal:** Make the Setup page honestly detect the **supported** agent inventory
(claude, codex, cursor, opencode, kimi) and add codex as a first-class native
CLI provider.

**Architecture:** Two-layer fix: (1) `nexus-acp-host::registry::scan_local_installations`
extracts bare command names from ACP registry relative paths so existing
ACP-registered agents (cursor/kimi/opencode) become detectable; (2) a new
`CodexNativeProvider` in `nexus-agent-host::providers::native_cli` — **not a
copy-paste of `ClaudeCliProvider`** (codex CLI is subcommand-based `codex exec
--json`, with codex-generated session IDs; see P0 spec AD-1); (3) the
`/v1/daemon/agent-host/scan` endpoint merges native CLI discovery results
alongside ACP registry agents so the Setup page sees both (additive —
`registry_agent_id: null` for native entries; no schema field change needed,
see P0 spec AD-2).

**Tech Stack:** Rust (nexus-acp-host, nexus-agent-host, nexus-daemon-runtime),
TypeScript/React (apps/web setup page)

**Execution:** mstar-sdd

## Problem Statement

The Setup page is the first thing every new author sees. It currently **lies** —
showing codex, cursor, opencode, and kimi as "not installed" even when they
are on PATH. Root causes (verified by code inspection + live ACP registry
fetch on 2026-07-13):

1. **ACP registry binary cmds are relative paths.** The registry at
   `cdn.agentclientprotocol.com` lists binary commands like `./kimi`,
   `./opencode`, `./dist-package/cursor-agent`. The `probe_local_binary`
   function calls `which::which("./kimi")` which looks for a file named
   `./kimi` in the current directory, NOT `kimi` on PATH. Result: every
   registry agent with a relative-path cmd is invisible.

2. **`codex-acp` has no binary distribution.** The registry entry for codex
   (`codex-acp`) has `binary: None`. It is never probed. Product decision
   (locked): codex is a **native CLI provider** (like `claude-native`), NOT
   through ACP as the preferred path.

3. **`KNOWN_COMMANDS` only has `claude`.** The `scan_path` function in
   `path_scan.rs` — the native CLI discovery path — only maps
   `("claude", "claude-native")`. codex is absent.

4. **Scan endpoint excludes native CLI providers.** `/v1/daemon/agent-host/scan`
   iterates ACP registry agents only. Native CLI providers discovered via
   `scan_path` (like `claude-native`) do NOT appear in the scan response.

5. **Verify button verbose text.** The button label is longer than a single
   verb; product wants just "Verify" / "验证".

**Relation to V1.110:** PATH enrichment (nvm/volta/etc.) improved *where*
`which` looks. This plan fixes *what* command string is probed and *which*
providers appear in Setup.

## Scope

### In scope

- Fix `scan_local_installations` to extract bare command names from ACP
  registry relative paths (`./kimi` → `kimi`, `./dist-package/cursor-agent`
  → `cursor-agent`)
- Add `("codex", "codex-native")` to `KNOWN_COMMANDS` in `path_scan.rs`
- Implement `CodexNativeProvider` adapter in
  `nexus-agent-host::providers::native_cli::codex` (session create / prompt /
  shutdown / health / capabilities — mirror `claude-native` pattern)
- Merge native CLI provider discovery into the
  `/v1/daemon/agent-host/scan` response (additive — existing ACP entries
  unchanged, native CLI entries appended)
- Frontend: Verify button label → "Verify" (en) / "验证" (zh-CN); ensure Setup
  list renders native entries (`registry_agent_id: null`)
- Tests: unit tests for bare-cmd extraction; codex-native provider tests;
  scan endpoint integration test with both ACP + native entries

### Not in scope

- Native CLI providers for cursor / kimi / opencode (they stay ACP registry
  agents — they have ACP adapters)
- Full ACP protocol support for codex as the preferred product path
  (codex-native is preferred; codex-acp may remain listed)
- codex streaming / structured tool calls (native CLI limited capabilities,
  same as claude-native)
- PATH enrichment expansion (homebrew / asdf / mise / nvm — separate concern;
  already improved in V1.110)
- Unbounded detection of every binary on PATH (supported inventory only)
- Full Setup wizard IA rework beyond detection honesty + Verify copy

## Global Constraints

- **Wire contracts (AD-2):** `AgentScanEntry.registry_agent_id` is already
  `["string", "null"]` — native CLI entries reuse `registry_agent_id: None`.
  **No schema field change.** Description-only update (additive, non-breaking)
  to mention "native CLI providers" alongside "custom wizard-supplied entries."
  `@42ch/nexus-contracts` stays at current version.
- **Provider ID naming:** `codex-native` (mirrors `claude-native` convention;
  avoids collision with ACP registry `codex-acp`).
- **Capability descriptor:** `native_cli_limited()` — same as claude-native
  (no set_model, no set_mode, no structured_tool_calls; `session_restore: true`
  since codex supports `exec resume <id>`).
- **codex CLI protocol (AD-1):** subcommand-based (`codex exec`), `--json`
  JSONL streaming, codex-generated session IDs. NOT a copy-paste of
  `ClaudeCliProvider`. Per-invocation mode only.
- **No hand-written DTOs:** any new wire types come from `schemas/` → codegen.
- **Clippy:** `cargo clippy -p nexus-agent-host -p nexus-acp-host -p
  nexus-daemon-runtime -- -D warnings` must pass.
- **Dedup (AD-3):** `NATIVE_PREFERRED_FAMILIES` constant maps registry IDs to
  suppress (`codex-acp`, `claude-acp`) when the matching native provider
  (`codex-native`, `claude-native`) is installed. When native is absent or not
  installed, the registry entry remains (shows "not installed" honestly).

### Task 3: Implement CodexNativeProvider adapter

**Files:**
- Create: `crates/nexus-agent-host/src/providers/native_cli/codex.rs`
- Modify: `crates/nexus-agent-host/src/providers/native_cli/mod.rs`
- Test: inline or sibling test file

**Interfaces:**
- Consumes: `ProviderAdapter` trait, `HostOperation`, `HostEvent`
- Produces: full `codex-native` provider (session create / prompt / shutdown
  / health / capabilities)

**Architect notes (AD-1):** codex CLI is subcommand-based (`codex exec`),
NOT flag-based like claude. The adapter is **not** a copy-paste of
`ClaudeCliProvider` — arg assembly, JSONL event parsing, and session-ID
lifecycle differ. Per-invocation mode only (codex `exec` exits after one
prompt; no persistent child reuse). Session ID is codex-generated (captured
from `--json` JSONL output), not host-generated.

- [ ] **Step 1:** Study codex CLI `exec --json` output shape (run
      `codex exec --json "test"` if auth available; otherwise study codex
      source/docs). Document the JSONL event types: session-start,
      message-delta, finish. Capture which event carries the session ID.
- [ ] **Step 2:** Write failing tests for session lifecycle (create /
      prompt / shutdown). Use `echo`-based mock or skip network-dependent
      assertions for unit tests; integration test for real codex CLI gated
      behind `cfg!(target_os = ...)` or a feature flag.
- [ ] **Step 3:** Implement `CodexNativeProvider`:
      - `default_config()`: provider_id `codex-native`, command `codex`,
        args `["exec", "--json", "-s", "read-only"]`
      - `launch()`: register `NativeSession { codex_session_id: None,
        first_exec_done: false }` (no process spawn yet)
      - `execute()`: first call spawns `codex exec --json -s read-only`
        with prompt on stdin; parse JSONL events; capture session ID;
        subsequent calls use `codex exec resume <id> --json`
      - `descriptor()`: `CapabilityDescriptor::native_cli_limited()` with
        `session_restore: true` (codex supports resume)
      - `probe()`: `which::which("codex")` (same pattern as claude)
      - **Fallback:** if `--json` parsing fails, fall back to plain stdout
        line streaming (drop `--json` from args) — preserves MVP
- [ ] **Step 4:** Register in `providers/native_cli/mod.rs` (`pub mod codex;`)
- [ ] **Step 5:** Tests pass; clippy clean
