# V1.90 — Daemon API Remote-Ready Rename — Delivery Compass v1

**Status**: completed — Phase 1 Review & Edit chain complete; P0/P1 implemented and merged; QC tri-review Approve; QA Pass; compound done; ready for PR to `main`.
**Author**: `@project-manager` (compass + grill-me locked scope).

## 0. Context

V1.89 shipped deeper manuscript reading (persisted progress + annotations/highlights). The codebase is in a clean state with zero open residuals. The next product-architecture concern is the naming of the HTTP API surface: today it is called **Local API**, but the web UI and desktop app could in principle connect to a daemon running on another machine. The name “Local API” therefore undersells the architecture and will become misleading if/when remote connectivity is enabled.

V1.90 renames the surface to **Daemon API**, updates all internal identifiers and generated contracts to match, changes the public HTTP path prefix from `/v1/local/*` to `/v1/daemon/*`, and adds an explicit opt-in remote listener so authors can bind the daemon to a non-loopback interface when they choose to.

## 6. Non-Goals

- **TLS termination** — remote users are expected to put the daemon behind a reverse proxy or VPN; no built-in TLS.
- **Cloud sync / platform integration** — platform remains paused per PD-05.
- **A new auth model beyond the existing API key** — remote access reuses `NEXUS42_DAEMON_API_KEY`.
- **Mobile apps or mobile-targeted UI**.
- **Remote deployment of the web UI** — the SPA remains bundled/served by the daemon.
- **Renaming the `nexus42` binary, `nexus-daemon-runtime` crate, or `@42ch/nexus-contracts` package** — only the API surface and its contracts are renamed.
- **Behavior changes to endpoint semantics** — only names and paths change; request/response shapes keep their current fields.
