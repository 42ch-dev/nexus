# V1.101 — Desktop Setup Polish, Agent Picker & Select Stretch

## Scope

V1.101 closes the author-visible setup gaps left after V1.100 clean-state first-launch, and keeps the design-system promotion line moving with a stretch `Select` slice.

### Must / Stretch integrity (locked)

| Tier | Plans | May defer? | Iteration incomplete if missing? |
|------|-------|------------|----------------------------------|
| **Must** | **P0** agent detection + AgentPicker; **P1** wizard UI polish (BACK / STEPS / POLL) | No | **Yes** |
| **Stretch** | **P2** `Select` promotion only | Yes → V1.102 | **No** — deferring P2 does not leave Must incomplete |

Order: **P0 → P1 → P2**. Inside each plan: **Studio visual → App wiring**. Do not treat P2 as Must, and do not start P2 until P0+P1 automated paths are Done (unless PM documents an explicit capacity exception).

- **SP-1 (Must / P0): Agent detection + AgentPicker.** Setup wizard agent step must surface locally available ACP agent CLIs, allow selection into the agent profile, and show honest empty/error/custom-launch states. UI follows an Open Design–inspired card grid (status dots, install/docs **outbound** links only). Extract a reusable `AgentPicker` for a future Settings shell (**shell itself = DF-70, not shipped**).
- **SP-2 (Must / P1): Setup wizard UI polish.** Close smoke residuals for Back button placement, sidebar Steps indicator, and daemon “running” poll/subscription timing.
- **SP-3 (Stretch / P2): `Select` component promotion.** Promote presentational `Select` into `@42ch/nexus-ui` under a locked contract; whole plan may defer to V1.102 if Must work consumes the iteration.

## Product Story

V1.100 made clean-state launch reachable. Authors still hit a setup step that does not surface installed agents credibly, plus wizard chrome that feels broken. V1.101 makes first-run agent choice trustworthy (local-first ACP client: use the author’s existing agents, no BYOK) and the wizard chrome intentional, while optionally proving the next design-system primitive (`Select`) under the same studio-first discipline.

## Acceptance Criteria

### Must (P0 + P1) — required for iteration Must completeness

- Setup agent step surfaces locally available ACP agents from the existing scan path (or a documented minimal fix if scan→UI is broken); author can select an **installed** agent (or custom launch) and persist profile.
- Card grid may show known-but-not-installed registry entries for discoverability; those cards are **not** selectable as the profile — only outbound install/docs (when URL present) plus custom launch as the escape hatch.
- Empty, error, and custom-launch states are **acceptance-visible** (Studio fixtures + App wiring + Vitest): honest copy, custom launch remains available when scan is empty or fails.
- Install/docs links are **outbound URLs only** (no in-app installer, no BYOK); missing URL → hide that link.
- `AgentPicker` is a reusable **app-shared** presentational/composition surface at `apps/web/src/components/setup/agent-picker.tsx` (no wizard-route coupling; **not** promoted to `@42ch/nexus-ui` this iteration) suitable for a future Settings host; wizard is the first consumer. **Settings shell is not shipped** (DF-70 remains deferred).
- If scan→UI RCA is daemon PATH/env: fix via process PATH enrichment at daemon/sidecar start — **no** `schemas/` change.
- `R-V1100P0SMOKE-AGENT-SCAN`, `R-V1100P0SMOKE-UI-BACK`, `R-V1100P0SMOKE-UI-STEPS`, and `R-V1100P0SMOKE-UI-POLL` are closed or explicitly re-scoped with **automated** evidence. Human interactive smoke may further confirm PATH reality but **does not** block automated Done.
- Design Studio fixtures exist and pass visual acceptance **before** App wiring for each UI-bearing Must plan.
- Automated QA/CI does **not** require interactive macOS smoke; human smoke is scheduled separately after automated paths land.
- Prefer `wire_contracts_changed: false`. Any proposed `schemas/` change blocks implement and returns to architect/PM.

### Stretch (P2) — optional; deferral allowed

- If P2 runs: `Select` is exported from `@42ch/nexus-ui`, Studio-direct + Web thin wrapper strategy matches V1.100 form-field pattern; package stays presentational.
- If P2 is deferred: compass + `status.json` retarget V1.102 with reason; Must completeness is unaffected.

## Non-Goals

- BYOK / API-key execution modes.
- Full Settings shell, settings sidebar IA, or settings routes (DF-70).
- In-app agent installers or package managers.
- Field groups / FormField framework / React Hook Form / Zod.
- Promotion of dialogs, tabs, tables, or other primitives beyond optional Stretch `Select`.
- Treating Stretch `Select` as a Must / iteration-incomplete gate.
- `R-V192SEC-001` transport-layer cert pinning.
- Platform sync, billing, entitlements, signing, notarization, auto-update.

- **Relation to V1.100:** Continues UI completeness after clean-state bootstrap; consumes smoke residuals registered at P0 Done.
