# V1.116 Delivery Compass — Stabilization & Canvas/Compute Readiness

## Product story

V1.115 made Canvas and Compute foundations **honest and reusable**. V1.116 is
a **stabilize-before-extending** iteration (same cadence family as V1.80 /
V1.93): clear the trust and hygiene blockers that would poison the next
capability wave, then produce **evidence** so the next deep-dive is a
deliberate pick — not a leap of faith.

The single coherent bet:

> **Make first-run Setup and maintainer surfaces tell the truth, then prove the
> Canvas/Compute rails are ready before we build on them.**

| Who | What they get when V1.116 is Done |
| --- | --- |
| **Authors (first launch)** | Setup detects the **supported** agent inventory honestly — installed CLIs show as installed; absent CLIs show as not-installed |
| **Authors who use codex** | codex is a first-class **native CLI** provider (detectable, selectable, session can start and accept a prompt) — not an ACP-only dead end |
| **Maintainers** | `pnpm dev:desktop` is production-like (quiet, dist-load); design-studio previews show real **en** text, not raw i18n keys |
| **Next iteration** | A readiness assessment + **3 candidate skeletons** (Strategy `onConnect` / compute state editor / 5th surface) so PM can pick a direction and enter Prepare with evidence |

**Direction lock mode: interactive** (grill-me with user; seven decisions
recorded below). Do not re-litigate.

### Grill-me decisions (locked)

1. **Iteration main line**: Stabilization + readiness research. No new product
   feature surface this iteration. Similar to V1.80 / V1.93
   stabilize-before-extending cadence.
2. **Plan split**: 3-plan (P0 blocker + P1 hygiene + P2 research).
3. **codex-native scope**: Full native CLI provider adapter (detection +
   session management), same pattern as `claude-native`. codex does **not**
   go through ACP as the preferred path.
4. **P2 deliverable**: Readiness assessment spec + 3 candidate spec skeletons
   (Strategy `onConnect` / compute state editor / 5th canvas surface).
5. **Desktop dev strategy**: `pnpm dev:desktop` loads from pre-built
   `web/dist/` (production-like, no Vite server); `pnpm dev:desktop:web`
   preserves the current HMR mode (Vite + Tauri dual-start).
6. **Iteration ID / branch policy**: V1.116; `iteration_base_branch: main`;
   `spec_integration_branch: iteration/v1.116`; `target_branch: main`.
7. **Design-studio locale**: Studio imports compiled en locale from web
   (web remains locale SSOT); Studio loads en only.

### Scope (one coherent bet)

V1.115 shipped honest foundations. Three residual honesty/hygiene issues plus
one strategic question remain. This iteration **clears the honesty blockers and
answers the strategic question** — not new product surface.

**Supported agent inventory (product — P0):** Claude (native), Codex (native,
new), Cursor / Kimi / OpenCode (ACP registry, bare-cmd detection). DoD is
honesty for this set — not "every binary on PATH."

**Root cause inventory (locked):**

| Issue | Root cause (product-facing) |
|-------|-----------------------------|
| Agent CLI detection broken | Setup lies: ACP registry cmds are relative paths so PATH probes miss installed agents; codex has no native product path; scan omits native CLI providers |
| Desktop dev noise | Default desktop script starts Vite before sidecar → console spam; does not match "launch the installed app" mental model |
| Design-studio raw keys | Studio has no locale provider; shared components call `t()` → previews show keys, not copy |

V1.110 improved PATH enrichment (nvm/volta/etc.). V1.116 P0 is the remaining
**detection honesty** gap (bare-cmd + codex-native + scan merge + Verify copy).

### Priority justification (Must vs Should)

| Plan | Tier | Why this tier (product) | What fails if deferred |
|------|------|-------------------------|------------------------|
| **P0** Agent Detection + codex-native | **Must** | First-impression blocker: Setup lies to authors who have supported agents installed | Authors cannot trust Setup; codex users have no first-class path; onboarding confidence collapses |
| **P1** Desktop Dev + Studio Locale | **Must** | Maintainer-surface honesty on a stabilize iteration — desktop noise trains people to ignore real errors; Studio raw keys mislead design review of the same Setup chrome P0 fixes | Devs avoid `pnpm dev:desktop`; design-studio mis-previews ship bad copy decisions |
| **P2** Readiness Research | **Should** | Evidence for next-iteration direction; not an author ship-blocker | Next PM picks a deep-dive blind; risks discovering foundation gaps mid-implement |

If capacity forces a cut: **cut P2 before P0/P1**. Prefer a thinner readiness
note over shipping a lying Setup page.

## Non-Goals

Honest freeze — do not let these creep into V1.116 "while we're here":

- **New Canvas product surface** (Strategy `onConnect`, compute state editor,
  5th surface) — readiness research only; implementation is next iteration
- **Compute module authoring SDK** — readiness research may reference it;
  no SDK code this iteration
- **Canvas ↔ compute intersection UI** — needs deep-dive first
- **Full ACP protocol support for codex** — codex is deliberately native CLI
  preferred; community `codex-acp` may remain in the registry but is not the
  product path
- **Native CLI providers for cursor/kimi/opencode** — these stay ACP registry
  agents (they have ACP adapters); only codex gets native this iteration
- **Multi-language design-studio** — en only; zh-CN and other locales stay
  web-only
- **Dynamic locale bundle splitting** (R-P0-003 carried from V1.112) —
  still deferred
- **Unbounded "every binary on PATH" detection** — supported inventory only
- **Closing the entire residual slate** (open tech-debt burn-down) — not a
  burn-down iteration
- **STATUS.json archival** — nice-to-have but not a plan-level goal
- **New `{KNOWLEDGE_DIR}` docs** — iteration-close compound only

## Risk Register

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| codex CLI session protocol differs from claude (args/stdin/JSON shape) | Low (Mitigated: AD-1) | Med | codex CLI is subcommand-based (`codex exec --json`), not flag-based like claude. Adapter is NOT a copy-paste of `ClaudeCliProvider` — separate arg assembly + JSONL parsing. Fallback: plain stdout streaming if `--json` shape is unstable. See P0 spec AD-1. |
| Bare-cmd extraction breaks on registry entries with no path separator (already bare) | Low | Low | `Path::file_name()` handles both `./cmd` and `cmd` shapes idempotently. See P0 spec AD-4. |
