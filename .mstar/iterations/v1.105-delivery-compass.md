# V1.105 — First-Launch Wizard Reshape

## Scope

Reshape desktop first-launch so authors experience a clear two-phase entry:

1. **Launch ritual (P0)** — fullscreen Daemon wait until Ready; not a wizard preference.
2. **Setup wizard (P1 + P2)** — three visible steps only: **Agent → Workspace → Done**, inside a fixed portrait card with top horizontal Steps.

**In scope:** always-on sidecar auto-start (D2, rewrite V1.100 Rule 13); retire Welcome and Daemon wizard steps; Agent scan via daemon HTTP API only (grill-me **B**); Workspace default `~/Documents/nexus/default` + Browse with bootstrap on Continue; portrait shell (H1/N1); Settings Re-run Setup compatibility (V1.103 R1 lands in new IA after fullscreen gate).

**Out of scope for this iteration:** Tauri PATH agent probe; multi-workspace switcher; BYOK / execution-mode matrix; Settings shell IA beyond re-run compatibility; wire/schema changes unless P0 proves unavoidable.

Order: **P0 → P1 → P2**. P2 is Studio-first (fixtures → visual accept → App wiring).

- **SP-1 (Must / P0): App-level fullscreen Daemon gate (D2).** Desktop always auto-starts sidecar (rewrite V1.100 Rule 13). Fullscreen `DaemonReadySplash` until Ready. `setup_completed=false` still only allows `/setup` (not main UI). Retire wizard-only Daemon step.
- **SP-2 (Must / P1): Wizard IA reorder (W1).** Visible steps **Agent → Workspace → Done**. Remove Welcome. Agent scan remains `POST /v1/daemon/agent-host/scan` after gate Ready (grill-me **B**). Workspace step keeps default path + Browse; Continue runs bootstrap.
- **SP-3 (Must / P2): Portrait shell + top Steps (H1/N1).** Fixed card ~480×720 (or `min(720px, 85vh)`), content scrolls; top horizontal Steps; remove left 208px step panel. Design Studio fixtures first.

## Product Story

**Who:** A new or returning desktop author installing Nexus for creative work.

**Problem:** The current four-step wizard buries the hard dependency (ACP Agent) behind Welcome and treats daemon startup as a setup step — implying authors can "configure" readiness instead of waiting for it.

**Narrative (cold start, `setup_completed=false`):**

1. App opens → fullscreen **Starting daemon…** (sidecar auto-starts silently; no wizard yet).
2. Daemon Ready → portrait Setup Wizard opens on **Agent** (Step 1). Scan lists installed agents; author picks one or enters a custom launch command.
3. **Workspace** (Step 2) shows default `~/Documents/nexus/default`; Browse is optional. **Continue** runs bootstrap then advances.
4. **Done** (Step 3) confirms → `setup_completed` set → main UI at `/works`.

**Narrative (return visit, `setup_completed=true`):** fullscreen wait → Ready → main UI (no wizard).

**Narrative (Settings Re-run Setup, V1.103 R1):** confirm clears marker only (workspace + agent profile kept) → fullscreen wait → Ready → new three-step wizard (not the legacy Welcome-first flow).

**Iteration complete when:** P0–P2 automated gates pass (fullscreen gate + IA reorder + portrait chrome).

## Acceptance Criteria

### P0 — Daemon gate (app-level, not a wizard step)

- [ ] Clean state: Tauri `.setup()` **always** auto-starts sidecar (no `setup_completed` gate — D2 rewrites V1.100 §13.9.2).
- [ ] **Both** first-launch and return visits show fullscreen Daemon wait before `/setup` or main UI.
- [ ] After Ready + `setup_completed=false`: product routes allow `/setup` only (not main shell).
- [ ] After Ready + `setup_completed=true`: main UI loads under existing `SetupGate`.
- [ ] Timeout / retry / diagnostic affordances preserved (V1.96/V1.97 parity); reset-local-database recovery still reachable from splash error paths.

### P1 — Wizard IA

- [ ] Visible steps are **only** Agent → Workspace → Done (no Welcome, no Daemon step).
- [ ] Step 1 Agent: `POST /v1/daemon/agent-host/scan` after Ready; Continue requires selection or custom command.
- [ ] Step 2 Workspace: default path displayed; Browse on desktop; `ensureSetupBootstrap` on **Continue** (not on Agent Continue).
- [ ] Step 3 Done: `setAgentProfile` + `markCompleted` → `/works`.
- [ ] Settings **Re-run Setup** (V1.103 R1): marker clear → fullscreen gate → `/setup` on Agent step; workspace path and agent profile **not** deleted.

### P2 — Portrait shell

- [ ] Fixed portrait card (~480px wide × `min(720px, 85vh)` tall); content scrolls; CTA row remains usable.
- [ ] Top horizontal Steps (Agent / Workspace / Done); left 208px step rail **removed**.
- [ ] Studio fixtures accepted before App wiring (light/dark; long agent-list overflow case).

### Cross-cutting

- [ ] Prefer `wire_contracts_changed: false`.
- [ ] Browser build: wizard + gate remain desktop-first; no regression to Vite/static-serve flows.

## Non-Goals

- **Tauri-side independent agent PATH scan** (grill-me **A** rejected; scan stays daemon HTTP only)
- **Daemon as a wizard step** — readiness is exclusively the fullscreen launch gate (P0)
- **Welcome step** — workspace selection moves to Step 2; no greeting / intro screen
- Multi-workspace switcher or workspace management beyond single default + Browse
- BYOK / execution-mode matrix / AgentPicker package promotion
- Settings shell IA redesign (V1.103 sections unchanged; only re-run → new wizard path)
- Wire/schema changes unless P0 implementation proves unavoidable
- In-app agent installers or download flows
- Bundling Design Studio into author product surface
