# V1.87 — nexus-ui Component Library Promotion + manuscript.body.read Path-Guard Fast-Follow — Delivery Compass V1

**Status**: locked (Phase 1 Review & Edit chain complete: product-manager → architect → writing-specialist → PM lock). Promotes `@42ch/nexus-ui` from the V1.83 assets/tokens-only package into a real shared React component library consumed by `apps/web`, and closes the one medium residual V1.86 deferred (`R-V186-QC1-S005`). `wire_contracts_changed: false` (pure frontend-package maturation + one surgical runtime-security fix). PR to `main` after Phase 3.

## 0. Context

The brand arc (V1.83 foundation → V1.84 polish → V1.85 app icons) deliberately shipped `@42ch/nexus-ui` as **assets + tokens + theme CSS only — no React components**. The package README's own roadmap states: *"React component library (`<NexusLogo />`, layout primitives) — deferred to a later plan after P2 proves stable usage."* V1.85 proved stable usage: `apps/web` consumes the SVG assets directly via a hand-written `components/brand/nexus-logo.tsx` (31 lines, 2 call sites). V1.86 was a security detour. V1.87 returns to the UI/package cadence and cashes the deferred roadmap item.

Meanwhile V1.86 left one medium same-class residual: `R-V186-QC1-S005` — `nexus.manuscript.body.read` tool (`host_tool_handlers.rs:2155-2156`) still uses the string-prefix `starts_with` anti-pattern that V1.86 T3 eliminated for `fs/*`. The remote-reach vector is closed by V1.86 T1 (CORS Origin allowlist), so urgency is reduced to medium/latent, but the class is real and the fix is a short delegation to the canonical `resolve_guarded_path` already proven in V1.86 (three concrete steps: determine `must_exist`, call the helper, map `BadRequest` → `InvalidInput`). Bundling it as a P1 companion batch avoids a separate hotfix round.

This iteration is squarely on-strategy: `STRATEGY.md` frames Nexus as a local-first creative-writing tool whose surfaces (CLI + web + desktop) share a brand identity. A shared component library is the structural expression of that identity across surfaces and de-risks future `nexus-platform` consumption.

**Product value (honest framing)**: For authors today there is **zero visible change** — the sidebar and header marks will render identically (visual parity is the explicit bar). The value is foundation plumbing. It eliminates duplication (the 31-line hand-written wrapper + unconsumed `logo-mono.svg`) and makes the Nexus brand a single structural source of truth. When desktop or future surfaces consume the package they inherit coherence without copy-paste; for contributors, the surface area where brand drift can occur shrinks. This is the maturation of a deferred roadmap item into a real shared library so the "one Nexus identity" principle (STRATEGY) has an implementation home — not a new author-facing feature. The headline remains P0; the P1 residual (see previous paragraph) is bundled as a companion batch, not folded into the headline framing.

## 2.1 Architecture Hierarchy and Ownership

- **P0 lives in `packages/nexus-ui/`**: `src/index.ts` (re-export), new `src/components/nexus-logo.tsx` + `src/components/nexus-mark.tsx`, `package.json` (peer deps, exports, version), `tsconfig.json` (jsx), build config. `tsup` build entry updated. **No `.svg` imports in package source** — tsup/esbuild cannot resolve `.svg` files. `<NexusLogo>` accepts a consumer-provided `src` prop (the thin wrapper in apps/web resolves SVGs via Vite and passes the URL); `<NexusMark>` uses hand-authored JSX path data (logo-mono.svg is simple enough for inline JSX — a bundler-agnostic approach).
- **P0 consumption in `apps/web/`**: `src/components/brand/nexus-logo.tsx` (thin theme-aware wrapper), `src/components/layout/sidebar.tsx` + `src/components/layout/header.tsx` (unchanged call-site ergonomics), `src/components/brand/nexus-logo.test.tsx` (updated). No routing/state/transport change.
- **P1 lives in `crates/nexus-daemon-runtime/src/api/handlers/host_tool_handlers.rs`** (the `nexus.manuscript.body.read` handler at ~line 2155) + a regression test in the same crate's test suite. Reuses `resolve_guarded_path` from `api/path_guard.rs` (V1.86-proven).
- **Single plan, single feature branch `feature/v1.87-nexus-ui-component-library`, two sequential batches.** P0 (frontend) then P1 (backend). The two batches touch disjoint file trees (TypeScript package vs Rust crate) so there is no merge-conflict risk, but the iteration is small enough that parallel worktrees would add overhead without throughput gain. Sequential batches in one plan keeps the review surface unified.
- **Spec owner**: `@architect` amends `packages/nexus-ui/AGENTS.md` + `README.md` during Prepare (Phase 1 Review & Edit chain); optional `web-ui.md` note.
- **Out of bounds**: `apps/desktop/**` runtime code (the desktop shell reuses the web SPA dist — once `apps/web` consumes the package components, desktop inherits the change transparently; no Tauri-side touch). No new daemon routes, no schema work.

## 6. Non-Goals

- **Layout-primitive extraction** (Header/Sidebar/RootLayout) — these are deeply coupled to react-router, nav items, and daemon-status; extracting them would create leaky abstractions. The package stays brand-primitive-focused.
- **ThemeProvider consolidation** — the generic theme infra (localStorage / `.dark` class / Tailwind strategy) stays in `apps/web`. Putting generic infra in a brand-named package is a naming mismatch.
- **shadcn primitive extraction** (`components/ui/*`) — shadcn follows copy-into-app philosophy; these stay app-local.
- **Repo-wide `Path::starts_with(string)` sweep** — V1.86 retrospective flagged it as a candidate; V1.87 closes only the one confirmed same-class instance (`R-V186-QC1-S005`). The broader sweep is deferred to a dedicated hygiene iteration if the class recurs.
- **npm publish** — the package remains workspace-only (pre-1.0); publishing to the public npm registry is out of scope (consistent with V1.83).
- **`nexus-platform` consumption wiring** — the platform repo is paused (local-only until further notice); V1.87 only proves the package is consumable, it does not wire platform adoption.
- **New author-facing product surface** — this is a package-maturation + security-fast-follow iteration, not a new feature surface. The three author loops (writing V1.76, quality V1.77, memory V1.78–V1.82) remain the shipped surface set.
- **DESIGN.md token changes** — V1.87 consumes existing tokens; no new design tokens (the brand SSOT is stable post-V1.84).
