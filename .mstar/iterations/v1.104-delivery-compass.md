# V1.104 — Settings Workspace Path (DF-70 W2)

## Scope

V1.104 delivers the V1.103 Stretch that was deferred: **Settings Workspace path edit (W2)** — authors can view and change the active workspace folder from Settings, with honest reload/restart guidance.

**Carry-forward from V1.103:** V1.103 shipped Settings shell Must (Agent, Connection, Setup) but **omitted** Workspace nav/route when P4 Stretch deferred. V1.104 promotes W2 to **Must** — same product intent as `v1.103/specs/settings-workspace-section.md`, now iteration-blocking.

Residual hygiene is **capacity-only** (R1) and must not block Must close. Execution-mode matrix remains **Out**.

- **SP-2 (Stretch): Residual hygiene (R1).** Opportunistic only — low-cost product/spec hygiene (e.g. stale `/v1/local/*` literals in docs); **no** dedicated plan; **do not** commit to R-V192SEC-001 (TOFU transport pinning).

## Product Story

After V1.103, Settings hosts Agent, Connection, and Setup — but workspace path is still **wizard-time only**. An author who picked the wrong folder during first-run, or who later moves creative files to a new directory, today must either re-run setup (which does not change workspace path) or edit `~/.nexus42/config.toml` by hand. That is a dead end for a post-setup control surface.

**V1.104 closes the gap:** Settings → **Workspace** → see current path → **Change Folder…** (desktop native picker) → persist → honest copy that restart/reload may be required before the running daemon uses the new root.

**Iteration complete when:** P0 automated gates pass (Workspace section usable on desktop with honest copy). **Human desktop smoke** (author picks a real folder, restarts, confirms daemon reads new root) is a **separate gate** — recommended before ship narrative, not an automated CI blocker. Stretch R1 residual work is optional and never blocks close.

## Acceptance Criteria

### Must (P0) — iteration incomplete if any fail

- Desktop author can open Settings → Workspace, see current path, change folder via native picker, and persist.
- After persist, UI shows honesty copy that restart/reload may be required (no "instant everywhere" claim).
- Shell shows Workspace nav; `/settings/workspace` resolves under Settings shell.
- Browser build shows honest desktop-only disabled state (no fake path-change API).
- Prefer no `schemas/` / wire contract change.
- Studio visual acceptance before App wiring claim (UI path).

**Author-visible test scenarios (desktop):**

| # | Scenario | Expected |
|---|----------|----------|
| 1 | Open Settings → Workspace on desktop | Current workspace folder path is visible |
| 2 | Tap **Change Folder…**, pick a different directory, confirm | Path persists; success/info copy mentions restart/reload may be required |
| 3 | Without restart, observe running daemon | Previous root may still be in use — UI must not claim instant switch |
| 4 | Open same route in browser build | Desktop-only helper; change action disabled |
| 5 | Shell nav | **Workspace** appears; default landing remains Agent |

## Non-Goals

- **Execution-mode matrix, BYOK, API-key execution modes** as Settings sections.
- **Multi-workspace switcher** or migrating creative files between roots.
- **Automatic daemon/sidecar restart** orchestration after path change.
- **Live hot-switch** — path guard + sidecar capture startup root; no in-session daemon rebind.
- **Re-run setup as workspace change** — Setup re-run (V1.103 R1) clears wizard marker only; does not replace W2.
- **R-V192SEC-001** TOFU transport-layer cert pinning (explicitly not committed).
- Harness-process work packaged as plan tasks (status/QC ceremony belongs outside product plans).
- Platform / cloud sync features (platform paused).
