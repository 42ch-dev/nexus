## PD-1 — Complete replace, not a second stack

## PD-3 — Decode / drift contract

**Resolved (user, 2026-08-17).** Corrects the earlier “skip everything” inconsistency.

| Failure class | Behavior |
|---------------|----------|
| Unknown method / unknown enum variant (crate already downgrades) | Per-item **skip** + `tracing::debug` |
| Typed-decode failure / stream abort (`Error::Deserialization` and kin) | **Whole turn** one terminal `HostEvent::OpFailed`. Do not skip item-by-item (error already left the crate). Optional plaintext retry is **out of scope** this iteration. |

T1 of P1 **must** observe crate behavior on a fixture that triggers typed-decode failure before T2/T3 wire the clients. If T1 shows decode errors are already per-item recoverable, document that fact and keep OpFailed only for unrecoverable stream abort.

Keep `CapabilityDescriptor::native_cli_limited()` **as-is this iteration**:

- Do **not** raise the false fields (`structured_tool_calls`, `images`, `set_model`, `set_mode` stay false).
- Do **not** silently drop the true fields (`text_prompt`, `streaming`, `cancellation`, `session_restore` stay true). Hand-rolled `--resume` deletion is not permission to drop `session_restore`. If a crate cannot honor a currently-true field, architect documents a **narrower descriptor** — do not change the claim quietly.

CLI version skew warnings from the crates: log `warn` only; never fail-closed (user chooses the local bin).

### AR-2 — dsh uses high-level `DeepSeekHarness` + `Session::run`

One `DeepSeekHarness` per provider session, lazy `start` on first execute, `close()` on shutdown; `start_session(Some(host_generated_id))` + `Session::run(Input::Text)` per execute. Rationale: `Session::run` already implements the inbox-receipt / root-idle algorithm, fails visible on malformed notifications, and fails fast on broadcast lag — reimplementing it over `HarnessClient` would be a second protocol parser, which PD-1 rules out in spirit. Accepted trade-off: no incremental events and no mid-turn cancel (documented crate non-goals) → honest narrower descriptor (AR-6). Session continuity: a session id unknown to the runtime lazily creates the agent+session pair; reusing the id across executes resumes — `session_restore: true` is honest.

### AR-3 — Workspace pin + features

- Pins go in root `Cargo.toml` `[workspace.dependencies]`; `crates/nexus-agent-host/Cargo.toml` consumes `x.workspace = true`.
- `claude-codes = { version = "<pin>", default-features = false, features = ["async-client"] }` — `default` also pulls `sync-client`; the `auth` feature (added upstream in 2.1.222+) is **not** in default and must stay off (PD-2).
- `codex-codes = { version = "<pin>", default-features = false, features = ["async-client"] }` — same shape; no `auth` feature exists in this crate today.
- `deepseek-harness-sdk = "=0.1.0"` — the crate publishes **no features** (`features: {}` in the registry index); a plain exact pin, nothing to turn off.
- Deps are always-on on `nexus-agent-host` — no new cargo feature flags of our own in either plan.

### AR-4 — Codex app-server sandbox ≡ today's read-only

`turn/start` carries `approval_policy: Some(AskForApproval::Never)` and `sandbox_policy: Some(SandboxPolicy::ReadOnly { network_access: None })` — the app-server equivalent of today's headless `codex exec --json -s read-only` (never prompts; work runs inside the read-only sandbox; strictly not more writable). Any approval server-request that still arrives (`item/commandExecution/requestApproval`, `item/fileChange/requestApproval`) is auto-answered from the existing native permission classification: `Allow` → accept, `Deny` → deny, `Ask` → deny (headless fail-safe, logged). No author prompt, no new UI.

### AR-5 — `session_restore` honesty

- **Claude:** continuity via crate-owned builder flags — first execute supplies the host UUID via `ClaudeCliBuilder::session_id` (the crate emits `--session-id` itself); subsequent executes use `.resume(uuid)` / `AsyncClient::resume_session`. Nexus never assembles `--session-id`/`--resume` argv. Claim stays true.
- **Codex:** `thread_start` on first execute; reuse the thread id while the app-server lives; `thread_resume` (history replay) restores after a restart. Replaces `exec resume <id>`. Claim stays true.
- **dsh:** AR-2 session-id reuse. Claim stays true.

No provider needs a narrower descriptor for `session_restore`.

### AR-6 — dsh incremental deltas do not exist on the chosen surface

`Session::run` returns only after the root session reports idle; `final_response` is derived from the last root `assistant/message` event. There is no incremental delta API and no token-delta notification vocabulary in the SDK. `dsh-native` therefore ships a **documented narrower descriptor**: `text_prompt: true`, `session_restore: true`, `streaming: false`, `cancellation: false` (no cancel/session-close RPC — killing the runtime mid-turn abandons the turn), everything else as `native_cli_limited()`. Exactly one `MessageDelta(final_response)` + one terminal event per turn. Raising either field later needs an upstream delta vocabulary or a low-level `HarnessClient` rewrite — Durable Roadmap in P2.

### AR-7 — Author-visible OpFailed reason string

`error_category` stays a stable snake_case token owned by the mapper (same pattern as today's `io_error` / `timeout`): `decode_error` (typed-decode / `Error::Deserialization` / dsh `Error::SdkProtocol`), `stream_closed` (EOF / `ConnectionClosed` / `ServerClosed` / dsh `TransportClosed`), `provider_error` (claude error `Result` subtypes, codex `TurnStatus::Failed`, dsh `JsonRpc`), `timeout` (dsh `RequestTimeout`, our execute wrapper), `io_error` (spawn/stdio). `error_message` is the crate error's `Display` verbatim — diagnostic text (may cite method names and bounded stderr tails; carries no secrets). Exactly one terminal `OpFailed` per failed turn (PD-3); copy is not product-locked.
