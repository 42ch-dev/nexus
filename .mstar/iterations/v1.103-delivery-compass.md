# V1.103 — Settings Shell Deepening (DF-70 Remainder)

## Scope

V1.103 turns the V1.102 thin Settings host into a real **Settings shell (S3)** and moves previously deferred setup/connection surfaces into it — fulfilling V1.94 “Connect / Re-run setup live in Settings” and DF-70 fuller IA (minus execution-mode / BYOK).

### Must / Stretch integrity (locked)

| Tier | Plans | May defer? | Iteration incomplete if missing? |
|------|-------|------------|----------------------------------|
| **Must** | **P0** shell + section nav; **P1** Agent + `getAgentProfile`; **P2** Connection + `/connect` redirect; **P3** Setup re-run | No | **Yes** |
| **Stretch** | **P4** Workspace path edit (W2) | Yes → V1.104+ | **No** |

Order: **P0 → P1 → P2 → P3 → (P4 Stretch)**. Inside each UI-visual plan: **Studio visual → App wiring**.

- **SP-1 (Must / P0): Settings shell + section nav (S3).** `/settings` host with secondary section navigation; default section **Agent**; nested routes for Connection / Setup (/ Workspace Stretch).
- **SP-2 (Must / P1): Agent section + G1 preselect.** Existing AgentPicker as Agent section content; Tauri-only `getAgentProfile` preselects current profile (`wire_contracts_changed: false`).
- **SP-3 (Must / P2): Connection section + C1.** Move Connect UI into `/settings/connection`; permanent `/connect` → `/settings/connection` redirect.
- **SP-4 (Must / P3): Setup re-run (R1).** Confirm → clear `setup_completed` → `navigate('/setup')`; do not wipe workspace/agent files.
- **SP-5 (Stretch / P4): Workspace (W2).** Show + change current workspace path (native picker + `set_workspace_path`) with honest reload/restart copy; multi-workspace **Out**.

## Product Story

Authors who finished first-run still need a single place to manage local agent, remote daemon connection, and re-run setup — without hunting a top-level Connect route or re-entering wizard chrome by accident. Settings becomes that place.

**Iteration complete when:** P0–P3 automated gates pass (shell + Agent + Connection + Setup). P4 Workspace is optional Stretch — deferring P4 does **not** block close.

### V1.94 promise fulfillment (this iteration closes the gap)

V1.94 shipped sidebar IA with Connect **out of the sidebar** and deferred Settings bodies. V1.102 delivered a thin Settings host (Agent only). V1.103 finishes the author-facing promise:

| V1.94 author promise | V1.103 delivery | Plan |
|----------------------|-----------------|------|
| "Connect is reachable only from Settings" | Connect UI lives at `/settings/connection`; `/connect` permanently redirects (C1); no sidebar Connect entry | **P2 Must** |
| "Re-run setup" clears marker and re-enters wizard | Setup section offers confirm → clear `setup_completed` → `/setup` (R1); workspace/agent files preserved | **P3 Must** |
| Agent change after setup is a Settings action | Agent section preselects saved profile (G1) and persists via `setAgentProfile` | **P1 Must** |
| Settings is a real shell, not a single page | S3 secondary nav + nested `/settings/*` routes; default landing Agent | **P0 Must** |

## Architecture Locks (architect-locked §5.2)

| Topic | Lock |
|-------|------|
| Router parent | Single nested tree under `SetupGate` → `RootLayout` in `apps/web/src/App.tsx` (sibling of `/works`, `/memory`, … — **not** under `/setup`) |
| Shell route | `<Route path="settings" element={<SettingsShellLayout />}>` with child `<Outlet>` |
| Nested routes | Index `<Navigate to="agent" replace />`; children `agent`, `connection`, `setup`; Stretch `workspace` registered **only** when P4 runs |
| Section nav owner | `SettingsShellLayout` — in-page secondary nav + page title; **not** Creator/Orchestrator tabs; **not** a second app sidebar |
| Section body owners | `SettingsAgentSection`, `SettingsConnectionSection`, `SettingsSetupSection` (+ `SettingsWorkspaceSection` when P4) under `apps/web/src/pages/settings/` |
| Default landing | `/settings` and `/settings/agent` both resolve to Agent (index redirect) |
| Header title | `ROUTE_TITLES['/settings'] = 'Settings'` covers all `/settings/*` (top segment match in `root-layout.tsx`) |
| V1.102 lift | **Supersedes** V1.102 `settings-thin-host.md` lock “no `/settings/*` IA” for the accepted S3 section allowlist only; thin host Agent logic migrates into `SettingsAgentSection` |
| Agent content | App-shared `AgentPicker` (`components/setup/agent-picker.tsx`); mapping helpers from `setup-step-agent.tsx` |
| Agent write | `DesktopCapabilities.setAgentProfile` → Tauri **`set_agent_profile`** (existing) |
| Agent read (G1) | New Tauri **`get_agent_profile`** + `DesktopCapabilities.getAgentProfile()` — **no** `schemas/` / HTTP |
| `getAgentProfile` semantics | Returns `{ name: string; launchCommand?: string } \| null`; first `protocol === "native_cli"` provider in `~/.nexus42/agent-host/config.toml`; missing/malformed/empty → `null`; preselect treats errors as `null` (no crash) |
| Browser agent | `useDesktopCapabilities()` is `null` — mount AgentPicker; no fake preselect/persist |
| Connection UI | **Extract** `ConnectDaemonForm` from `connect-daemon-page.tsx` into a shared module; `SettingsConnectionSection` mounts it; **delete** top-level `<Route path="connect" element={<ConnectDaemonPage />}>` |
| Post-connect nav | After activate/revert, **stay on** `/settings/connection` (replace `navigate('/')` from legacy page) |
| `/connect` redirect | `<Route path="connect" element={<Navigate to="/settings/connection" replace />} />` in `App.tsx` under the same `SetupGate` parent |
| Connection tests | Form behavior → extracted module tests (migrate from `connect-daemon-page.test.tsx`); redirect → route test; section mount → `settings-connection-section.test.tsx` |
| Setup re-run (R1) | Confirm → `setSetupCompleted(false)` **only** → sync `SetupCompletedContext` to `false` → `navigate('/setup', { replace: true })` |
| Setup data wipe | **Forbidden** — no `resetLocalDatabase`, no workspace/agent profile clears, no `set_workspace_path` in re-run |
| SetupGate note | `/setup` is **outside** `SetupGate`; re-run must update React context **and** disk before navigate so a return to gated routes does not flash main UI with stale `completed: true` |
| Workspace Stretch (W2) | Reuse `getWorkspaceRoot`, `pickDirectory`, `setWorkspacePath` (wizard parity via `setup-step-welcome.tsx`); **copy-only** honesty after persist (restart/reload may be required — path guard + sidecar use startup root per desktop-shell limitation) |
| Workspace nav | Register `/settings/workspace` route + nav item **only** when P4 Stretch runs |
| Wire / icons | `wire_contracts_changed: false`; lucide only |
| DF-70 | Closes fuller Settings IA for accepted sections; execution-mode remains deferred |

## Acceptance Criteria

Author-visible checks below are the product bar; automated tests and Studio gates are implementation evidence.

### Must (P0–P3) — iteration incomplete if any fail

**P0 — Shell**

- Author opens Control Room → **Settings** and sees secondary section nav with **Agent**, **Connection**, and **Setup** (Workspace nav item appears **only** when P4 Stretch runs).
- Default landing content is the **Agent** section (not Connection or Setup).
- Deep links `/settings/agent`, `/settings/connection`, `/settings/setup` resolve inside the main app chrome (sidebar + header remain).
- Studio shell fixtures accepted before App wiring claim.

**P1 — Agent**

- Agent section shows the existing AgentPicker; saved profile is **pre-selected on desktop** when `getAgentProfile` returns a value (G1).
- Author changes selection and it persists via `setAgentProfile` (same as V1.102).
- Browser build: AgentPicker mounts; preselect/persist are honestly desktop-oriented (no fake success).
- Prefer `wire_contracts_changed: false`.

**P2 — Connection (V1.94 Connect-in-Settings)**

- Author reaches daemon connection config **only** via Settings → **Connection** (no sidebar or mobile product nav entry for Connect).
- Connection section hosts the full Connect-to-Daemon UI (endpoint / API key / TOFU fingerprint pinning) with existing save/pin behavior.
- Visiting legacy `/connect` lands on `/settings/connection` (permanent redirect, C1).

**P3 — Setup (V1.94 Re-run setup)**

- Settings → **Setup** shows a **Re-run Setup** action with a confirm dialog explaining the wizard will restart.
- **Re-run Setup** (confirm) clears `setup_completed` and navigates to `/setup` immediately (R1).
- **Cancel** leaves `setup_completed` unchanged.
- After confirm, author's workspace path and agent profile files remain intact (no silent wipe).

**Gates**

- Studio-first for UI-bearing plans.
- Automated Done ≠ human smoke Done.

### Stretch (P4) — optional; does not block iteration close

- If run: author can view and change the current workspace path from Settings → **Workspace** with honest reload/restart guidance after change.
- If deferred: retarget V1.104+ with reason in compass/tracker; **Must completeness unaffected**.

## Non-Goals

Hard stops — QC should reject scope creep into these areas:

- **Execution-mode matrix, BYOK, or API-key execution modes** as Settings sections, toggles, or product surfaces. These remain DF-70 deferred post-V1.103; do not add placeholder nav items or "coming soon" stubs that imply imminent delivery.
- **In-app agent installers**; **AgentPicker promotion** to `@42ch/nexus-ui` package.
- **Multi-workspace switcher** / multi-root model / workspace file migration between roots.
- **Moving FooterProfiles or Daemon status bar** into Settings.
- **Shipping Studio Surfaces section menu** into App Settings.
- **Top-level Connect route or sidebar entry** as a product destination (redirect-only legacy `/connect` is in-scope via C1).
- Platform sync, billing, entitlements, signing, notarization, auto-update.
- `schemas/` / wire contract changes unless architect hard-stop waived.
- **Treating Stretch P4 as Must** or blocking iteration close when P4 is deferred.
