# V1.98 — Design Studio & DESIGN Unification — Delivery Compass v1

## Scope

This iteration delivers a **standalone design-system gallery app** and **unifies the DESIGN contract** so token tuning has a single mirror, not two drifting sources.

- **SP-1: DESIGN.md unification (Prepare + implement).** Merge the normative design contract into **repo-root `DESIGN.md` + `DESIGN.dark.md` only** (Production-level YAML frontmatter SSOT). Retire `apps/web/DESIGN.md` and `apps/web/DESIGN.dark.md`; update `apps/web` consumers (`index.css`, `tailwind.config.ts`, AGENTS.md references) to read the root SSOT. Preserve token **names** verbatim where possible to minimize CSS churn.
- **SP-2: `apps/design-studio` (new product surface).** A daemon-independent Vite + React SPA (pnpm workspace member) that visualizes the unified DESIGN contract: color/typography/spacing/rounded scales, component token tables, **light/dark theme toggle**, brand VI (all `@42ch/nexus-ui` logo variants), all existing `apps/web/src/components/ui/*` primitives with interactive states, Voice & Content samples, and 1–2 real surface slices (Setup wizard step card, App shell chrome). **Read-only mirror** — token edits remain file-based (edit DESIGN.md → refresh studio).
- **SP-3: `nexus-ui` brand layer only.** Consolidate brand/VI showcase in design-studio; **do not** migrate shadcn-style `components/ui/*` into `packages/nexus-ui` (preserves V1.87 package boundary). design-studio may import apps/web ui primitives for gallery display during this iteration.
- **SP-4: Closure.** QC tri-review + QA (UI observable gate) + Profile B compaction + PR to `main`.

## Iteration Retrospective (minimal)

**What went well**
- SDD per-task loop (7 tasks) ran cleanly serial; each task had a fresh L2 review catching real issues (T1 dead path refs → folded into T7; T5 alias scoping → tightened in T7).
- DESIGN merge + token-pipeline extraction (T1) preserved exact web parity (548 tests, empty drift register) — the `design-unification.md` merge playbook paid off.
- Plan QC tri caught a production-invisible bug (qc1 W001: unregistered `bg-gray-alpha-150`) that dev-only JIT had masked; one-line fix + targeted re-review closed it in one wave.

**What to improve**
- Tailwind scale-step registration should be verified against the **production** build, not just dev JIT — consider a CI/build-time grep guard that flags utility classes referencing unregistered scale steps (qc2 suggestion; defer to V1.99+ tooling).
- The `@web-ui/*` transitional coupling between design-studio and apps/web is intentional for V1.98 but creates an alias-resolution surface (tsconfig + vite); track decoupling as a V1.99+ option if the studio grows.
- T1's dead DESIGN path references (F-1) spread across 6 files including non-web packages (nexus-ui, desktop) — a pre-merge grep gate in the merge playbook would have caught them at T1 rather than T7.

**Carry-forward**: V1.97 desktop clean-state residuals re-targeted to V1.99 (next iteration).
