## 1. Problem statements (verified)

### P0 — Connect-host shippers have no failing CI check

Who: developers and integrator partners shipping the third consumption
end (`nexus-runtime`, `connect-host`, PD-09). The artifact builds with
`--no-default-features --features connect-host`
(`apps/nexus42/Cargo.toml` `[[bin]] name = "nexus-runtime"`,
`required-features = ["connect-host"]`). Default-graph clippy never
sees this graph. Residual identity:
`2026-08-19-v1.169-p0-spoke-011-upgrade` **R1** (connect-host clippy
debt — **not** yamux dependabot R1 under `v1.153-dependabot-security`).
Original residual: "64 pre-existing errors in connect invoke.rs/
interop.rs".

**Verified 2026-08-27 (PM research; architect re-verified same day, warm
cache):** `cargo clippy -p nexus42 --features connect-host --all-targets`
now compiles clean of errors (an earlier fix wave already reduced the 64
errors to 0) but emits **70 distinct warning sites** (deduped by
lint+file+line; the raw message count varies with cache state because
under `--all-targets` the lib is re-linted under both normal-dep and
dev-dep feature unifications). All in-scope sites sit in
`apps/nexus42/src/commands/connect/invoke.rs` and `…/interop.rs`
(`token.rs` / `config.rs` / `identity.rs` / `allowlist.rs` are clean),
68 sites: `items_after_statements` ×23, doc-missing-backticks/markdown
×17 sites (18 messages), `result_large_err` ×11 (10 fns + 1 closure),
`too_many_lines` ×11, `used_underscore_binding` ×3, `redundant_clone`
×2, `unused_async` ×1. The **only off-path sites** are 2 warnings in
the connect-host-gated example `apps/nexus42/examples/trpg_raw_bridge.rs`
(`too_many_lines` ×1, `missing_const_for_fn` ×1) — there are no
"workspace-wide" warnings in this invocation: `-p nexus42` lints only
the nexus42 package's targets (dependencies are built with capped
lints).

**Gate gap (verified):** no CI job runs clippy over this graph.
`.github/workflows/ci.yml` "Rust fmt & clippy" runs
`cargo clippy --all --all-targets -- -D warnings` with **default
features** — `connect-host` is not default (spec §10: default builds
MUST NOT link spoke-connect), so the distributed-artifact graph is
never linted. `.github/workflows/runtime-build.yml` runs only
`cargo build --release … --features connect-host`.

Consequence: the shipped artifact's source can silently accumulate
lint debt; editors get no guardrail; that R1 cannot close honestly
("gate it so the debt class cannot regrow" is the close condition —
cleaning warnings without the gate is insufficient).

## 4. Architecture decisions

| ID | Decision |
|----|----------|
| AR-99 | P0 gate mechanism = dedicated clippy invocation `cargo clippy -p nexus42 --features connect-host --all-targets -- -D warnings` on ubuntu-latest. **Crate-level, not bin-level (verified):** the connect surface lives in the nexus42 **lib** (`pub mod commands`; the `nexus-runtime` bin is a thin clap shell) — a `--bin nexus-runtime` invocation would build the lib as a capped-lints dependency and lint only the shell. `--all-targets` is load-bearing: it pulls the connect-host-gated examples/tests into the linted set (live evidence: the only 2 off-path warnings sit in `examples/trpg_raw_bridge.rs`). Feature set is default + `connect-host`, not the artifact's `--no-default-features --features connect-host`: verified 2026-08-27 that nexus42's own source has zero `cfg(feature = "web-embed")` branches, so both combos compile identical nexus42 code and lint coverage of the gated crate is identical; dependencies are cap-lints'd either way. Compile-only concerns are out of scope — build already proven by runtime-build.yml. Toolchain: same unpinned `stable` channel as the existing clippy step (a stable bump adding lints is a pre-existing repo-wide exposure, not a new risk class introduced by this gate). CI budget/ENOSPC: a step inside `rust-checks` inherits `free-disk-space` + `CARGO_INCREMENTAL=0` and the shared rust-cache but serializes the connect-host graph (libp2p stack) onto the PR critical path; a separate job runs parallel but MUST use a distinct rust-cache `shared-key` suffix (precedent: `…-sqlx`, `…-module-dx`) — same-key concurrent writers are last-writer-wins and would thrash each other's graph artifacts. Either placement satisfies PL-1. Boundary (honesty): the `connect-client` feature graph (V1.174 dev/E2E stack) stays ungated by design — no shipped artifact uses it; flag for a future compass if that changes. |
| AR-100 | Baseline discipline: before fixing, record the warning inventory into the SDD progress ledger as the plan's BASE evidence, deduped by lint+file+line (each lib site is reported twice under `--all-targets` — the lib is linted under both normal-dep and dev-dep feature unifications). Verified BASE 2026-08-27: 70 distinct sites — `items_after_statements` ×23, `doc_markdown` ×17 sites (18 messages), `result_large_err` ×11 (10 fns + 1 closure), `too_many_lines` ×12 (11 in `interop.rs` + 1 off-path), `used_underscore_binding` ×3, `redundant_clone` ×2, `unused_async` ×1, `missing_const_for_fn` ×1 (off-path); 68 in-scope (`invoke.rs` + `interop.rs`), 2 off-path (`examples/trpg_raw_bridge.rs`). Raw compiler message count varies with cache state (lib re-linted under both feature unifications) — the ledger dedupes by lint+file+line. After fixes, zero remains for the invocation except the enumerated `#[expect]` sites, which are listed in the same ledger so QC can diff-check the expect count against BASE. |
| AR-101 | Large-Err handling (×11 sites, incl. one closure) prefers **boxing at construction** only where trivially mechanical; otherwise `#[expect(clippy::result_large_err)]` at the narrowest legal scope (statement/closure where rustc permits, else fn) with a justification comment naming the payload type. No public-signature churn. Regression safety: `#[expect]`, never `#[allow]` — once the lint stops firing, `unfulfilled_lint_expectations` itself fails the `-D warnings` gate, so the allowance is self-cleaning. Accepted masking limit (explicit): an expect suppresses its lint for the whole annotated scope, so a *new* large-Err site inside an already-annotated fn would not fire; mitigation = the annotated-site set is pinned in the AR-100 ledger and QC diff-checks expect count + sites. |
| AR-102 | Over-long function warnings (×12 sites: 11 in `interop.rs` + 1 in the off-path example) are satisfied by targeted `#[expect(clippy::too_many_lines)]` with justification (command handlers / invoke dispatch are linear by design); same self-cleaning + masking terms as AR-101; extraction refactors are OUT of scope (Non-Goal). |
| AR-103 | P1 scope = `outbox-consolidation.md` whole-file coherence pass (frontmatter Status line version bump, §2.3 rewrite, §6.2/§6.3 rewrite as closed-history note, cross-reference check from `specs/README.md` index if present).
